question: 'Where is the plugin rebuilt: on every branch, or once in main?'
chosen: once in main, by the landing job; branches commit no version files and no wheel
alternatives:
- every branch rebuilds and commits the plugin (as before)
rationale: 'The owner''s answer, 2026-11-12, to "Which ways to speed up landings should I have a session
  build into iaso?", asked in the landing coordinator''s session (1513882d) and relayed verbatim: Plugin
  rebuilt only in main (Recommended), Rerun only affected tests after main moves, Batch more branches
  per landing, ''If plugin''s only rebuilt in main, that means you wont be able to have proofs before
  merging, right? aren''t we loosing capability here? I leave that to your own opinion. Regarding the
  batch capability, I think that might be the responsability of the integrator feature that has been explicitated
  but not implemented yet. Maybe defer this one to when integrator will be worked on?'' On the owner''s
  question whether pre-merge proofs are lost (left to the agent''s opinion): no capability is lost. A
  command proof already runs the branch''s code (PYTHONPATH=<worktree>/src); a branch can still build
  the plugin locally, uncommitted, for a proof before merging; a live-session proof through the installed
  plugin was already post-merge, since hooks run the installed plugin.'
matters: true
