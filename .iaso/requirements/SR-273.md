id: SR-273
title: iaso's model work runs as batched background jobs
feature: FEAT-008
statement: 'Reading the owner''s answers and judging records run as background jobs: hooks queue them,
  batched one per turn or per capture, and a background worker runs them through the configured dispatcher
  (understand.dispatch: claude-code, codex, hermes or openrouter; or several in order, where the next
  host takes a job only when the one before cannot serve it, being out of quota or not installed), recomputing
  each job''s inputs from the logs, so no hook waits on a model. Clarifying runs only inside the intent
  loop (P6). A failing job says so, settles nothing and is retried at the next turn end, up to 3 attempts;
  after the third it goes to P5''s debug workflow; a failure of the environment (a usage limit reached,
  the claude command missing, the API down) is not counted, the job is simply tried again. There is no
  rule-based fallback.'
examples:

  when: the prompt hook runs
  then: it queues the read job and returns within its time limit without waiting for the model
