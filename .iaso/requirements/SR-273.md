id: SR-273
title: iaso's model work runs as batched background jobs
feature: FEAT-008
statement: 'Reading the owner''s answers and judging records run as background jobs: hooks queue them,
  batched one per turn or per capture, and a background worker runs them through the one configured dispatcher,
  recomputing each job''s inputs from the logs, so no hook waits on a model. Clarifying runs only inside
  the intent loop (P6). A failing job says so, settles nothing and is retried at the next turn end, up
  to 3 attempts; after the third it goes to P5''s debug workflow. There is no rule-based fallback.'
examples:
- id: EX-1
  given: the last reply showed something for the owner to answer, and the owner's message arrives
  when: the prompt hook runs
  then: it queues the read job and returns within its time limit without waiting for the model
- id: EX-2
  given: the Claude Code dispatcher runs a job
  when: iaso's hooks fire inside that headless session
  then: they exit at once and queue nothing
- id: EX-3
  given: the configured model is unreachable
  when: the turn ends
  then: the turn-end iaso line says iaso could not check the owner's answers, nothing is approved, and
    the job is retried next turn
- id: EX-4
  given: the same job inputs queued twice
  when: the worker runs
  then: the job runs once
- id: EX-5
  given: the configured model is unreachable
  when: the worker runs the read job
  then: no word rule decides in the model's place and nothing is approved
- id: EX-6
  given: the Claude Code dispatcher builds its command
  when: iaso starts the job
  then: the command selects the iaso agent with --agent and passes --setting-sources empty, --strict-mcp-config
    and --disable-slash-commands, runs in an empty temporary directory, and the job's context holds no
    CLAUDE.md text
- id: EX-7
  given: a judge job queued by the agent through iaso capture, with inputs that differ from the logs
  when: the worker runs it
  then: the worker uses the inputs it recomputed from the logs, not the file's, so the file cannot make
    a record look supported
- id: EX-8
  given: a turn whose previous reply showed five records and one open question
  when: the prompt hook queues jobs
  then: one read job covers all six items, not six jobs
- id: EX-9
  given: a capture that writes one intent and six requirements
  when: the capture finishes
  then: one judge job is queued for the seven records
- id: EX-10
  given: a job that has failed at three turn ends in a row
  when: the third failure is logged
  then: the iaso line says one case went to debugging, and the job is not queued again by the turn end
- id: EX-14
  given: a background worker is doing the upkeep a turn end left, for longer than the lock's silence limit
  when: the session's next turns end and ask for a worker
  then: 'no second worker starts for that session: the one worker holds the session''s lock, with a fresh
    heartbeat, for the whole upkeep and its jobs'
