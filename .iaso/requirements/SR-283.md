---
id: SR-283
title: Codex and Hermes each get a thin adapter that installs only...
feature: FEAT-004
statement: 'Asked to set iaso up for Codex or Hermes, iaso writes only that host''s adapter: Codex''s
  AGENTS block and hooks, Hermes''s plugin and namespaced skills, each with the /iaso command where the
  host has one and its session marker where it can be set. Installing twice changes nothing, the owner''s
  own entries are kept, uninstalling removes only iaso''s, and status reports what is installed without
  claiming it is active. Each adapter binds events to the project it was installed in, ignores child sessions,
  gives the brief once, sends a block at most once, and records a summary that never reached the owner
  as unseen. The Pi adapter and the MCP server stay removed; the Codex and Hermes adapters are kept and
  not frozen (they may come back into use later, and nothing of them is removed).'
examples:
- id: EX-1
  given: an AGENTS.md with the owner's own text
  when: iaso's Codex adapter is installed twice
  then: the owner's text is unchanged and one iaso block exists
- id: EX-2
  given: iaso's Codex adapter installed
  when: it is uninstalled
  then: only iaso's entries are removed
- id: EX-4
  given: a repository
  when: iaso's Codex adapter is installed
  then: 'nothing of Claude Code''s or Hermes''s is written: no .claude settings, no Hermes plugin'
- id: EX-5
  given: the adapter not loaded (Hermes with project plugins off, Codex with a foreign shell_environment_policy
    kept)
  when: iaso's status for that host is asked
  then: it says the session marker is missing on this host, where the owner's prompts come from, and how
    many approvals rest on a self-recorded message
- id: EX-6
  given: the Hermes plugin files and discovery flag exist
  when: iaso's status for Hermes is asked
  then: installed files and prerequisites are reported while runtime activation remains unverified
- id: EX-7
  given: Hermes skills installed for a project
  when: the agent resolves a iaso skill
  then: only the iaso-qualified name resolves, and uninstalling the Hermes adapter removes those skill
    files
- id: EX-8
  given: iaso installed for Codex or Hermes
  when: iaso installs there
  then: iaso's Claude Code band is not installed; that host gets only its own things
- id: EX-9
  given: the rendered Hermes plugin and a fake ctx
  when: register(ctx) runs
  then: a iaso command is registered and each registered hook returns turn output lines
- id: EX-10
  given: a Hermes ctx without hook registration
  when: register(ctx) runs
  then: only the command is registered, no error is raised, and the instruction block tells the agent
    to run iaso turn start and iaso turn end
- id: EX-12
  given: the generated Hermes plugin belongs to repo A and the process runs in repo B
  when: a prompt callback runs
  then: only repo A receives the hook payload
- id: EX-13
  given: the generated plugin root lacks .iaso
  when: any event callback runs
  then: no subprocess is launched and empty adapter output is returned
- id: EX-14
  given: an observer may fire before session ancestry is known
  when: the first eligible parent prompt arrives
  then: one brief is obtained after filtering, and later prompts do not duplicate it
- id: EX-15
  given: parent_session_id is explicit
  when: prompt and later callbacks run
  then: no owner prompt or summary events are emitted for the child
- id: EX-16
  given: a child observer fires without parent metadata
  when: later callbacks identify its parent session
  then: no startup or other subprocess event is emitted
- id: EX-17
  given: another transform wins or a reply is interrupted
  when: the turn settles
  then: the summary is recorded as unseen, so the records it named are not marked as shown and are given
    to the agent again on the next turn
proof:
  plan: 'Recommended: in a scratch repository holding the owner''s own AGENTS.md and Hermes config, the
    agent sets iaso up for Codex, then Hermes, twice each, and shows the owner the diff after each: only
    that host''s files changed, the owner''s text intact, and an uninstall diff removing only iaso''s
    entries. The owner decides whether these diffs or a live session in one of those hosts is the proof.'
  kind: command
