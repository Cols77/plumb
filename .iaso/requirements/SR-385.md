id: SR-385
title: iaso ships ready-made workflows for the work it hands to the agent
statement: 'iaso ships its own workflows for the work it hands to the coding agent: the debug cases a
  landing leaves, the plan and build steps of an intent loop, and landing a branch. Each carries its gates,
  the capability level of each stage (the Sonnet-like level unless a stage failed at it), the one-heavy-job
  lock around test runs and the checks that end it. Where iaso tells the agent to run such work on a host
  that has workflows, it names the shipped workflow; the agent writes no workflow of its own.'
examples:
- id: EX-1
  given: a landing left 3 debug cases
  when: the agent's next turn starts
  then: the text names iaso's debug-cases workflow with the 3 cases as its input, and the agent runs it
    as shipped, writing no script
- id: EX-2
  given: an intent loop whose clarify gate passed and the owner opted in to a workflow
  when: the plan step starts
  then: the plan and the build run as phases of iaso's shipped intent workflow, each phase ends on its
    gate command, and the next phase starts only when that command exits 0
- id: EX-3
  given: a branch whose build is done
  when: iaso's landing workflow runs
  then: main is merged into the branch, the full test run goes under the one-heavy-job lock, the links
    the merge moved are repinned after their tests pass, and the merge into main goes through the merge
    check with nothing forced
- id: EX-4
  given: a shipped workflow's stage that edits code
  when: the stage's agent is started
  then: it runs at the Sonnet-like level, on Sonnet unless the workflow was given another model for that
    level; a higher level is used only for a stage that already failed
proof:

    iaso evaluate sets iaso up without the plugin, so it cannot show the shipped workflows: its before
    and after run is taken with the background-checks and self-fix parts.'
