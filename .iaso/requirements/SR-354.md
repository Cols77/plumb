---
id: SR-354
title: A mid-session plugin reinstall loses no answer
statement: 'When the iaso plugin is reinstalled during a session and the private copy for the new plugin
  version is not ready yet, iaso''s background checks keep running on the previous version''s private
  copy until the new one is ready, so no owner answer or edit goes unrecorded. A check that still cannot
  run, or whose process fails, writes one line saying which check and why to .iaso/session/errors.log,
  in an adopted project only; a project not adopted gets nothing written. This narrows SR-279: outside
  this window, checks run only on the copy of the plugin''s version, and EX-1 and EX-4 stand for a first
  install.'
examples:
- id: EX-1
  given: an adopted project, a session open, and the plugin reinstalled to a new version whose private
    copy is still being built
  when: the owner answers a question through the question tool
  then: the answer is recorded by the check running on the previous version's copy
- id: EX-2
  given: an adopted project and no private copy that can run
  when: a background check starts
  then: one line naming the check and the reason is appended to .iaso/session/errors.log and the owner's
    session is not interrupted
- id: EX-3
  given: a project not adopted and no private copy that can run
  when: a background check starts
  then: nothing is written into the project
proof:
  plan: 'in a session in an adopted project, reinstall the iaso plugin, answer a question through the
    question tool at once: the answer shows in iaso''s log; then make the private copy unusable and start
    a check: one line appears in .iaso/session/errors.log'
  kind: live-session
