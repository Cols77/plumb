id: SR-401
title: An idle debug work copy is removed at a landing and by iaso debug...
statement: 'At each landing into main and when the owner types iaso debug prune, a debug work copy whose
  branch has no commit of its own, with no uncommitted changes (untracked log and cache files aside) and
  no open problem naming it, is removed and its branch is kept; the landing line, or the prune line, names
  each copy removed and the space freed. A copy with an open problem, with uncommitted changes, or whose
  branch has a commit not merged is kept. The rule covers debug work copies only: any other worktree follows
  the rule for finished worktrees.'
examples:
- id: EX-1
  given: a clean debug work copy whose branch has no commit of its own and which no open problem names
  when: a landing runs
  then: the copy is gone, its branch stays, and the landing line names it as removed
  quote: a clean debug worktree with no commit of its own and no open case is removed at the tidy
  prompt: a4218e97aba44b36
- id: EX-2
  given: a debug work copy just made for a problem being fixed
  when: a landing runs
  then: the copy stays, because its problem is open
- id: EX-3
  given: a debug work copy with an uncommitted change to a tracked file
  when: a landing runs
  then: the copy stays and the line names it kept for uncommitted changes
- id: EX-4
  given: a debug work copy whose branch has a fix commit not yet merged
  when: a landing runs or iaso debug prune runs
  then: the copy and its branch are untouched
- id: EX-5
  given: several idle debug work copies
  when: the owner types iaso debug prune
  then: every one is removed at once and the line gives how many and the space freed
  quote: by iaso debug prune
  prompt: a4218e97aba44b36
- id: EX-6
  given: a worktree outside the debug folder with no commit of its own, clean and merged
  when: a landing runs or iaso debug prune runs
  then: it is untouched, as the rule for finished worktrees says

    prune and a landing and see only the idle ones removed and named, with the space freed

  summary: 'Ran the proof twice in fresh scratch repos, once with `iaso debug prune` and once with a landing
    (landing.land after a fast-forward merge). Each repo had idle-1 (clean except 3 MB of untracked .iaso/cache),
    idle-2, open-1 (open problem), dirty-1 (tracked README edited), unmerged-1 (unmerged fix commit) and
    a non-debug worktree `feat` (no commit of its own, clean, merged). Free space was stubbed, because
    the real disk sat at the tree''s 5 GB floor. Prune printed ''removed 2 idle work copies (3 MB freed):
    debug-idle-1, debug-idle-2'' plus ''debug work copy debug-dirty-1 is idle but kept: uncommitted changes''.
    The landing line said ''removed idle debug work copies debug-idle-1, debug-idle-2 (3 MB freed); debug
    work copy debug-dirty-1 is idle but kept: uncommitted changes''. In both runs only the two idle copies
    were removed. Their branches debug/idle-1 and debug/idle-2 stayed. The open, dirty and unmerged copies
    and their branches, and the `feat` worktree, were untouched. A second prune after the first removed
    0 and left the rest alone. This covers EX-1 to EX-6. One caveat: an untracked file at the repo root
    (junk.log) counts as uncommitted, since only iaso''s own .iaso/log and .iaso/cache files are ignored.
    That fits the rule''s ''untracked log and cache files''.'
