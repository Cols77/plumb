---
id: SR-353
title: An exact copy of an owned file is owned through its original
statement: At the merge, a changed file no requirement links to, whose content is byte-for-byte the content
  of a file a requirement does link to (for example a skill copied into another folder, or LICENSE copied
  next to a package), counts as owned through that original and is not listed as untraced. A copy whose
  content differs from every owned file is listed as before. Untraced files never hold the merge (SR-260);
  a new trace.exempt glob still holds it as SR-288 says.
examples:
- id: EX-1
  given: src/a.py is linked to SR-001 and the branch adds plugin/a.py with the same content
  when: the merge check runs
  then: plugin/a.py is not listed as changed without a requirement
- id: EX-2
  given: the branch adds plugin/a.py whose content differs from src/a.py by one line
  when: the merge check runs
  then: plugin/a.py is listed as changed without a requirement, and the merge is not held for it
- id: EX-3
  given: the branch adds src/** to trace.exempt and nothing approves it
  when: the merge check runs
  then: the merge still holds as SR-288 EX-1 says
proof:
  plan: 'run iaso merge-check on a branch that adds a copy of an owned skill file: the copy is not listed;
    change one line of the copy and run it again: it is listed and the merge is not held'
