---
id: SR-279
title: The Claude Code plugin installs only Claude Code's things and runs...
feature: FEAT-007
statement: 'iaso''s repository offers iaso as a Claude Code plugin that carries a ready-built copy of
  iaso and installs only Claude Code''s things: the /iaso command, iaso''s skills, its background checks
  and its in-app panels. Everything it runs uses iaso''s own private copy of its tools, kept per user
  and plugin version, never the project''s setup, except in iaso''s own repository and its worktrees,
  where it runs that checkout''s code (SR-315); the copy is set up in the background, and only an adopted
  project shows a line about it. The shipped bundle holds only what runs, no test file; the command guard
  starts no Python for a command that does not concern iaso; on Windows the launcher uses Git for Windows''
  sh.exe when cmd.exe has no sh on its PATH. One exception: in a main checkout, a command that could write
  (a redirect, git, a file command) starts Python for the main-checkout guard, about 0.3 s (SR-384); a
  plain reading command like ls still starts none.'
examples:
- id: EX-1
  given: a machine with Claude Code and uv but no iaso anywhere
  when: the owner adds iaso's plugin list and installs the iaso plugin with Claude Code's plugin commands,
    then opens a session in any project
  then: /iaso, the iaso skills and the background checks are available, and nothing was written into that
    project
- id: EX-2
  given: the plugin installed and a session open in a project
  when: the installation is inspected
  then: 'nothing for Codex, Pi or Hermes was written: no AGENTS.md block, no .codex entry, no Pi extension,
    no Hermes plugin'
- id: EX-3
  given: an adopted project other than iaso's own repository, whose own development setup holds no iaso,
    or another iaso version
  when: any background check, the /iaso command or an in-app panel runs iaso
  then: it runs the plugin's own copy of iaso and uses nothing from the project's setup
- id: EX-4
  given: iaso's private copy of its tools is missing or older than the plugin, in an adopted project
  when: the first session starts
  then: it is set up once in the background, the owner sees one plain line saying iaso is getting ready,
    and checks that cannot run yet stay silent; in a project not adopted no such line appears
- id: EX-5
  given: setting up iaso's private copy fails (no Python 3.12 or later, or the install step fails)
  when: the session starts
  then: the owner sees one plain line saying iaso could not get ready and why, no half-built copy is left
    and the next session tries again
- id: EX-6
  given: the plugin and iaso's plugin list
  when: Claude Code's plugin validation runs on each
  then: both pass, and the validation lists what the in-app panels respond to
- id: EX-7
  given: a *.test.tsx file inside plugin/
  when: the plugin's bundle check runs
  then: it fails naming the file
- id: EX-8
  given: the repository path contains 'iaso'
  when: the agent runs ls
  then: no Python starts for the guard
- id: EX-9
  given: cmd.exe without sh on its PATH
  when: iaso.cmd runs
  then: it uses Git for Windows' sh.exe
