---
id: SR-313
title: The agent hears of a status change at its next step
feature: FEAT-005
statement: 'When iaso''s status changes during a session (its state, the counts, failing or out-of-date
  tests, stale links, what waits), the agent receives one line as text naming what changed since it last
  saw it, as soon as possible: at its next step (after a tool call), at the owner''s next message, or
  when a workflow it waits on ends. The per-step check reads only the status file and adds nothing when
  nothing changed; when it changed more than once the line gives the latest state. Its frequency is a
  setting whose default the owner sets from measured costs. It reaches the agent the same way on every
  host.'
examples:
- id: EX-1
  given: the status went from aligned to regression after a background refresh, mid-turn
  when: the agent's next tool call returns
  then: its context gets one line naming the new state and the failing requirement, before the owner says
    anything
- id: EX-2
  given: the status did not change since the agent last saw it
  when: a tool call returns or the owner sends a message
  then: no status line is added, and the check reads only the status file
- id: EX-3
  given: the status changed twice before the agent's next step
  when: the check runs
  then: one line gives the latest state
- id: EX-4
  given: the same change on Codex, which has no band
  when: the agent's next step runs
  then: it receives the same line as on Claude Code
- id: EX-5
  given: the session-start brief already gave the status
  when: the first message arrives with no change since
  then: the status is not repeated
- id: EX-6
  given: the per-step check and a stale-only refresh are measured on this machine
  when: the measurements are ready
  then: the owner is asked, with the numbers, how often the check and the refresh run, and the default
    follows the answer
proof:
  plan: In a live session, a background refresh turns the status to failing while the agent works; the
    agent mentions the change after its next step without the owner pointing it out; the owner is shown
    the measured cost of the per-step check and sets the frequency.
  kind: live-session
