id: SR-254
title: A merge is never green while an affected acceptance test lacks a...
feature: FEAT-003
statement: 'The merge check refuses a merge into the default branch while an acceptance test of a touched
  requirement, or of one covering a changed path, fails or lacks a passing run on the current identity;
  a failure stays until a run passes it. A regression is an existing test that passed and now fails; a
  new red test is not one; a same-tree rerun pass is flaky. Shared test infrastructure sets full verification
  pending: the quick check at merge never runs tests, holds with exit 5 and has the agent ask the owner
  once, through the question tool, to run the full suite now or waive it for this exact change; the pre-push
  check runs the full suite once while it is still pending, and a passing run clears it. The report-only
  form and the running form give the same verdict on the same tree. On a merge into a work branch these
  test problems are listed and never hold (DEC-271). A test in a frozen part (SR-380) counts in no merge
  hold (DEC-404). A branch''s green full run still counts after main moves (owner, 2026-11-12): when the
  merged tree differs from that run''s tree only in paths the test map covers (no shared test infrastructure,
  no source file without a covering test), the merge check runs only the covering tests of those paths,
  once, on the merged tree, and their pass counts as the full run of that tree; otherwise a full run is
  needed as before. A pyproject.toml whose only change is its [project] version (the landing''s bump,
  SR-377) is no shared test infrastructure change: it sets no full run pending and keeps that covering
  run; any other pyproject.toml change still does (owner, DEC-551).'

  plan: 'Four parts, each in a scratch repository with a green full run recorded. (i) EX-22: a covering
    test that fails on its first attempt and passes on the automatic retry; ''iaso repin --after-tests''
    on the stale link refuses it and names that test as needing a retry, and the link stays stale; with
    a clean first-attempt pass the same repin succeeds. (ii) EX-11, the waiver by question: a change that
    puts the full run pending; the merge check holds and tells the agent to ask the owner once through
    the question tool (iaso tests ask-waiver --merge <base> prints the question, run or waive); the owner''s
    ''waive'' answer (a scripted owner when no live owner is present) is recorded as the waiver for that
    exact change and the merge check then passes; a later edit holds it again. (iii) Main moves by one
    covered source file and is merged in: the merge check runs only that file''s covering tests, once,
    on the merged tree, and their pass counts as the merged tree''s full run; when main moves again with
    no new run, that covering run no longer counts; a change to shared test infrastructure (pyproject.toml)
    still needs a full run. (iv) A landing''s [project] version bump of pyproject.toml alone sets no full
    run pending; after main moves by that bump and one covered source file, the merge check runs only
    that file''s covering tests; a pyproject.toml change beyond its version line (a pytest setting) still
    sets a full run pending and runs the whole suite.'
