---
id: SR-243
title: JEV's provider and credential name are settings; the key never...
feature: FEAT-002
statement: JEV is reached only through the judgment protocol; its provider preset, model and credential
  variable are settings. The key is read from the environment or a user-level env file outside the repository,
  never written to any repository file, log, notice or output; JEV status reports provider, endpoint,
  key source, reachability and version without the key.
examples:
- id: EX-1
  given: judgment.backend jev and no credential in the environment
  when: a hook asks for an intent-change judgment
  then: iaso says the JEV credential is missing, naming the variable, once for the session; no heuristic
    answers
- id: EX-2
  given: any repository
  when: iaso jev setup --env-var MY_KEY runs
  then: config.yaml names MY_KEY, a jev-setup event holds the name, and no secret is written anywhere
- id: EX-3
  given: 'judgment.jev says provider: openrouter and nothing else'
  when: iaso loads its config
  then: JEV posts to https://openrouter.ai/api/alpha/decisions with model typesafe/jev-1.13, validated
    against typesafe/jev-1.13, reading OPENROUTER_API_KEY; any judgment.jev value set explicitly (base_url,
    path, model, validated_against, credential_env) wins over the preset
- id: EX-4
  given: OPENROUTER_API_KEY is not in the environment and ~/.config/iaso/jev.json names an env file outside
    the repository that holds it
  when: iaso resolves the JEV key
  then: the key is read from that file in place, the source label is env-file, and the key is written
    to no repository file, log entry, judgment record, notice or output; an env file inside the repository
    is refused
- id: EX-5
  given: the owner says /iaso jev setup openrouter and names an env file outside the repository
  when: the agent runs the setup
  then: config.yaml gets only provider, model and the variable name, the user-level jev.json names the
    variable and the env file, and /iaso jev status shows the provider, endpoint, key source label, reachability
    and the normalized resolved version, never the key
- id: EX-6
  given: an earlier setup left a base_url, path or validated version for one JEV provider
  when: the owner says /iaso jev setup with another provider
  then: config.yaml keeps none of the earlier provider's base_url, path, model or validated_against; the
    new provider's preset applies; other judgment.jev settings such as thresholds stay
- id: EX-7
  given: JEV is set up or not, calibrated or not, the fast track on or off
  when: the owner says /iaso jev status or /iaso jev calibrate
  then: the status and refusal text name /iaso commands or plain words, never a iaso CLI command, a record
    id or 'in your terminal'
proof:
  plan: 'Recommended: in a scratch repository the owner says /iaso jev setup openrouter naming an env
    file outside it, then /iaso jev status; the owner sees status show reachability and version without
    the key, and watches the agent search the repository and its log for the key and find nothing. The
    owner decides whether this is the proof.'
  kind: command
