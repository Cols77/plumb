id: SR-397
title: An independent evaluator's verified verdict confirms a proof
statement: 'When the owner picked the evaluator, iaso starts at the end of the build, for a requirement''s
  proof, a fresh agent session that took no part in the build. It is given the requirement, its examples,
  the stated proof and the built tree, and nothing of the builder''s conversation. It writes an evaluation
  case (the requests to send and the checks to run) and runs it with iaso evaluate''s parts: a scratch
  repository with the branch''s iaso set up, headless Claude Code turns, the scripted owner answering
  the questions raised, and the checks. It ends on one verdict: verified, not verified (with what was
  not shown) or could not check (with why). Verified is recorded as the proof''s evidence with the run''s
  folder and confirms the proof: done and the merge accept it as they accept the owner''s yes, and the
  owner is told the verdict and where the evidence is, not asked. Could not check: the owner is asked
  ''Did you see it working?'' for that proof only. The owner overrules a verdict by saying so, which opens
  the proof again. For a proof the evaluator was picked for, done refuses passing evidence that neither
  the evaluator''s verdict nor the owner''s yes confirmed. The verdict is logged by iaso''s evaluator
  run, never by the building agent, and counts only for the requirement''s words and evidence it was given
  on.'
examples:
- id: EX-1
  given: the owner picked the evaluator and the build of a requirement is finished
  when: the evaluator's case runs and shows what the proof states
  then: the verdict is verified, the run's folder is recorded as the proof's evidence, the loop's final
    message names the requirement as verified with where the evidence is, and the owner is asked nothing
  quote: This agent should spin up an evaluation case that confirms proof was verified
  prompt: 522ae60df99a64e9
- id: EX-2
  given: a requirement with a verified verdict on its current words and evidence
  when: the loop is called done and its branch is merged into main
  then: neither done nor the merge check names that requirement as not shown or not confirmed
- id: EX-3
  given: a proof that only the owner's own screen shows
  when: the evaluator cannot reproduce it
  then: the verdict is could not check with the reason, and the owner is asked 'Did you see it working?'
    for that proof only
- id: EX-4
  given: a requirement the evaluator verified
  when: the owner says they do not accept that verdict
  then: the proof is open again and done and the merge refuse it until it is confirmed anew
- id: EX-5
  given: the building agent writes a verified verdict by hand, with no evaluator run
  when: done or the merge check reads the proof
  then: it does not count as confirmed
- id: EX-6
  given: a requirement reworded after the evaluator verified it
  when: done or the merge check reads the proof
  then: the earlier verdict no longer counts
- id: EX-7
  given: the evaluator is started for a proof
  when: its session opens
  then: it holds the requirement, its examples, the stated proof and the built tree, and no part of the
    builder's conversation
  quote: And independant agentic step that takes care of that would be nice
  prompt: 522ae60df99a64e9
- id: EX-8
  given: a proof whose case needs a session of the agent under iaso
  when: the evaluator runs it
  then: it uses the scratch repository, the headless turns and the scripted owner that iaso evaluate uses
  quote: The evaluator would re-use components from the iaso:iaso evaluate feature
  prompt: 522ae60df99a64e9
- id: EX-9
  given: the evaluator's run folder, which it passes as an absolute path
  when: its verified verdict is recorded
  then: the proof's evidence and the logged verdict name the folder by its repository path, or as '<name>
    (not kept)' when it lies outside the repository, never by its machine path (report-bb6888e4)
- id: EX-10
  given: a proof whose case needs a live session of the agent and the judge, on a machine with claude
    installed and a judge key set up
  when: the evaluator runs the case in its sandbox
  then: the case run finds the installed claude command and reaches the judge, whose key is read where
    it already lives and never copied, printed or written into the scratch repository or the run folder
  quote: Yes, give it claude and the judge (Recommended)
