---
id: SR-205
title: The Obsidian view is generated and never approves
feature: FEAT-005
statement: On the owner's request iaso writes an Obsidian vault, one note per record with links by title,
  plus an intent-map canvas, generated and byte-identical on regeneration. iaso never reads the vault
  back, so editing a note changes no record. A note names no command to run and no record id.
examples:
- id: EX-1
  given: a repository with records
  when: the view is written twice
  then: the two outputs are byte-identical
- id: EX-2
  given: the owner edits a requirement's note in the vault to say approved
  when: iaso's status is next shown
  then: the requirement's state is unchanged
- id: EX-3
  given: the generated intent-map canvas
  when: it is parsed
  then: it is valid JSON Canvas with unique node ids and an edge for each derives-from link
- id: EX-4
  given: a requirement awaits arbitration
  when: the owner opens its note in the vault
  then: the note says iaso will ask in the session through the question tool, names no command to run
    and no id, and shows its links by title
proof:
  plan: 'Recommended: the owner asks /iaso view, opens the vault in Obsidian, sees the intent map and
    a note, edits the note, and sees iaso''s status unchanged. The owner decides whether that is the
    proof.'
