id: SR-198
title: Drift on linked code is resolved in the turn that makes it
feature: FEAT-002
statement: 'After each edit iaso tells the agent which links it made stale, and the end-of-turn hook holds
  the turn while a link this turn made stale is unresolved, at most hooks.stale_holds_max times (3 by
  default); after that the turn ends and the unresolved link becomes one question through the question
  tool; iaso files it as a question for the agent to ask, which iaso withdraws by itself once the link
  is current again, and nothing is shown to the owner to press. A check that waits on an unreachable judge
  never holds the turn. The link is repinned when covering tests pass and the judge says the meaning is
  kept, a record that disagrees with its intent is reworded, an unrequested intent-breaking change goes
  back to the agent, and the owner is asked through the question tool only when confirmed intent would
  change. Workflow agents get the same. In main''s checkout the turn is not held for a stale link: no
  work happens there, and it is resolved on a branch (SR-384).'
examples:

    not repinned

  given: the judge cannot be reached

    is decided by rule, and the turn is not held for the check that waits on the judge

  when: the agent resolves the link
