id: SR-207
title: A hidden regression of an approved example holds until the test...
feature: FEAT-001
statement: 'When an approved example''s acceptance test is changed so that a regression now passes, iaso
  names it a hidden regression: the stop hook blocks the agent once naming the example, the agent asks
  the owner about it through the question tool, the owner gets the one plain regression line of SR-373
  with the block, and the stop that follows the block adds no owner text, status and drift name it, and
  the merge check lists the changed test and the regression and exits 5. It resolves when the test body
  that passed before passes again, when the owner agrees, or when a background judge job reads the test
  edit as a real, needed change with confidence of at least 0.8; until that job answers, or if it fails,
  the flag stays, and no hook calls a model (SR-273). Wanting the example''s outcome to change is a change
  of older intent, put to the owner through the question tool. An acceptance test extended with no regression
  goes back through the judge cascade and holds the merge only until a run passes its original body (DEC-261).'
examples:
- id: EX-1
  given: an approved requirement whose example "given a=1 and b=2 ... then it returns 3" is verified by
    tests/test_mod.py, a passing full run, then add() changed to subtract and the run reporting the regression
  when: the agent rewrites the test to assert add(1, 2) == -1, it passes, and the merge check runs
  then: it lists the requirement as "(acceptance test changed)" with the example and the test diff, lists
    the failing acceptance test as "regression, hidden", and exits 5
- id: EX-2
  given: the same turn
  when: the stop hook runs
  then: it blocks the agent once with "regression hidden" naming the requirement's example, the agent
    asks the owner about it through the question tool, the owner sees one plain line naming the behaviour
    that worked before and now fails (SR-373), and the stop that follows the block adds no owner text
- id: EX-3
  given: the same change
  when: iaso status and iaso drift run
  then: both name the changed acceptance test and the hidden regression
- id: EX-4
  given: an approved acceptance test extended with a new passing test, no regression
  when: the merge check runs
  then: the requirement is listed as "acceptance test changed" and goes back through the judge cascade;
    the merge does not hold on it once a run passes the test's original body, and the owner is not asked
- id: EX-5
  given: a regression on test body h1
  when: a pass comes on test body h2, then a pass on h1
  then: the first pass marks it hidden; only the pass on h1 resolves it, unless the background judge reads
    the h2 edit as real and needed (EX-6)
- id: EX-6
  given: a hidden regression of an approved example, and the agent or the owner wanting the example's
    outcome to change
  when: the background judge job (queued when the hidden regression is seen, retried at turn end up to
    three times, then a debug hand-off) reads the test edit against the requirement and its examples
  then: a confident verdict (0.8 or more) that the edit was real, needed and makes sense drops the flag;
    a verdict that it was made only to pass, a doubtful one, no answer yet or a failed job keeps it, and
    the merge holds until the original test passes again or the owner agrees; a change of the example's
    outcome is still put to the owner through the question tool
  quote: This flag should be raised after an actual judge reviews whether the change was done solely so
    that the test is passed or whether it was a real, needed and making sense change.
- id: EX-7
  given: a hidden regression of an approved example is seen by a hook or a check
  when: the check runs
  then: a background judge job for that test edit is queued once, keyed by the changed test body, no model
    is called inside the hook, and the flag is raised with the line saying a judge is reading the change
- id: EX-8
  given: the judge job has logged its verdict for a changed test body
  when: the merge check or the stop hook lists regressions
  then: 'the stored verdict decides: real with confidence 0.8 or more drops the flag, anything else keeps
    it; the verdict never approves a record, and a further edit of the test is a new question'
