id: SR-414
title: A loop's window comes to the front instead of opening twice
statement: 'When the owner asks to see a loop in its own window, from the action on its row in the loops
  class of iaso''s pane or asked of the agent of any session, iaso looks for the session working on it:
  when one is live and its window can be found, that window is brought to the front of the computer and
  nothing new opens; when the platform cannot bring it forward, iaso says so and names the session so
  the owner can find the window; when no session works on the loop, a new session opens on it as SR-394
  says. The full detail of a loop (its records and each requirement''s proof) is read in that window;
  the pane''s row keeps the loop''s main details.'
examples:
- id: EX-1
  given: a loop is live in another Claude Code window on this computer
  when: the owner presses 'show its window' on its row
  then: that window comes to the front; no new session or window opens
- id: EX-2
  given: a loop is live but the platform gives iaso no way to raise windows
  when: the owner presses 'show its window'
  then: iaso says it cannot bring the window forward and names the session and its folder; nothing opens
- id: EX-3
  given: a loop no session works on
  when: the owner presses its row's action
  then: a new session opens on it in its own window, as SR-394 says, and the row reads live once it starts

    action in the pane brings that window to the front and opens nothing new; the evaluator checks it
    from the session logs and a screenshot'
