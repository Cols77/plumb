---
id: SR-307
title: Tests that depend on machine load wait for free CPU
feature: FEAT-001
statement: A test whose result depends on machine load (a time budget) is marked as such and checks its
  budget through an explicit helper that raises a distinct budget miss. Before it runs it waits until
  the machine's CPU is free, at most five minutes; when it still fails with that budget miss it is reported
  as load-bound, counts as passed for the merge check and the status, and a debug case is written to make
  it pass. An unmarked test, or a marked one failing any other way, including a plain assertion whose
  message names a duration, fails as usual.
examples:
- id: EX-1
  given: a marked timing test and the CPU at 90%
  when: the suite reaches it
  then: it waits until the CPU is below 50%, then runs
- id: EX-2
  given: a marked timing test whose budget helper raises a budget miss after waiting
  when: the suite ends
  then: it is reported as load-bound, the merge is not refused for it, and one debug case names it
- id: EX-3
  given: a marked test failing on an assertion that is not its time budget
  when: the suite ends
  then: it fails as usual
- id: EX-4
  given: the CPU stays busy for five minutes
  when: a marked test waits
  then: it runs anyway and says it ran under load
- id: EX-5
  given: a marked test failing a plain assert whose message reads 'took 9 ms, 1 ms budget'
  when: the suite ends
  then: it fails as usual, not as load-bound
proof:
  plan: 'The full suite under load: the timing tests wait, then pass or are reported load-bound with a
    debug case; no unmarked failure is hidden.'
