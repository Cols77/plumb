title: A question raised in a workflow or subagent reaches the owner...
feature: FEAT-005
statement: 'A question that arises where no question tool exists (a workflow agent, a subagent, a headless
  run), such as a link whose meaning changed, comes back to the owner through the main session''s question
  tool: the main agent is told as text to ask it, at the end of its turn (the nudge at the end of the
  turn, not a reminder at each owner message) or when the workflow ends and wakes it, worded for the owner
  with its options and their consequences and no ids. What it files is never left unasked. The owner''s
  answer goes back to what raised it. An intent question goes to the owner, not to the debug workflow;
  plumb''s own failures still go to debugging.'
examples:
- id: EX-1
  given: a workflow agent's edit leaves a link whose meaning changed and the agent has no question tool
  when: the main session's turn ends or the workflow ends and wakes it
  then: the main agent is told as text to ask it, and asks it with the question tool, with its options
    and their consequences and no id
  quote: workflow questions come back to me
- id: EX-2
  given: the owner answers that question
  when: the answer arrives
  then: it is applied to the link or record that raised it, and the question is not asked again
- id: EX-3
  given: the owner dismisses the question
  when: the turn goes on
  then: it is not asked again in a loop that session, and the status says it awaits the owner
- id: EX-4
  given: two workflow agents raise the same question about the same link
  when: the main session asks
  then: the owner is asked once
- id: EX-5
  given: a workflow agent hits plumb's own failure, not an intent choice (a job error)
  when: it is found
  then: it goes to the debug workflow and is not put to the owner as a question
- id: EX-6
  given: a workflow question is waiting
  when: the workflow's other items run
  then: they go on; only the item that needs the answer holds
