---
id: SR-181
title: Hook time limits are settings with defaults that survive a loaded...
statement: The watchdog's hard limit (hooks.hard_limit_s, default 30 s) and each hook's soft budget (hooks.budget_ms,
  default 20 s for session start, prompt and stop, 5 s after an edit) are settings read from .plumb/config.yaml,
  as are the covering-test budget of a turn (verify.turn_budget_s, default 60 s) and the judge's time
  inside a hook (judgment.hook_timeout_ms, default 5 s). The defaults sit above what a loaded machine
  needs and below the host's own hook timeouts (60 s, 120 s for the stop and async hooks), so a hook is
  cut only when it is truly stuck.
examples:
- id: EX-1
  given: a loaded machine where a hook takes 4 s to answer
  when: the hook runs with the default settings
  then: it is not cut and its check is not skipped
- id: EX-2
  given: a hook that never answers
  when: the hard limit passes
  then: the watchdog cuts it with the budget notice, at the configured value
- id: EX-3
  given: config.yaml sets hooks.hard_limit_s and hooks.budget_ms
  when: the settings are loaded
  then: the watchdog and the budgets use those values, and the defaults apply when unset
- id: EX-4
  given: the default hard limit plus the stop hook's grace
  when: the host hook timeouts are read from the plugin bundle
  then: every one of them is above that sum
