---
id: SR-026
title: A change no requirement owns is read back and put to the owner
feature: FEAT-001
statement: A changed source path that no requirement owns through an implemented_by or verified_by link
  is an untraced change. The stop hook names it in the owner summary and tells the agent, without blocking,
  to read the change back and record a proposed SR with examples linked to it; the always-loaded CLAUDE.md
  block asks for a read-back of each request; plumb validate --merge lists untraced changes in the same
  trigger-2 question as unconfirmed touched requirements and exits 4 until a requirement owns them or
  the owner exempts them in trace.exempt.
examples:
- id: EX-1
  given: a turn writes src/app/mul.py and no requirement links it
  when: the stop hook runs
  then: the summary names src/app/mul.py as untraced and the next prompt tells the agent to read it back
    and record a proposed SR, and the turn is not blocked
- id: EX-2
  given: the stop hook already blocks the turn to run covering tests
  when: an untraced change exists
  then: the block reason also carries the read-back instruction, once
- id: EX-3
  given: a branch adds src/mul.py and no requirement owns it
  when: plumb validate --merge BASE runs
  then: it exits 4 and lists src/mul.py under untraced changes with the way to resolve it
- id: EX-4
  given: generated files (__pycache__, *.pyc), tests, docs, records or a path under trace.exempt
  when: they change
  then: they are never untraced changes
- id: EX-5
  given: plumb is installed in a repository
  when: CLAUDE.md is written
  then: its plumb block tells the agent to read back each request and record it as proposed
