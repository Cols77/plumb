---
id: SR-277
title: The agent gets each relevant record once per session
feature: FEAT-005
statement: Every agent-facing line from plumb's hooks and API passes through one emitter that gives the
  agent each relevant record once per session, again only when its hash or state changes or after a /clear
  or compaction, never cuts a must or one-shot line, and, when the budget leaves a record out, points
  to plumb show for it; the session start gives the session lines of the one table of insights (SR-374),
  not a separate short brief (INT-114).
examples:
- id: EX-1
  given: 10 prompts about the same three unchanged records
  when: the prompt hook runs each time
  then: each record's line is injected once
- id: EX-2
  given: an untraced-change instruction already emitted for src/app/mul.py
  when: the next prompt hook runs with the path still untraced
  then: the instruction is not repeated
- id: EX-3
  given: SR-004 changed after its line was injected
  when: the next prompt mentions it
  then: its line is injected once more with the new state
- id: EX-4
  given: a queued untraced-change instruction for src/app/mul.py, whose note the hook consumes when it
    reads it, and relevant records that fill hooks.prompt_tokens
  when: the prompt hook runs
  then: the instruction is injected all the same; a one-shot line (queued instruction or escalation) is
    never cut by the budget
- id: EX-5
  given: the owner types the same words ("continue", "ok") in two turns of one session
  when: each turn's stop finds covering tests without fresh evidence
  then: each turn blocks once with the covering-tests instruction; a per-turn line is deduplicated within
    its turn, never for the whole session
- id: EX-6
  given: a session whose first prompt injected "SR-003 [proposed] Links pin both ends"
  when: a second prompt names SR-003 again and nothing changed
  then: the hook injects nothing; another session still gets the line
- id: EX-7
  given: the same session
  when: SR-003's statement is edited and a prompt names SR-003 and SR-004
  then: only the SR-003 line is injected again
- id: EX-8
  given: SR-004 injected as proposed
  when: it is approved (by the judge or the owner's answer) and a prompt names it
  then: '"SR-004 [approved]" is injected once with the compare line, and not on the next prompt'
- id: EX-9
  given: a prompt budget that fits one line and a prompt naming SR-003 and SR-004
  when: the hook runs twice
  then: the first injects SR-003 and points to plumb show SR-004, which is not marked as given; the second
    injects SR-004 only
- id: EX-10
  given: SR-003 already given this session
  when: the owner runs /clear or the context is compacted
  then: the next prompt naming SR-003 injects its line again
proof:
  plan: 'Recommended for the owner to decide: a hook test runs ten prompts naming the same three records
    in one session and shows each line injected once, re-injected after an edit and after /clear.'
  kind: hook
