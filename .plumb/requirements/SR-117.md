---
id: SR-117
title: Project context settles the clearly safe requirements
statement: 'A proposed requirement settles by context when all hold: every implemented_by link is current
  and its code exists; its covering tests ran and passed on the current tree; an independent model (not
  the coding agent) judges it consistent with every owner-confirmed record and with the linked code; it
  is not a decision, an intent, an escalated set member, or an edit of an owner-confirmed record. The
  approval is logged as ''by: context'' with the tests, the model and its verdict, listed to the owner
  once, and revocable in one step. Losing any condition makes it proposed again.'
examples:
- id: EX-1
  given: SR-013 with current links, its covering tests passing and the model judging it consistent with
    the confirmed records
  when: context settling runs
  then: SR-013 is settled by context, logged with the test run and the verdict, and listed to the owner
    once
- id: EX-2
  given: SR-020 whose covering test fails
  when: context settling runs
  then: SR-020 stays proposed
- id: EX-3
  given: a requirement with a stale implemented_by link
  when: context settling runs
  then: it stays proposed until the link is repinned
- id: EX-4
  given: DEC-030, a decision that matters, and INT-017, an intent
  when: context settling runs
  then: neither is settled by context
- id: EX-5
  given: a requirement settled by context
  when: one of its covering tests later fails
  then: it is proposed again and the owner sees why
- id: EX-6
  given: the model judges a requirement inconsistent with the owner-confirmed INT-028
  when: context settling runs
  then: it is not settled and it reaches the owner as a card naming the disagreement
- id: EX-7
  given: no model can be reached
  when: context settling runs
  then: nothing is settled and the owner sees the error
