---
id: SR-077
title: A quick merge check holds open intent conflicts
feature: FEAT-006
statement: 'plumb check --merge and plumb merge-check list every open intent conflict as a card and wait
  for the owner''s choice (exit 4). /plumb init and plumb hooks install also install, by default, a quick
  merge-time check as git''s pre-merge-commit and prepare-commit-msg hooks (R17): it holds a merge carrying
  an open intent conflict, a touched requirement not yet confirmed, a file no requirement declares or
  two records holding one ID, however the merge is recorded (git merge, git pull, or git commit finishing
  it), and a rebase, cherry-pick or revert step carrying an open intent conflict; it judges what git will
  record and runs no test suite (the one full run happens at push, in the pre-push hook); a foreign hook
  is left untouched.'
examples:
- id: EX-1
  given: a merge result with IC-001 open
  when: plumb check --merge main runs
  then: it exits 4 and shows the conflict card
- id: EX-2
  given: the pre-merge-commit hook is installed
  when: git merge produces IC-001
  then: git does not record the merge commit and the output names the conflict and /plumb conflicts
- id: EX-3
  given: a foreign pre-merge-commit hook
  when: the install runs
  then: the foreign hook is untouched and the output says how to call plumb from it
- id: EX-4
  given: the quick merge check is installed
  when: git merge runs on a branch whose tests were never run
  then: the check reports what holds the merge without starting any test run
- id: EX-5
  given: a repository adopted with /plumb init
  when: git hooks are listed
  then: the quick merge check is installed and the full test run stays at push
- id: EX-6
  given: a merge held by IC-001
  when: the owner chooses a side and the touched requirements are confirmed
  then: the quick check passes and the merge can be finished
- id: EX-7
  given: JEV is configured and a merge leaves IC-001 open
  when: the pre-merge-commit or the pre-push hook shows its card
  then: no judgment is requested and nothing is written to the log; the card shows a judgment only when
    one is already logged
- id: EX-8
  given: a repository adopted with /plumb init or plumb hooks install
  when: git hooks are listed
  then: the quick merge check and the pre-push hook (the one full test run) are both installed, and a
    pre-push hook plumb did not write is left untouched
- id: EX-9
  given: the quick merge check is installed and a merge leaves IC-001 open or touches an unconfirmed requirement
  when: 'the merge is finished by hand: git commit after a text conflict or after git merge --no-commit,
    git merge --continue, or git pull'
  then: git does not record the merge commit and the output names what holds it; a choice left out of
    the commit holds it too
- id: EX-10
  given: the quick merge check is installed
  when: a rebase, cherry-pick or revert step meets an intent conflict on a record
  then: git stops on the record; continuing with the conflict still in it is refused, and after the owner's
    choice the step continues with the chosen version
- id: EX-11
  given: the owner confirmed an early decision that chose between exactly the two versions of SR-005 a
    merge meets
  when: the quick merge check, plumb merge-check or /plumb conflicts meets the resulting intent conflict
  then: it is settled with the owner's answer (logged and staged), the card says it is already answered,
    nothing is asked again, and "finish the merge" records it
- id: EX-12
  given: an early decision on SR-005 was never answered and the merge leaves an intent conflict on SR-005
  when: the quick merge check runs and the owner then picks a side on the conflict card
  then: only the conflict card asks (the decision is not listed beside it), and the owner's pick also
    answers the decision
- id: EX-13
  given: /plumb init adopted the repository, main has not moved since feat-x branched, and feat-x touches
    an unconfirmed requirement and a file no requirement declares
  when: feat-x is merged into main with a plain git merge, a git pull, or an explicit fast-forward (git
    merge --ff-only, git pull --ff-only)
  then: nothing held stays recorded on main; a plain merge or pull records a merge commit the quick check
    holds, and an explicit fast-forward is checked after git made it and main is put back where it was,
    with local changes kept and the owner told to say "merge feat-x"
