---
id: SR-320
title: A finished worktree is removed at a landing
feature: FEAT-003
statement: At a landing into main, a worktree whose branch this landing merged, with no uncommitted changes
  (untracked files under the log and cache folders aside) and no open intent loop naming it, is removed
  with its branch. A finished worktree with uncommitted changes or an open loop naming it is kept, and
  the landing line names it with the reason. The main checkout, the worktree the landing runs in, a detached
  worktree and a worktree whose branch is not merged are never touched.
examples:
- id: EX-1
  given: a worktree whose branch the landing merged, with only an untracked log entry
  when: the landing runs
  then: the worktree and its branch are gone and the landing line names the worktree as removed
- id: EX-2
  given: a worktree whose branch the landing merged, with an uncommitted change to notes.md
  when: the landing runs
  then: the worktree stays and the landing line says it finished but is kept for uncommitted changes
- id: EX-3
  given: a worktree whose branch the landing merged, named by an open intent loop
  when: the landing runs
  then: the worktree stays and the landing line says it finished but is kept for an open intent loop
- id: EX-4
  given: a worktree whose branch is not merged
  when: the landing runs
  then: the worktree and its branch are untouched and the landing line does not name it
proof:
  plan: impl/fit's landing removes a finished worktree and keeps a busy one
  kind: command
