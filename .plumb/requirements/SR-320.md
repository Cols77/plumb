---
id: SR-320
title: A finished worktree is removed at a landing
feature: FEAT-003
statement: At a landing into main, a worktree whose branch has at least one commit of its own and is merged
  into main, whether this landing or an earlier one merged it, with no uncommitted changes (untracked
  files under the log and cache folders aside) and no open intent loop naming it, is removed; its branch
  is kept. A finished worktree with uncommitted changes or an open loop naming it is kept, and the landing
  line names it with the reason; its worktree is removed at a later landing once it is clean. The main
  checkout, the worktree the landing runs in, a detached worktree, a worktree whose branch is not merged
  and a fresh fork with no commit of its own are never touched.
examples:
- id: EX-1
  given: a worktree whose branch the landing merged, with only an untracked log entry
  when: the landing runs
  then: the worktree is gone, its branch stays, and the landing line names the worktree as removed
- id: EX-2
  given: a worktree whose branch the landing merged, with an uncommitted change to notes.md
  when: the landing runs
  then: the worktree stays and the landing line says it finished but is kept for uncommitted changes
- id: EX-3
  given: a worktree whose branch the landing merged, named by an open intent loop
  when: the landing runs
  then: the worktree stays and the landing line says it finished but is kept for an open intent loop
- id: EX-4
  given: a worktree whose branch is not merged
  when: the landing runs
  then: the worktree and its branch are untouched and the landing line does not name it
- id: EX-5
  given: a worktree kept at an earlier landing for an uncommitted change, now clean, its branch merged
  when: the next landing runs
  then: the worktree is gone, its branch stays, and the landing line names it as removed
- id: EX-6
  given: a worktree just created with no commit of its own
  when: a landing runs
  then: the worktree and its branch are untouched and the landing line does not name it
- id: EX-7
  given: a branch with its own commit merged by fast-forward
  when: the landing runs
  then: the worktree is gone and its branch stays
- id: EX-8
  given: a worktree whose branch was only reset or rebased onto main, clean and merged
  when: a landing runs
  then: the worktree and its branch are untouched and the landing line does not name it
- id: EX-9
  given: a worktree whose branch the landing merged, with an open adopted intent loop in its own session
    that names no path
  when: the landing runs
  then: the worktree stays and the landing line says it finished but is kept because an open intent loop
    lives there
proof:
  plan: at the next landing into main, a finished clean worktree is removed and its branch is still listed
    by git branch; a worktree with uncommitted changes is kept and named
  kind: command
  post_merge: true
