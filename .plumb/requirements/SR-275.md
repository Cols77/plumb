---
id: SR-275
title: Hook time limits are generous settings the owner can raise
feature: FEAT-001
statement: Every time limit around plumb's hooks (the watchdog's hard limit, each hook's soft budget,
  a turn's covering-test budget, the judge's and git's time inside a hook) is a setting whose default
  is generous enough that a hook is cut only when truly stuck. The owner changes a limit by asking in
  plain words, and limits may grow past today's, up to what the plugin's fixed host hook timeouts allow.
examples:
- id: EX-1
  given: a loaded machine where a hook takes 4 s to answer
  when: the hook runs with the default settings
  then: it is not cut and its check is not skipped
- id: EX-2
  given: a hook that never answers
  when: the hard limit passes
  then: the watchdog cuts it with the budget notice, at the configured value
- id: EX-3
  given: .plumb/config.yaml sets hooks.hard_limit_s and hooks.budget_ms
  when: the settings are loaded
  then: the watchdog and the budgets use those values, and the defaults apply when unset
- id: EX-4
  given: the default hard limit plus the stop hook's grace
  when: the host hook timeouts are read from the plugin bundle
  then: every one of them is above that sum
- id: EX-5
  given: the owner says "let the hooks run up to 45 seconds"
  when: the agent applies it
  then: the hard limit becomes 45 s in .plumb/config.yaml and the next hook is cut only after 45 s; the
    owner typed no command
- id: EX-6
  given: the owner asks for hooks to run up to two minutes, above the plugin's 60 s host hook timeouts
  when: the agent applies it
  then: the hard limit is set to 59 s, the most the host timeouts allow with the stop hook's 1 s grace,
    and the agent tells the owner the host would cut a longer hook first
- id: EX-7
  given: plumb's own repository
  when: each hook runs as a subprocess
  then: each finishes within its configured budget
- id: EX-8
  given: a settled line and a question to show at the end of a turn
  when: the stop hook runs
  then: the turn-end plumb line is produced within the stop budget
- id: EX-9
  given: a hook raises an internal error
  when: the host calls it
  then: it writes the error to the session error log, exits 0 so the host goes on, and the plumb line
    says one case went to debugging
proof:
  plan: 'Recommended for the owner to decide: a hook test drives each hook with a scripted 4 s delay (not
    cut, check not skipped) and with a hang (cut at the configured hard limit with the budget notice);
    then, in a live session, the owner asks in plain words for a longer limit and sees the agent apply
    it and the plugin''s host timeouts stay above it.'
  kind: hook
