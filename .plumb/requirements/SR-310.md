---
id: SR-310
title: Hook limits default to 90 s, with budgets and host timeouts scaled...
feature: FEAT-001
statement: 'Every time limit around plumb''s hooks (the watchdog''s hard limit, each hook''s soft budget,
  a turn''s covering-test budget, the judge''s and git''s time inside a hook) is a setting whose default
  is generous enough that a hook is cut only when truly stuck: the hard limit defaults to 90 s, the session-start,
  prompt and stop budgets to 60 s and the after-edit budget to 15 s, and the plugin''s fixed host hook
  timeouts sit above the hard limit plus the stop hook''s grace. The owner changes a limit by asking in
  plain words, up to what the host hook timeouts allow.'
examples:
- id: EX-1
  given: no hook settings in .plumb/config.yaml
  when: the settings load
  then: the hard limit is 90 s, the session-start, prompt and stop budgets are 60 s and the after-edit
    budget is 15 s
  quote: hook limit to 90 s
  prompt: 240b6dca7a199be4
- id: EX-2
  given: a loaded machine where a hook takes 40 s to answer
  when: the hook runs with the default settings
  then: it is not cut and its check is not skipped
- id: EX-3
  given: a hook that never answers
  when: the hard limit passes
  then: the watchdog cuts it with the budget notice, at the configured value
- id: EX-4
  given: .plumb/config.yaml sets hooks.hard_limit_s and hooks.budget_ms
  when: the settings load
  then: the watchdog and the budgets use those values, and the defaults apply when unset
- id: EX-5
  given: the default hard limit plus the stop hook's grace
  when: the host hook timeouts are read from the plugin bundle
  then: every one of them is above that sum
- id: EX-6
  given: the owner says "let the hooks run up to 100 seconds"
  when: the agent applies it
  then: the hard limit becomes 100 s in .plumb/config.yaml and the next hook is cut only after 100 s;
    the owner typed no command
- id: EX-7
  given: the owner asks for hooks to run up to five minutes, above the plugin's host hook timeouts
  when: the agent applies it
  then: the hard limit is set to the most the host timeouts allow with the stop hook's grace, and the
    agent tells the owner the host would cut a longer hook first
- id: EX-8
  given: plumb's own repository
  when: each hook runs as a subprocess
  then: each finishes within its configured budget
- id: EX-9
  given: a hook raises an internal error
  when: the host calls it
  then: it writes the error to the session error log, exits 0 so the host goes on, and the plumb line
    says one case went to debugging
proof:
  plan: In a live Claude Code session on this repository, a hook delayed by 40 s finishes and its check
    runs instead of being cut, and the hook timeouts in the installed plugin read above 90 s; a hook test
    shows a hang cut at 90 s with the budget notice.
  kind: live-session
