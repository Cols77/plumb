---
id: SR-002
title: Record hashes ignore formatting and change with meaning
feature: FEAT-001
statement: A record's content hash covers every frontmatter field except links plus the normalized body;
  it ignores YAML style, key order, CRLF, trailing whitespace and derived blocks, and changes when the
  meaning (for example the statement) changes.
examples:
- id: EX-1
  given: SR-001 with a pinned hash
  when: the file is re-saved with CRLF line endings, reordered keys and trailing spaces
  then: its hash is unchanged
- id: EX-2
  given: SR-001 with a pinned hash
  when: its statement is edited
  then: its hash changes
- id: EX-3
  given: a linked source file
  when: it is re-saved with CRLF line endings and no other change
  then: the file end's hash is unchanged
