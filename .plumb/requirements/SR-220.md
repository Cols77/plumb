---
id: SR-220
title: What plumb cannot settle goes to a debug workflow, the owner last
feature: FEAT-008
statement: When plumb cannot settle or converge (a failure in its own step, missing information, or a
  judge cascade still not clear after its round limit, 3 rounds by default per P9), it opens a debug workflow
  in the background. The workflow reads the log, the records and the repository, reruns the failed step
  once, and reports to the agent as text what happened and what is missing; plumb debug and plumb status
  say how many cases are in debugging and how many it resolved, and the turn end says nothing about debug
  hand-offs (INT-114). It may rerun a step; it never changes a record's meaning and never approves anything.
  An intent choice goes to the owner as a question, not to debugging.
examples:
- id: EX-1
  given: the judge cascade on a requirement is still not clear after 3 rounds (P9's default round limit)
  when: the limit is reached
  then: the case is logged as sent to debugging and plumb debug lists it, the agent gets one text line
    naming the requirement, and the owner is not asked about the requirement's wording
- id: EX-2
  given: the settling job fails with an error on one question
  when: the failure is caught
  then: the workflow reruns the step once; when the rerun passes, plumb debug counts one case resolved
    by debugging; when it fails again, the agent gets the error and its log entry as a plumb defect, and
    nothing is settled by rule
- id: EX-3
  given: an issue that is plumb's own failure, not an intent choice (a job error, a link to a file that
    no longer exists with nothing to repin to)
  when: the judge reads it
  then: it is not put to the owner as an intent question; it opens the debug workflow, and plumb debug
    lists one case
- id: EX-4
  given: a requirement's covering test was deleted and nothing in the repository covers its behaviour
  when: the stale check cannot repin
  then: the agent gets one text line naming the requirement and the deleted test, to restore it; the owner
    is asked only if the behaviour itself may no longer be wanted, which is an intent question
- id: EX-5
  given: no judge can be reached
  when: a step needs one
  then: 'this is not a debug case: plumb says so, nothing is decided and the agent is never held (SR-378,
    DEC-391)'
- id: EX-6
  given: an issue that is a real intent choice or trade-off
  when: it is found
  then: it goes to the owner as a question, not to the debug workflow
- id: EX-7
  given: a debug workflow is running
  when: the owner keeps working
  then: the owner's work is not stopped, and the status shows one line saying how many cases are in debugging
proof:
  plan: 'Recommended for the owner to decide: a session with a scripted judge that never converges on
    one requirement; plumb debug lists it as a case, and the owner sees no question.'
