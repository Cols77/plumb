---
id: SR-110
title: Targeted validation selects tests by the functions they execute,...
statement: plumb records, per test, which functions it executes (collected once with coverage contexts,
  then refreshed only for tests whose run or source changed), and selects for a change the tests that
  executed a changed function, plus the tests linked to the changed requirement. Import-closure selection
  is used only for a file no recorded test has executed. Selected tests run in parallel (pytest-xdist,
  verify.workers). When nothing is recorded for a changed function, plumb says so rather than silently
  running everything.
examples:
- id: EX-1
  given: a change to one function in src/plumb/approvals.py that 12 tests executed when recorded
  when: plumb selects tests for the change
  then: those 12 tests and the tests linked to the requirement the function implements are selected, not
    the 424 tests whose imports reach approvals.py
- id: EX-2
  given: a new function no recorded test has executed
  when: plumb selects tests
  then: it falls back to the import closure for that file and says the function has no recorded test
- id: EX-3
  given: verify.workers set to 2 and pytest-xdist installed
  when: the selected tests run
  then: they run on two workers
