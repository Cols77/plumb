---
id: SR-253
title: Every requirement carries the proof the owner chose, and done and...
feature: FEAT-007
statement: 'Every requirement carries a proof: how the owner will see it working, matched to what changed,
  of kind live-session, hook, command or other. The agent researches the best proof and recommends it;
  the owner decides through the question tool or their own words, and a ''done when'' line the owner states
  is taken as the proof without a question. The plan includes the code the proof needs. Once shown, the
  proof''s evidence (where to see it) is recorded; done refuses a requirement without it and, for a proof
  the evaluator was picked for, without that verdict or the owner''s yes, and a merge into the default
  branch refuses each requirement it delivers until its proof is shown working and the owner confirms
  it through the question tool (DEC-256, DEC-257), or, for a proof the owner picked the independent evaluator
  for at the proof question, until the evaluator''s verified verdict confirms it (SR-397); a proof the
  owner agreed can only be shown after the landing (post-merge) does not hold the merge, and the turn
  after the landing asks for it. plumb''s alignment check names, in plain words, every ''done when'' item
  that no example covers.'
examples:
- id: EX-1
  given: a requirement that changes what Claude Code draws
  when: the agent recommends its proof
  then: the recommendation is a live session capture showing the drawing, put to the owner through the
    question tool with the alternatives
- id: EX-2
  given: the owner answers the proof question with 'I open the panel and see the card'
  when: the loop writes the plan
  then: the plan carries that proof as a live-session proof and the code it needs
- id: EX-3
  given: the owner said "it's done when I get a reminder three days before each deadline"
  when: the agent records the intent
  then: its proof records "you get a reminder three days before each deadline" as how the owner will see
    it done, and no question about the proof is asked
- id: EX-4
  given: a request that states no success criterion
  when: the agent clarifies it
  then: plumb's hints to the agent say success is not stated, and the agent recommends a proof that the
    owner decides through the question tool
- id: EX-5
  given: a requirement whose proof has run
  when: the owner asks in plain words how it was shown working
  then: the proof and its evidence (where to see it) are given
- id: EX-6
  given: the build is finished and the proof was not shown
  when: the agent calls the intent done
  then: plumb says the proof is missing and the intent stays open
- id: EX-7
  given: a merge into main whose commits deliver a requirement whose proof was never shown
  when: the merge check runs
  then: it names that requirement as not shown working and refuses the merge until its evidence is recorded
    and the owner confirms it
- id: EX-8
  given: a "done when" item that no example covers
  when: plumb checks alignment
  then: it names that item as a gap in plain words
- id: EX-9
  given: an example that covers that "done when" item
  when: plumb checks alignment again
  then: the gap is gone
- id: EX-10
  given: a change the owner sees, and a proof that is only its passing tests
  when: the agent recommends a proof
  then: it recommends a way the owner sees the change, not the passing suite
- id: EX-11
  given: a live-session proof when no Claude Code session can be started in this environment (no display,
    or no host installed)
  when: the agent tries to show it
  then: done stays refused, the plumb line says one case went to debugging, and the owner gets one question
    only if the debug workflow cannot make the environment ready
- id: EX-12
  given: the owner later says the proof should be a browser demonstration instead
  when: plumb reads the message
  then: the requirement's proof becomes the browser demonstration, and done and the merge refuse it again
    until that demonstration's evidence is recorded
- id: EX-13
  given: a requirement whose proof was asked with plumb proof --ask in a worktree, and the owner answers
    yes in a session whose checkout is main
  when: the question tool's answer hook runs
  then: the answer is tagged as that proof's confirmation and the proof counts as shown in the worktree,
    the pending question there is removed, and the outcome is recorded once, in the worktree, not in main
    too
proof:
  plan: 'Recommended for the owner to decide: in a live session the owner opens /plumb intent with a small
    visible change; the question tool offers the agent''s recommended proof first, with alternatives;
    the owner picks one; the agent calling it done before showing it is refused, naming the missing proof;
    after the proof is shown its evidence is recorded and done passes; a branch with another touched requirement
    lacking evidence is refused at the merge check.'
  kind: live-session
