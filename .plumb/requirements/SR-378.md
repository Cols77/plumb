---
id: SR-378
title: An ordinary message never blocks the agent on the judge
statement: Judge jobs run only in the background worker, never inside a hook or an agent command; plumb
  clarify --wait answers at once with what is known and never runs a job itself. Outside the intent loop
  the edit gate closes only when a request contradicts or extends a confirmed record; open judge questions
  never refuse an edit or a shell command. Questions reach the agent as text and are asked as the pacing
  rule says (SR-334).
examples:
- id: EX-1
  given: an ordinary message with three judge jobs queued
  when: the agent runs plumb clarify --wait
  then: it answers within a second and no model call runs in that process
- id: EX-2
  given: an unanswered judge question about a record from another day
  when: the agent edits an unrelated file
  then: the edit is allowed
- id: EX-3
  given: a request that reverses behaviour the owner confirmed
  when: the prompt hook runs
  then: the gate closes until the owner answers or types /plumb go
- id: EX-4
  given: no judge is reachable
  when: an ordinary message arrives
  then: the agent works on; the brief says once that the judge is unreachable
proof:
  plan: 'In a live session on this repository: a message with judge questions pending; clarify --wait
    answers at once; the agent edits before the questions are answered; the questions arrive as the pacing
    rule says.'
  kind: live-session
