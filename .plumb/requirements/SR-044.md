---
id: SR-044
title: Untraced changes get a proposed owning requirement, never a written link
feature: FEAT-002
statement: For an untraced changed path, plumb proposes the owning requirement chosen by the backend among
  candidates narrowed by the code map, in the agent's read-back instruction; at commit, a "does this diff
  serve its claimed SRs?" judgment may print a non-blocking warning and never changes the trailer check's
  result; a verified_by link to a bare test file gets a proposed test node as a drift hint. None of these
  writes a link.
examples:
- id: EX-1
  given: src/app/mul.py changed with no owner and SR-001 owns src/app/calc.py in the same package
  when: the untraced instruction is built
  then: it names SR-001 as the proposed owner and no link is added
- id: EX-2
  given: a commit claiming SR-004 that only changes src/app/report.py
  when: the commit-msg hook runs with a backend answering no
  then: it prints a warning and exits 0
- id: EX-3
  given: SR-001 verified_by tests/test_calc.py with test_add_returns_sum inside
  when: plumb drift runs
  then: a hint proposes tests/test_calc.py::test_add_returns_sum for EX-1
- id: EX-4
  given: SR-001 owns src/app/calc.py and src/app/mod.py is written and not committed
  when: plumb review runs
  then: its drift section names SR-001 as the proposed owner of src/app/mod.py, reading uncommitted changes
    as plumb merge-check does
