---
id: SR-321
title: Only the log kinds plumb needs elsewhere are committed
feature: FEAT-006
statement: 'Log entries another clone needs for plumb to stay consistent and work are committed: approval,
  prompt, config, calibration, pre-intent, question-answer, premise, test-run, mod-hello, revocation,
  escalation-declined, renumber, import, conflict-resolution, waiver, browser-hello and claims-ingest.
  Judgment entries are telemetry: the live files are ignored by git and each landing moves them into the
  kind''s tracked archive segment (SR-376); the offer kind no longer exists. Every other kind (verdict,
  trial, card-press, card-settled, card-withdrawn, gate, read-entry, job-note, triage, merge-evidence,
  repin, relink, unlink, eval-run, jev-setup, intent-gate, intent-done, card-unsettled) is written where
  it was but ignored by git, and its readers behave as before on the machine that wrote it.'
examples:
- id: EX-1
  given: a session that appends a verdict and an approval
  when: git status runs
  then: the approval is listed as untracked and the verdict is not
- id: EX-2
  given: a clone with no verdict entries but the approvals and judgments
  when: plumb status runs
  then: every approved record shows approved and no requirement shows unjudged that the other clone showed
    judged
- id: EX-3
  given: a new log kind added to the code
  when: the suite runs
  then: a test fails until the kind is listed as shared or local
proof:
  plan: 'Two loops in two worktrees write log entries at once and land one after the other: main''s checkout
    shows no untracked shared entry left behind and no local entry committed.'
  kind: command
