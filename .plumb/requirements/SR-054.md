title: plumb hosts install codex writes a thin Codex adapter
feature: FEAT-004
statement: plumb hosts install codex writes the AGENTS.md block, the Codex lifecycle hooks or notify entry
  the installed version supports and the session marker where possible, idempotently and preserving foreign
  entries; rows the version lacks use the CLI-only fallback, recorded in docs/hosts.md.
examples:
- id: EX-1
  given: an AGENTS.md with the owner's own text
  when: plumb hosts install codex runs twice
  then: the owner's text is unchanged and one plumb block exists
- id: EX-2
  given: plumb's Codex adapter installed
  when: plumb hosts uninstall codex runs
  then: only plumb's entries are removed
- id: EX-3
  given: the Codex adapter installed, and the agent's shell with the environment it gives (the marker
    codex where the adapter sets it, none otherwise) and no terminal
  when: the agent runs plumb approve SR-001 with "y" piped on stdin
  then: it exits 3 and no approval is written
- id: EX-4
  given: a foreign shell_environment_policy kept in .codex/config.toml
  when: plumb hosts status codex runs
  then: 'it prints "no session marker on this host: owner-only commands require an interactive terminal"
    with the trust model, says where prompts come from, and counts the confirmations resting on a self-recorded
    message (R13 Q4)'
