---
id: SR-403
title: The committed log keeps only entries a checkout needs
statement: At each landing, every loose entry of the retired offer kind goes into its archive segment
  (each entry once; the files go, git history keeps them), and a test-run entry that is only the latest
  run or last pass of tests whose files no longer exist is moved into the archive segment as well as one
  a newer run replaces, so a checkout copies only the live entries as files. The entry that is the latest
  run or last pass of a test that still exists, and any entry a record still cites, stay as files.
examples:
- id: EX-1
  given: loose offer entry files, some of which the archive segment already holds
  when: a landing runs
  then: no loose offer file remains, the segment holds each entry once, git history still has the files,
    and plumb validate is clean
- id: EX-2
  given: a test-run entry that is only the latest run of tests whose files were deleted
  when: a landing runs
  then: it is in the test-run archive segment and no entry file remains for it
- id: EX-3
  given: a test-run entry that a newer run of the same tests replaces
  when: a landing runs
  then: it is in the test-run archive segment and no entry file remains for it
- id: EX-4
  given: the latest run, or last passing run, of a test that still exists
  when: a landing runs
  then: its entry file stays, because verification still reads it
proof:
  plan: in a scratch repository with loose offer entries and many replaced test-run entries, run the landing
