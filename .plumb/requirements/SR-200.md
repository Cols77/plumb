---
id: SR-200
title: A change no requirement owns gets a judge-proposed owner and is...
feature: FEAT-002
statement: 'A changed source path no requirement links is untraced: plumb tells the agent in that turn,
  without blocking, naming the owning requirement the judge proposes among code-map candidates, and plumb
  review''s drift section names the same proposal, uncommitted changes included; the merge check lists
  it as untraced, without holding the merge, until a requirement owns it or it is exempted (DEC-261, SR-260).
  plumb never writes the link itself. One definition of source code, shared with covering-test selection,
  decides what is source, flat layouts included. The agent''s standing instructions (plumb''s CLAUDE.md
  and AGENTS.md block, and its plumb-records and plumb-clarify skills) tell it to formalize each request
  that changes the system into proposed records linked to the code it changes, for the judge to validate,
  and ask the owner to read nothing back.'
examples:
- id: EX-1
  given: src/app/mul.py changed with no owner, SR-001 owns src/app/calc.py in the same package, and the
    judge picks SR-001 among the candidates
  when: the untraced instruction is built
  then: it names SR-001 as the proposed owner and no link is added
- id: EX-2
  given: no judge can be reached, src/app/mul.py changed with no owner and SR-001 owns src/app/calc.py
  when: the untraced instruction is built
  then: it lists SR-001 as a candidate, says judging is unavailable naming the cause, proposes no owner
    and adds no link
- id: EX-3
  given: a turn writes src/app/mul.py and no requirement links it
  when: the turn ends
  then: the turn is not blocked, and at the next prompt the agent is told src/app/mul.py is untraced and
    to record a proposed requirement with examples linked to it (SR-373)
- id: EX-4
  given: a repository with no source_dirs configured and a changed mypkg/extra.py and tool.py that no
    requirement owns
  when: the turn ends
  then: the turn is not blocked, and at the next prompt the agent is told both are untraced
- id: EX-5
  given: the end-of-turn hook already keeps the turn open to run covering tests
  when: an untraced change exists
  then: the hold's reason carries only the covering-tests instruction (SR-373's one next action); the
    untraced instruction waits for the next prompt, once
- id: EX-6
  given: SR-001 owns src/app/calc.py, src/app/mod.py is written and not committed, and the judge picks
    SR-001
  when: plumb review runs
  then: its drift section names SR-001 as the proposed owner of src/app/mod.py, reading uncommitted changes
    as the merge check does
- id: EX-7
  given: a branch adds src/mul.py and no requirement owns it
  when: the merge check runs
  then: it lists src/mul.py under untraced changes with the way to resolve it and does not hold the merge
    on it
- id: EX-8
  given: the same flat-layout changes (mypkg/extra.py, tool.py) on a branch
  when: the merge check runs
  then: it lists mypkg/extra.py and tool.py as untraced and does not hold the merge on them; NOTES.txt
    is not listed
- id: EX-9
  given: generated files (__pycache__, *.pyc), tests, docs, records or a path under trace.exempt
  when: they change
  then: they are never untraced changes
- id: EX-10
  given: source_dirs set to [lib] in .plumb/config.yaml
  when: lib/x.py, tool.py and src/mul.py change
  then: only lib/x.py is source
- id: EX-11
  given: the covering-test selection and the trace
  when: they decide whether a changed path is source
  then: they use the same is_code_path answer
- id: EX-12
  given: plumb is installed in a repository for Claude Code
  when: its CLAUDE.md block is written
  then: the block tells the agent to formalize each request that changes the system into proposed records
    linked to the code it changes, for the judge to validate; it asks the owner to read nothing back
proof:
  plan: 'Recommended for the owner to decide: in a live session on a flat-layout scratch repository, the
    agent writes a module no requirement owns; the agent''s reply names the module as untraced with the
    judge''s proposed owner, and no link is written; the merge check then holds the branch naming the
    path until the agent links it.'
