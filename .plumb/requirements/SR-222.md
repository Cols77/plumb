id: SR-222
title: /plumb intent opens one intent loop whose stages each run only on...
feature: FEAT-002
statement: 'Typing /plumb intent with the owner''s words opens one loop for that intent: the clarifier
  asks its blocking questions through the question tool, checks each answer against the confirmed records,
  writes the intent candidates and passes them through one judge gate, the judge cascade as P9 defines
  it, fixing until only low findings remain. Each later stage (update records and plans, build, then the
  proof P10 requires) refuses to run until the previous stage''s gate passed; a gate that cannot settle
  goes to P5''s debug workflow. An ordinary message opens no loop.'
examples:
- id: EX-1
  given: no loop is open
  when: the owner types /plumb intent add multiply next to add
  then: the blocking questions come through the question tool, as many as there are gaps, and no record
    is written until the intent is clear
- id: EX-2
  given: an intent candidate contradicts a confirmed requirement's example
  when: the loop checks the candidate
  then: the contradiction is put to the owner as one question through the question tool before the candidate
    is written, in plain words and without a record id
- id: EX-3
  given: the judge gate finds a high finding on a candidate
  when: the gate runs
  then: the candidate is fixed and judged again, and the loop ends only when every finding left is low
- id: EX-4
  given: no loop is open
  when: the owner types make the status line show the branch name
  then: no loop opens and no model runs
- id: EX-5
  given: clarification has not passed its judge gate
  when: the update stage is asked to run
  then: it refuses and names the gate that has not passed
- id: EX-6
  given: the judge gate passed with only low findings
  when: the update stage runs
  then: it proceeds and records that it ran on that gate
- id: EX-7
  given: the build stage finished
  when: the proof the owner chose has not been shown
  then: 'the loop does not close: its last stage names the proof gate (P10) as not passed'
proof:
  plan: 'Recommended for the owner to decide: in a live session on a scratch repository with a confirmed
    add requirement, the owner types /plumb intent add multiply next to add and then /plumb intent make
    add subtract; the questions arrive through the question tool, the contradiction arrives as one question,
    the plumb line reports the judge gate passing; asking the agent to run the update stage before the
    gate passed shows the refusal naming that gate. The loop''s command tests run as the command-level
    check.'
  kind: live-session
