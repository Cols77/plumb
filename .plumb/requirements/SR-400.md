---
id: SR-400
title: A debug work copy is made without the committed log
statement: A work copy plumb makes to fix one of its own problems has none of the tracked log entry files,
  so the copy is about the size of the code alone; plumb commands still run in it, and what they build
  there (the cache) is its own and small. A work copy made before this rule is left as it is.
examples:
- id: EX-1
  given: a repository whose tracked log holds thousands of entry files
  when: plumb makes the work copy for a debug case
  then: the copy holds the code and the records but none of the tracked log entry files
- id: EX-2
  given: a work copy made without the log
  when: a plumb command runs in it
  then: the command works and the cache it builds there is the copy's own and small
- id: EX-3
  given: a work copy made before this rule, with its full log
  when: plumb reuses it for its case
  then: it is reused as it is and not rebuilt
proof:
  plan: in a scratch project with a large tracked log, make a debug work copy and see that it has no log
    entry files, uses the main cache, and is far smaller than a full checkout
  kind: command
  evaluator: true
evidence:
  at: '2026-11-08T00:32:50Z'
  summary: 'Scratch project with 3000 tracked log entry files (~12 MB). EX-1: selfdebug._worktree made
    .plumb/wt/debug-case-a; it has README and .plumb records/config but no .plumb/log, and git status
    there is clean. The whole copy is about 3.4 KB of files, against about 12 MB for the main log alone.
    EX-2: `plumb status --root <copy>` ran fine; it built a cache of its own in the copy (.plumb/cache,

    the proof plan says the copy ''uses the main cache'', but the statement and EX-2 say the cache is
