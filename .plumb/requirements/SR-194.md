---
id: SR-194
title: A stage of the intent loop runs only on the passed gate of the...
statement: Each stage of the intent loop (clarify and integrate, update records and plans, build and prove)
  records its outcome in the intent's session state, and the command of the next stage refuses to run
  until the previous stage's review gate passed; a workflow phase carries each gate, and the owner can
  see which gate is open.
examples:
- id: EX-1
  given: clarification has not passed its judge gate
  when: the update stage is asked to run
  then: it refuses and names the gate that has not passed
- id: EX-2
  given: the judge gate passed with only low findings
  when: the update stage runs
  then: it proceeds and records that it ran on that gate
- id: EX-3
  given: the build stage finished
  when: the proof the owner stated has not been shown
  then: the intent is not called done
- id: EX-4
  given: stage B applies the record updates and a new requirement supersedes one whose tests still cover
    the behaviour
  when: the links are moved
  then: plumb relink moves each link to the new requirement with a note, plumb repin --after-tests pins
    it once the linked tests pass, and a test of a retired example is unlinked with plumb unlink --note
    and deleted in the same commit
- id: EX-5
  given: stage C edits code that a confirmed requirement's link pins
  when: the edit hook reports the link stale
  then: the agent repins it after the linked tests pass, relinks it when the code moved, or cards it when
    the meaning changed, before the turn ends; the merge boundary holds any link problem left
proof:
  plan: run the stages out of order on a scratch intent and see the refusal name the missing gate; run
    them in order and see each gate recorded
  kind: command
