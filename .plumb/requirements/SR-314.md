---
id: SR-314
title: plumb's trace from intent to code shows only what matters
feature: FEAT-005
statement: When the agent or the owner asks plumb why something exists (explain), the answer gives the
  requirement, the owner's words behind it, the decision, the code it lives in, and only the tests that
  fail or block it; tests that pass or merely wait for a rerun are given as one count. It is the agent's
  first tool for tracing intent to code, before searching the code.
examples:
- id: EX-1
  given: a requirement with fifteen linked tests, three failing and twelve waiting for a rerun
  when: plumb explains it
  then: the three failing tests are named and the other twelve are one line with their count
- id: EX-2
  given: a requirement linked to code files
  when: plumb explains it
  then: the answer names the files the requirement lives in
- id: EX-3
  given: a requirement whose tests all pass
  when: plumb explains it
  then: no test is named, only their count and that they pass
- id: EX-4
  given: the agent needs to find the code behind an owner's request
  when: it starts tracing
  then: plumb's instructions to it say to run explain first and search the code only for what it leaves
    out
proof:
  plan: 'The owner sees plumb explain on the hook time limit answer in a handful of lines: the requirement,
    their words, the decision, the code files, and only the tests that fail.'
