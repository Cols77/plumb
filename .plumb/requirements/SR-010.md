id: SR-010
title: Each prompt receives the relevant records new to the session and an intent-change flag
feature: FEAT-001
statement: When a judge model is set up, the prompt hook flags a prompt that contradicts or extends a
  confirmed requirement (EX-2), and flags it again on a later, different prompt (EX-3). When no judge
  model is set up, the hook reports that judging is unavailable and flags nothing by rule.
examples:
- id: EX-1
  given: a prompt that names SR-003 and mentions stale links
  when: the prompt hook runs
  then: SR-003 is listed first
- id: EX-2
  given: confirmed SR-004 says an edit leaves a record unconfirmed and a configured judge
  when: a prompt asks to keep records confirmed after edits and the judge reads it as a change of SR-004
  then: the prompt is flagged as a possible intent change on SR-004
- id: EX-3
  given: confirmed SR-004, a configured judge, and a first prompt of the session already flagged as a
    possible change of SR-004
  when: a second, different prompt in the same session may change SR-004
  then: it is flagged again with its own ask-before-editing instruction, while the SR-004 record line
    is not repeated
- id: EX-4
  given: confirmed SR-004 and no judge configured
  when: a prompt asks to keep records confirmed after edits
  then: the hook prints one "judging unavailable" line naming judgment.backend, flags nothing and saves
    no flag, and the prompt still gets its records; a second prompt in the same session does not repeat
    the line
