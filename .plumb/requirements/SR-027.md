---
id: SR-027
title: A failing acceptance test shows where the owner looks; a regression holds the merge
feature: FEAT-001
statement: 'A requirement whose verified_by (or marker-mapped) tests failed in their last recorded run
  is listed with its example ids by plumb validate --merge, plumb drift and plumb status. The failure
  is kept until a run passes the test, whatever changed since (marked stale when the identity moved).
  The merge report exits 5 while an acceptance test of a touched requirement fails (a test that never
  passed as much as a regression), has no passing evidence on the current identity, or while any recorded
  regression is unresolved. A full run satisfies full verification pending only when it collected cleanly,
  ran tests and every test it failed has passed since: exit 5 (nothing collected), a collection error,
  an empty run or a failing test never clears it.'
examples:
- id: EX-1
  given: confirmed SR-001 with EX-1 verified_by tests/test_mod.py, which passed, and add() changed to
    subtract
  when: the covering run fails test_add and plumb validate --merge BASE runs
  then: it lists "SR-001 EX-1 tests/test_mod.py (regression)" and exits 5; after a fix and a passing run
    it exits 0
- id: EX-2
  given: the same regression
  when: plumb drift and plumb status run
  then: drift reports the failing acceptance test and exits 1; status counts SR-001 as failing and names
    EX-1
- id: EX-3
  given: a full run that collected no tests (exit 5), hit a collection error, or ran nothing
  when: full verification pending is computed
  then: it is still pending
- id: EX-4
  given: confirmed SR-001 with EX-1 verified_by tests/test_mod.py, and a new test in it that has never
    passed
  when: the run fails it and plumb validate --merge BASE runs
  then: it lists "SR-001 EX-1 tests/test_mod.py (failing)" and exits 5
- id: EX-5
  given: a failing acceptance test of SR-001
  when: src/pkg/mod.py changes again and no test is rerun
  then: validate --merge still lists the failure marked stale and exits 5, drift still reports it, and
    a passing run clears it
- id: EX-6
  given: confirmed SR-001 whose acceptance test passed, then src/pkg/mod.py changed
  when: plumb validate --merge BASE runs before any rerun
  then: it lists SR-001 EX-1 tests/test_mod.py as an unverified acceptance test and exits 5; after a passing
    run it exits 0
- id: EX-7
  given: a full run in which a test fails
  when: full verification pending is computed
  then: it stays pending, naming the failed test, until a run passes that test
