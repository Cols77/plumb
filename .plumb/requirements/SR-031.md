---
id: SR-031
title: The merge is never green while an acceptance test the change can affect lacks a pass
feature: FEAT-001
statement: plumb validate --merge BASE checks the acceptance tests of the touched requirements and of
  every confirmed requirement whose acceptance tests cover a changed path, and exits 5 while one fails
  or has no passing evidence on the current identity. A full verification pending (R5, shared test infrastructure)
  holds the merge with exit 5 until a full run satisfies it or an owner waiver pins this exact change
  (plumb tests waive --merge BASE, refused under the agent session marker; any later edit voids it).
examples:
- id: EX-1
  given: confirmed SR-001 (add) and SR-002 (doubling, verified_by tests/test_helper.py) with a passing
    full run, and a committed tests/conftest.py that breaks pkg.helper
  when: plumb validate --merge BASE runs
  then: it says the full verification pending holds the merge, lists SR-001 and SR-002 as affected, and
    exits 5; after a run that fails test_helper it lists the regression and still exits 5
- id: EX-2
  given: the same project and a change to src/pkg/mod.py that breaks twice(), with only tests/test_mod.py
    rerun
  when: plumb validate --merge BASE runs
  then: it lists SR-002 EX-1 tests/test_helper.py as unverified (stale) and exits 5; after rerunning it,
    as a failing regression, still 5
- id: EX-3
  given: a pyproject.toml comment change that leaves full verification pending
  when: the owner runs plumb tests waive --merge BASE --reason ... in their own terminal
  then: the merge exits 0 and says the run is waived for this exact change; a later edit makes it 5 again;
    under the agent marker the waiver is refused (exit 3)
