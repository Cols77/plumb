---
id: SR-071
title: plumb merge-fix renumbers IDs that collide across clones
feature: FEAT-006
statement: When a merge brings a record whose ID another record already holds (another clone created it),
  plumb merge-fix keeps the first parent's record, gives the incoming record a newly reserved ID, rewrites
  every reference the incoming side introduced (links, feature and member lists, supersedes and decides,
  body wikilinks, test sr markers and the SR trailers of the pending merge message) and stages the result;
  it never rewrites history, it records a renumber event that maps the incoming commits' trailers and
  the incoming approvals of the unchanged content to the new ID, and running it again changes nothing.
examples:
- id: EX-1
  given: a clone created SR-070 "export csv" while this repository created SR-070 "relay checks"
  when: the clone's branch is merged and plumb merge-fix runs
  then: '"relay checks" stays SR-070, "export csv" gets the next reserved ID, and every reference the
    clone added names the new ID'
- id: EX-2
  given: 'the clone''s commits carry "SR: SR-070" trailers'
  when: merge-fix renumbers
  then: those commits are unchanged in git log, plumb claims check reads their trailers as the new ID,
    and the merge message's trailer is rewritten
- id: EX-3
  given: the clone's owner approved "export csv" at its content
  when: merge-fix renumbers it with no other change
  then: it stays confirmed under its new ID, while an approval of different content is not carried
- id: EX-4
  given: a record on this repository's side that references SR-070
  when: merge-fix runs
  then: that reference still names SR-070
- id: EX-5
  given: merge-fix already ran
  when: it runs again
  then: it reports nothing to fix and writes nothing
