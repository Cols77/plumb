---
id: SR-041
title: Auto-approval is off by default, owner-switched, calibrated, and only for records restating the
  owner's words
feature: FEAT-002
statement: Auto-approval is effective only when the owner's own plumb config auto-approve on event stands
  (written without the session marker), JEV answered, and a passing calibration exists for the resolved
  model version. Then an INT whose quote is verbatim in the logged prompt, or an SR whose every example
  quotes it, is approved by auto-jev with score, confidence, prompt digest and model version, only when
  JEV judges at or above the thresholds that the owner's logged words support the requirement's wording
  AND every one of its examples (R13 Q3). Never for a DEC, a set member, an edit of an owner-confirmed
  record, the heuristic, or JEV unavailable. Auto-approvals are labelled, revocable, and re-checked by
  plumb validate.
examples:
- id: EX-1
  given: config.yaml says auto_approve enabled true but no owner config event exists
  when: plumb capture writes an eligible INT
  then: the INT stays proposed and plumb validate warns about the mismatch
- id: EX-2
  given: auto-approval on, calibrated, JEV answering 0.95 high
  when: plumb capture writes a DEC with matters true
  then: the DEC stays proposed
- id: EX-3
  given: auto-approval on and calibrated
  when: the resolved JEV model version changes
  then: auto-approval is suspended and the status says recalibrate
- id: EX-4
  given: an auto-jev approval of INT-030
  when: the owner runs plumb revoke INT-030
  then: INT-030 is proposed again
