---
id: SR-377
title: The installed plugin refreshes by itself after a landing
statement: The plugin's version is derived at build time from git (0.1.<commit count>) and written to
  pyproject.toml, the package, the plugin manifest, the marketplace entry and the vendored wheel's manifest,
  so every build of main has a new version. Claude Code's plugin update then installs it and the private
  environment rebuilds for the new wheel; nothing is reinstalled by hand. The build check fails when the
  five places disagree.
examples:
- id: EX-1
  given: a commit lands on main
  when: the plugin is built
  then: its version is higher than the previous build's in all five places
- id: EX-2
  given: a session on an older plugin after a landing
  when: plugins are updated
  then: the new version is installed and the private environment rebuilds for the new wheel
- id: EX-3
  given: the five places disagree
  when: the build check runs
  then: it fails naming them
proof:
  plan: After the next landing, a session on the older plugin updates to the new version and a behaviour
    fixed in main shows in that session without a reinstall.
  kind: live-session
  post_merge: true
