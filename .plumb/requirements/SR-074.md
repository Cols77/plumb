id: SR-074
title: events.jsonl and evidence.jsonl are migrated without breaking the...
feature: FEAT-006
statement: plumb log migrate moves every line of events.jsonl and evidence.jsonl into per-entry files
  with the same fields, so every digest, prev link and evidence identity (run ids, node evidence, approval
  references) is unchanged; migrated files are named from the entry's time and digest, so the migration
  is idempotent and two branches that migrate independently merge cleanly; the legacy files are emptied,
  not deleted, so a branch made before the migration still merges; a line whose digest does not match
  is never migrated and the command refuses; until every line is migrated, readers accept both formats,
  deduplicated by digest.
examples:
- id: EX-1
  given: plumb's events.jsonl with 510 chained lines
  when: plumb log migrate runs
  then: 510 entry files exist, each with the digest and prev of its line, and plumb validate is clean
- id: EX-2
  given: the migration already ran
  when: it runs again
  then: no file is written or changed
- id: EX-3
  given: a branch created before the migration that appended two lines to events.jsonl
  when: it is merged after the migration
  then: git merges without conflict, readers see both lines, and the next migration moves them into files
- id: EX-4
  given: evidence.jsonl holds the test runs that made tests fresh
  when: the log is migrated
  then: plumb verify reuses the same evidence and the same tests stay fresh
- id: EX-5
  given: a legacy line edited by hand
  when: plumb log migrate runs
  then: it refuses, names the line and writes nothing
