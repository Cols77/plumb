---
id: SR-231
title: A link pins both ends and changes only through logged commands
feature: FEAT-001
statement: A link lives in its source record and pins the content hash of both ends; plumb reports it
  stale (naming which end moved) when either hash differs, dangling (an error) when its target is missing,
  unpinned (a warning) without a pin. Links are repinned, removed or moved only through the agent's repin,
  unlink and relink commands, each logging the old and new ends, unlink and relink with a required note;
  none of them approves a record.
examples:
- id: EX-1
  given: SR-001 verified_by a test file with current pins
  when: the test file's content changes
  then: plumb reports the link stale with the target moved
- id: EX-2
  given: the same link
  when: the test file is re-saved with CRLF line endings only
  then: the link stays current
- id: EX-3
  given: a link whose target record or file does not exist
  when: plumb validate runs
  then: it reports a dangling-link error
- id: EX-4
  given: a stale link
  when: the agent repins it
  then: its pins are refreshed, a repin event is logged and no record becomes approved
- id: EX-5
  given: 'a record has links #0..#22 and #5 points at a test file that moved'
  when: 'the agent unlinks #5 with a note saying where the test went'
  then: 'the record has 22 links, the old #6 is now #5, the output lists each renumbered link, and one
    unlink entry logs the removed link, its target, pin and note'
- id: EX-6
  given: 'a record with no link #40'
  when: 'the agent unlinks #40'
  then: it exits 1 saying there is no such link, and the record file is unchanged
- id: EX-7
  given: any link
  when: unlink or relink runs without a note
  then: it exits with a usage error and changes nothing
- id: EX-8
  given: a link that is the only verified_by link of an approved example, and its target still exists
  when: the agent unlinks it
  then: it is refused, saying the approved example would lose its only test and naming relink instead;
    the record is unchanged
- id: EX-9
  given: a dangling link that is the only verified_by link of an approved example
  when: the agent unlinks it
  then: it is removed (a dangling link proves nothing) and the output says the example now has no test
- id: EX-10
  given: 'link #5 verified_by a test path that no longer exists'
  when: 'the agent relinks #5 to the test''s new path with a note'
  then: '#5 keeps its number, kind and example, points at the new path pinned to both ends as they are
    now, and one relink entry logs both targets'
- id: EX-11
  given: a new target that does not exist
  when: the agent relinks to it
  then: it exits 1 naming the missing target and the record is unchanged
- id: EX-12
  given: the record already has a link with the same kind, target and example
  when: a relink would make link n a copy of it
  then: it is refused, naming the existing link and suggesting unlink
- id: EX-13
  given: a record-only link kind given a file target
  when: the agent relinks to it
  then: it is refused with the same message plumb link gives
