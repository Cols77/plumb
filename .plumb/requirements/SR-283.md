---
id: SR-283
title: Codex, Pi and Hermes each get a thin adapter that installs only...
feature: FEAT-004
statement: 'Asked to set plumb up for Codex, Pi or Hermes, plumb writes only that host''s adapter: Codex''s
  AGENTS block and hooks, Pi''s extension, Hermes''s plugin and namespaced skills, each with the /plumb
  command where the host has one and its session marker where it can be set. Installing twice changes
  nothing, the owner''s own entries are kept, uninstalling removes only plumb''s, and status reports what
  is installed without claiming it is active. Each adapter binds events to the project it was installed
  in, ignores child sessions, gives the brief once, sends a block at most once, and records a summary
  that never reached the owner as unseen.'
examples:
- id: EX-1
  given: an AGENTS.md with the owner's own text
  when: plumb's Codex adapter is installed twice
  then: the owner's text is unchanged and one plumb block exists
- id: EX-2
  given: plumb's Codex adapter installed
  when: it is uninstalled
  then: only plumb's entries are removed
- id: EX-3
  given: a repository
  when: plumb's Pi adapter is installed
  then: the rendered extension names each mapped Pi event and the plumb hook commands
- id: EX-4
  given: a repository
  when: plumb's Codex adapter is installed
  then: 'nothing of Claude Code''s, Pi''s or Hermes''s is written: no .claude settings, no Pi extension,
    no Hermes plugin'
- id: EX-5
  given: the adapter not loaded (Pi in an untrusted project, Hermes with project plugins off, Codex with
    a foreign shell_environment_policy kept)
  when: plumb's status for that host is asked
  then: it says the session marker is missing on this host, where the owner's prompts come from, and how
    many approvals rest on a self-recorded message
- id: EX-6
  given: the Hermes plugin files and discovery flag exist
  when: plumb's status for Hermes is asked
  then: installed files and prerequisites are reported while runtime activation remains unverified
- id: EX-7
  given: Hermes skills installed for a project
  when: the agent resolves a plumb skill
  then: only the plumb-qualified name resolves, and uninstalling the Hermes adapter removes those skill
    files
- id: EX-8
  given: plumb installed for Codex, Pi or Hermes
  when: plumb installs there
  then: plumb's Claude Code band is not installed; that host gets only its own things
- id: EX-9
  given: the rendered Hermes plugin and a fake ctx
  when: register(ctx) runs
  then: a plumb command is registered and each registered hook returns turn output lines
- id: EX-10
  given: a Hermes ctx without hook registration
  when: register(ctx) runs
  then: only the command is registered, no error is raised, and the instruction block tells the agent
    to run plumb turn start and plumb turn end
- id: EX-11
  given: a Pi stop output with a block and stop_active true
  when: the extension handles agent end
  then: no follow-up message is sent
- id: EX-12
  given: the generated Hermes plugin belongs to repo A and the process runs in repo B
  when: a prompt callback runs
  then: only repo A receives the hook payload
- id: EX-13
  given: the generated plugin root lacks .plumb
  when: any event callback runs
  then: no subprocess is launched and empty adapter output is returned
- id: EX-14
  given: an observer may fire before session ancestry is known
  when: the first eligible parent prompt arrives
  then: one brief is obtained after filtering, and later prompts do not duplicate it
- id: EX-15
  given: parent_session_id is explicit
  when: prompt and later callbacks run
  then: no owner prompt or summary events are emitted for the child
- id: EX-16
  given: a child observer fires without parent metadata
  when: later callbacks identify its parent session
  then: no startup or other subprocess event is emitted
- id: EX-17
  given: another transform wins or a reply is interrupted
  when: the turn settles
  then: the summary is recorded as unseen, so the records it named are not marked as shown and are given
    to the agent again on the next turn
proof:
  plan: 'Recommended: in a scratch repository holding the owner''s own AGENTS.md and Hermes config, the
    agent sets plumb up for Codex, then Pi, then Hermes, twice each, and shows the owner the diff after
    each: only that host''s files changed, the owner''s text intact, and an uninstall diff removing only
    plumb''s entries. The owner decides whether these diffs or a live session in one of those hosts is
    the proof.'
  kind: command
