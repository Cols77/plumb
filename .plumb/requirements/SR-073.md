---
id: SR-073
title: Every log entry is its own file under .plumb/log/<kind>/
feature: FEAT-006
statement: Every log entry (approval, prompt, judgment, test-run, merge-evidence, renumber, intent-conflict
  resolution and every other kind) is written through one append function as its own JSON file under .plumb/log/<kind>/,
  created with a no-replace link and never edited, carrying its digest and prev (the stream's latest entry,
  read from a gitignored head pointer rebuilt by a scan), so branches and worktrees that both append never
  produce a git conflict; plumb validate reports an edited entry, a deleted entry that a later prev names,
  and an unparsable file.
examples:
- id: EX-1
  given: two worktrees that each append approvals, prompts and test runs
  when: one branch is merged into the other
  then: git reports no conflict under .plumb/log and plumb validate accepts the forked chain
- id: EX-2
  given: two writers in one worktree in the same second
  when: both append
  then: two distinct files exist and neither replaced the other
- id: EX-3
  given: a committed entry file edited by hand
  when: plumb validate runs
  then: it reports that file as modified
- id: EX-4
  given: the head pointer in .plumb/cache was deleted
  when: the next entry is appended
  then: its prev is the stream's latest entry, found by a scan
