---
id: SR-090
title: An unrelated request in the same message never blocks an ok
feature: FEAT-007
statement: When plumb reads which records an owner's message confirms, objections and changes count only
  in the sentence that holds the ok and in sentences that name, or plainly refer to, the records being
  confirmed, whether the ok names them by number or is a bare ok after they were shown. An unrelated request
  in the same message neither blocks the confirmation nor counts as a reservation, and the words passed
  on need not include it. A correction in the ok's own sentence, a reservation about the shown records,
  and an objection that refers to them in general still hold the ok back. Every place plumb reads an ok
  (single records, a group, a big plan, picking a version, the suggestion to the agent and the merge glance)
  reads the same scope (ruling R16).
examples:
- id: EX-1
  given: the two decisions the owner names were shown
  when: the owner writes exactly "Make plumb a plugin that you can install using claude code so that then
    all commands are built in. Ok, confirm DEC-017 and DEC-018" and the agent passes on "Ok, confirm DEC-017
    and DEC-018"
  then: both decisions are confirmed, and no warning that the owner objected is attached
- id: EX-2
  given: the requirement SR-004 "reminder timing" was shown
  when: the owner writes "Ok, confirm SR-004. Also add a dark mode to the settings page."
  then: it is confirmed, and the dark mode request is not taken as a reservation
- id: EX-3
  given: the requirement SR-004 "reminder timing" was shown
  when: the owner writes "Ok, confirm SR-004. That example is wrong though."
  then: it is not confirmed
- id: EX-4
  given: the subtraction requirements were shown
  when: the owner writes "ok, except 3 minus 5 should return 0"
  then: nothing is confirmed
- id: EX-5
  given: the subtraction requirement, whose example says 3 minus 5 gives -2, was shown
  when: the owner writes "ok. 3 minus 5 should be 0 for us."
  then: nothing is confirmed, since the correction is about the shown subtraction
- id: EX-6
  given: the message of the first example
  when: plumb suggests to the agent what the ok confirms
  then: it suggests confirming the two decisions
- id: EX-7
  given: the cards of two reminder requirements were shown
  when: the owner writes "Also add a dark mode to the settings page. Ok."
  then: both reminder requirements are confirmed, and the dark mode request is left for the agent as a
    new request
- id: EX-8
  given: the card of the reminder timing requirement was shown
  when: the owner writes "Ok. The reminder should go out a day earlier."
  then: nothing is confirmed, since the second sentence is about the shown reminder
