---
id: SR-315
title: plumb's own repository runs plumb through the plugin, on its...
feature: FEAT-007
statement: 'plumb''s own repository is set up like any other project: plumb''s hooks come from the plumb
  plugin, not from hooks written into the repository''s Claude Code settings, so every hook the plugin
  ships (the question-answer hook among them) runs here. When the plugin runs in plumb''s own repository
  or one of its worktrees, it runs that checkout''s code, so a change is what the hooks run from the next
  hook on, with no refresh step; elsewhere it runs its own packaged copy as today.'
examples:
- id: EX-1
  given: plumb's repository with the old hooks in .claude/settings.json
  when: it is moved to the plugin
  then: no plumb hook command remains in its settings, the plugin is enabled for it, and the next session's
    hooks come from the plugin
- id: EX-2
  given: plumb's repository on the plugin
  when: the owner answers a question through the question tool
  then: the answer is logged as the owner's words and reaches the judge
- id: EX-3
  given: a change to plumb's hook code in main
  when: the next hook runs in a session on main
  then: it runs the changed code, with no plugin refresh
- id: EX-4
  given: a session in a worktree of plumb's repository
  when: a hook runs
  then: it runs that worktree's code, not main's
- id: EX-5
  given: another project using the plumb plugin
  when: a hook runs
  then: it runs the plugin's packaged copy, as before
- id: EX-6
  given: plumb's repository whose own environment cannot start (a broken checkout)
  when: a hook runs
  then: it falls back to the plugin's packaged copy and says so in one line to the agent; the owner is
    not blocked
proof:
  plan: 'In a fresh live session on plumb''s repository: its settings hold no plumb hook, the owner answers
    one judge question through the question tool and the judge stops asking it; then a one-line change
    to a hook''s text in a worktree shows up in that worktree''s next hook output.'
  kind: live-session
