title: A recommendable option is an assumption; every gap without one is...
statement: When the commanded check (/plumb clarify) can recommend an option, it writes the recommendation
  as a flippable assumption on the read-back and the agent builds on; a gap is asked only when no option
  is better supported by the conversation, the records and the code and a wrong pick is costly to undo;
  every such gap is asked in the same turn with Claude Code's question tool, specific, with its options,
  and a vague answer is asked again
examples:
- id: EX-1
  given: the owner says 'resolve all the findings using a workflow' right after the agent listed review
    findings
  when: the check runs
  then: 'no question: the read-back assumes ''the findings I listed above'' and the work starts'
- id: EX-2
  given: a request that could change a public interface two ways, neither favoured by any record or the
    conversation
  when: the check runs
  then: one question is asked with the question tool, with both ways and what each costs to undo
  quote: Question tool should be more practical than cards to clarify the intent
  prompt: 004a8f1ac780e8a5
- id: EX-3

  when: the check runs
  then: three assumption lines on the read-back and no question
- id: EX-4
  given: the owner answers a question with 'whatever works'
  when: the agent reads the answer

  then: both are asked with the question tool in the same turn, not one per turn and not on a card
