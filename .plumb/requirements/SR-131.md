id: SR-131
title: A recommendation is assumed, not asked; one blocking question at most
statement: When the commanded check (/plumb clarify) can recommend an option, it writes the recommendation
  as a flippable assumption on the read-back and the agent builds on; a choice card blocks the build only
  when no option is better supported by the conversation, the records and the code and a wrong pick is
  costly to undo; at most one blocking card is raised per turn, and a vague answer is followed up on the
  same card
examples:
- id: EX-1
  given: the owner says 'resolve all the findings using a workflow' right after the agent listed review
    findings
  when: the check runs
  then: 'no card: the read-back assumes ''the findings I listed above'' and the work starts'
- id: EX-2
  given: a request that could change a public interface two ways, neither favoured by any record or the
    conversation
  when: the check runs
  then: one choice card blocks, with both ways and what each costs to undo
- id: EX-3
  given: a request with three open gaps, each with a recommended option
  when: the check runs
  then: three assumption lines on the read-back and no card
- id: EX-4
  given: the owner answers a choice card with 'whatever works'
  when: plumb reads the answer
  then: the card stays open and a pick is still needed; no option is taken for the owner
- id: EX-5
  given: the owner asks in the conversation for a change with one blocking choice
  when: the check returns it to the agent
  then: the one question waits on a card the owner answers; the agent's reply says in one line that it
    waits there and does not restate the question or its options
