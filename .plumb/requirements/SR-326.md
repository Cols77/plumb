---
id: SR-326
title: A plumb defect becomes a landed fix of plumb
feature: FEAT-008
statement: 'In plumb''s own repository, when a debug case''s rerun fails again, the self-debug workflow
  runs in the background in a git worktree and branch of its own: it gathers the evidence (the case, its
  log entry, the records and the code path), finds the cause in plumb''s code, writes a failing test that
  reproduces the case, fixes plumb, runs the covering tests, repins every link the change moved once their
  tests pass, has the judge review the change against the requirements and intents it touches, and commits
  the fix on the case''s branch with the requirement trailer. The case is resolved when the branch holds
  the fix; main is never merged by the workflow. A fix the judge says changes a requirement''s or intent''s
  meaning is not committed: the owner gets one question through the question tool. After three rounds
  without a committed fix the case ends as a defect report to the agent, naming what was tried and what
  is missing.'
examples:
- id: EX-1
  given: a planted refusal in a plumb step whose rerun fails again
  when: the workflow runs
  then: a branch named for the case holds a test that failed before the fix and passes after it, the covering
    tests pass, no link is stale, the judge review is logged, and the case is resolved
- id: EX-2
  given: a fix that leaves a link stale
  when: the workflow reaches the commit
  then: the link is repinned once its tests pass and the judge keeps the meaning, else nothing is committed
    and the case stays open naming the link
- id: EX-3
  given: a fix the judge reads as changing what a requirement means
  when: the review runs
  then: nothing is committed, the case stays open, and the owner gets one question through the question
    tool about the behaviour, in their words
- id: EX-4
  given: three rounds that each failed the tests or the review
  when: the third ends
  then: nothing is committed, the case is a defect report to the agent naming the rounds and what is missing,
    and the owner is asked nothing
- id: EX-5
  given: no judge can be reached
  when: the review is due
  then: the workflow holds there, says so once, and commits nothing
- id: EX-6
  given: the owner keeps working in the main checkout
  when: the workflow runs
  then: no file of the main checkout changes and main is not merged
