---
id: SR-286
title: Each merge into main tidies away what the landed records supersede
feature: FEAT-001
statement: When work merges into main, a background tidy job deletes, in one tidy commit, the documents
  the landed records supersede and the working files the landing names (the landing lists those paths
  in its decision record), and removes any named folder outside the repository without a commit. A file
  a current record still cites is kept, unless the landing first rewords that record to cite the records
  that replaced the document; for the version 2 landing that means the descriptions and 'Sub-project N'
  titles of FEAT-001 to FEAT-008. The plumb line of the first turn end after the job finishes names what
  was removed; running it again changes nothing.
examples:
- id: EX-1
  given: the version 2 records land, their decision record names the sub-project specs and plans of sub-projects
    1 to 8, followups.md and the v2 working files, and the landing rewords the FEAT-001 to FEAT-008 descriptions
    and titles that cite those specs and plans
  when: the merge into main completes
  then: those files are gone in the landing's tidy commit, sp9-intent-loop.md and concept.md stay, no
    current record cites a removed file, and the next turn end's plumb line names what was removed
- id: EX-2
  given: the version 2 landing also names the pruned-worktree archive, a folder outside the repository
  when: the tidy job runs
  then: the folder is removed without any commit, and the same plumb line names it
- id: EX-3
  given: a landing names as superseded a document that a current confirmed record still cites
  when: the tidy job runs
  then: the document stays and the inconsistency goes to the debug workflow, not to the owner
- id: EX-4
  given: the tidy job already ran for this landing
  when: it runs again
  then: no file is deleted, written or committed
- id: EX-5
  given: an owner's file in docs/ that no landing named
  when: the tidy job runs
  then: the file is untouched
proof:
  plan: 'Recommended: on the version 2 landing, the owner sees the plumb line naming what was removed,
    the agent shows the tidy commit''s file list matching it, and running the tidy job again reports nothing
    to do. The owner decides whether this is the proof.'
  kind: hook
