id: SR-380
title: plumb keeps the parts the owner uses and freezes the hosts not...
statement: 'The Obsidian view, the pi-agent-factory importer, the MCP server, the Pi adapter, the card-press
  surface and the triage and spec approve commands are removed with their tests, and their records retired
  with a trail. The benchmark is frozen. The Codex and Hermes adapters are hooks-based (both hosts run
  lifecycle hooks) and are not frozen: their links and tests count like any other part (owner, 2026-11-03).
  A frozen part (the benchmark) takes no new records or tests and counts in no drift, brief or merge hold;
  a frozen part that names a host wakes when that host works on plumb. Installing plumb pulls PyYAML only;
  video studies need the optional extra plumb[video].'
examples:
- id: EX-1
  given: the repository after this work
  when: plumb view, plumb import, plumb mcp, plumb triage or plumb spec approve is typed
  then: plumb says the command does not exist
- id: EX-2
  given: the Codex adapter's tests
  when: the session brief or the merge check runs with Claude Code as the working agent
  then: their stale links and missing evidence are counted like any other part's
- id: EX-3

  when: that host's session starts on plumb
  then: the part wakes and counts again
- id: EX-4
  given: a fresh project runs uv add plumb
  when: the install finishes
  then: Manim is not installed; plumb study render says to install plumb[video]
- id: EX-5
  given: the card-press surface is gone
  when: the panel and the browser run
  then: they show the band, the status, the loop pane and the study room, and no card

  plan: plumb --help lists none of the removed commands; the test suite has no test for them; the brief
    on this repository counts no drift from the frozen adapters or the benchmark; a fresh install of the
    wheel pulls only PyYAML.
