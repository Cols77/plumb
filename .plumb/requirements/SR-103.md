id: SR-103
title: The clarifier asks every blocking question up front, with the...
feature: FEAT-008
statement: On every owner message a model decides whether it starts or changes intent; if so it drafts
  the read-back with will, won't, assumptions and two or three concrete examples, and finds the gaps that
  change what gets built; if not it returns no intent and there is no card. Per SR-131 a gap with a better-supported
  answer becomes a labelled assumption, and the owner gets at most one blocking choice card per turn,
  with suggested answers and a recommended one; assumptions stay labelled and proposed, and a choice answer
  confirms nothing by itself (per SR-130 the read-back's ok confirms its records). More than one blocking
  question with no better-supported answer escalates to a short spec session; a request with no such gap
  produces no card and work starts at once. The agent's first action is plumb clarify --wait, which returns
  the result, waiting up to a timeout for the job; until the result for the latest owner message is collected
  the guard refuses edits, and the agent does not build until a card is answered. This up-front block
  overrides INT-004's no-blocking only for gaps that change what gets built.
examples:
- id: EX-1
  given: a request "let users export their data" with format and scope unspecified
  when: the clarifier runs
  then: each question no better-supported answer settles is asked with the question tool, with suggested
    answers, and the other gaps are labelled assumptions
  quote: Clarify should ask specific questions that clarify the intent
  prompt: 004a8f1ac780e8a5
- id: EX-2
  given: a request that fully maps to a confirmed requirement
  when: the clarifier runs
  then: no question; work starts
- id: EX-3
  given: a request with three gaps and no better-supported answer for them
  when: the clarifier runs
  then: three questions are asked with the question tool, all before building; no spec session is offered
    for the count alone
  quote: It shouldn't just one question if there are more questions
  prompt: 004a8f1ac780e8a5
- id: EX-4
  given: the owner types '/plumb clarify what does plumb status show?', a question that carries no intent
  when: the clarifier runs
  then: it returns no intent, no card is shown, and the guard opens
- id: EX-5
  given: the clarify job is still running when the agent starts the turn
  when: the agent tries to edit before plumb clarify --wait returned
  then: the edit is refused; plumb clarify --wait waits for the job and the questions are ready before
    the first edit
- id: EX-6
  given: the clarify job finishes after plumb clarify --wait timed out
  when: the agent goes on
  then: a couldn't check card was shown, no build started, and the late result is collected by the next
    wait, not after the build
- id: EX-7
  given: the dispatcher fails for the clarify job
  when: plumb clarify --wait returns
  then: the owner sees a couldn't check card asking build without the check, nothing is built, and the
    guard opens only when the owner answers Build anyway by button, the typed /plumb go, or prose the
    reader maps to accepted at or above the reader's threshold
- id: EX-8
  given: a question answered with the question tool, and one labelled assumption the owner never mentioned
  when: the owner answers
  then: the answer confirms nothing; the read-back's ok confirms its records and the assumption stays
    proposed
- id: EX-9
  given: the check returned three questions and the agent asked all three with the question tool
  when: the owner answers them
  then: the answers are logged as the owner's words and carried by the read-back; no clarify job runs
    for that message (when it was typed '/plumb clarify', its job runs after the answers are read and
    returns no new gap for those questions); nothing asks them again, and the guard opens
- id: EX-10
  given: a couldn't check card is open and the owner answers "no, wait"
  when: the reader maps it to rejected
  then: the guard stays closed and the next message retries the check
- id: EX-11
  given: the clarify job fails for a typed '/plumb clarify ok'
  when: the agent tries to edit
  then: the edit is refused, because the failed model is the one that would say whether the message carried
    intent, until the owner releases it or the next turn's retry succeeds
- id: EX-12
  given: an evaluation set holding requests that need no clarification and requests with known gaps
  when: the clarifier is run on it before calibration
  then: its false-gap rate (questions asked that change nothing about what gets built) is measured and
    reported with the calibration results
