---
id: SR-103
title: The clarifier asks at most three questions up front, before building
feature: FEAT-008
statement: On every owner message a model decides whether it starts or changes intent; if so it drafts
  the read-back with will, won't, assumptions and two or three concrete examples, and finds the gaps that
  change what gets built; if not it returns no intent and there is no card. The owner gets one card with
  at most three questions, each with suggested answers and a recommended one, and the smaller gaps as
  assumptions on the same card; assumptions stay labelled and proposed, and answering the card confirms
  only the answers it maps to the questions. More than three such questions escalate to a short spec session;
  a request with no such gap produces no card and work starts at once. The agent's first action is plumb
  clarify --wait, which returns the result, waiting up to a timeout for the job; until the result for
  the latest owner message is collected the guard refuses edits, and the agent does not build until a
  card is answered. This up-front block overrides INT-004's no-blocking only for gaps that change what
  gets built.
examples:
- id: EX-1
  given: a request "let users export their data" with format and scope unspecified
  when: the clarifier runs
  then: one card asks which format and which data, each with suggested answers, and lists the remaining
    gaps as assumptions
- id: EX-2
  given: a request that fully maps to a confirmed requirement
  when: the clarifier runs
  then: no card; work starts
- id: EX-3
  given: a request with five gaps that each change what gets built
  when: the clarifier runs
  then: an escalation to a spec session is offered instead of a card
- id: EX-4
  given: the owner asks a question ("what does plumb status show?") that carries no intent
  when: the clarifier runs
  then: it returns no intent, no card is shown, and the guard opens
- id: EX-5
  given: the clarify job is still running when the agent starts the turn
  when: the agent tries to edit before plumb clarify --wait returned
  then: the edit is refused; plumb clarify --wait waits for the job and the card is ready before the first
    edit
- id: EX-6
  given: the clarify job finishes after plumb clarify --wait timed out
  when: the agent goes on
  then: a couldn't check card was shown, no build started, and the late result is collected by the next
    wait, not after the build
- id: EX-7
  given: the dispatcher fails for the clarify job
  when: plumb clarify --wait returns
  then: the owner sees a couldn't check card asking build without the check, nothing is built, and the
    guard opens only when the owner answers Build anyway by button, the typed /plumb go, or prose the
    reader maps to accepted at or above the reader's threshold
- id: EX-8
  given: a card with two answered questions and one labelled assumption the owner never mentioned
  when: the owner answers the card
  then: the two answers are confirmed and the assumption stays proposed
- id: EX-9
  given: a clarify card with three questions is open
  when: the owner answers all three in one message
  then: the read job maps the answers and is applied before that message's clarify job runs; the clarify
    job gets the answered card as input, returns no new gaps for those questions, no second card is shown,
    and the guard opens
- id: EX-10
  given: a couldn't check card is open and the owner answers "no, wait"
  when: the reader maps it to rejected
  then: the guard stays closed and the next turn retries the check
- id: EX-11
  given: the clarify job fails for an owner message that was only "ok"
  when: the agent tries to edit
  then: the edit is refused, because the failed model is the one that would say whether the message carried
    intent, until the owner releases it or the next turn's retry succeeds
- id: EX-12
  given: an evaluation set holding requests that need no clarification and requests with known gaps
  when: the clarifier is run on it before calibration
  then: its false-gap rate (questions asked that change nothing about what gets built) is measured and
    reported with the calibration results
