id: SR-225
title: Outside the loop the edit gate closes only when a request or edit...
feature: FEAT-001
statement: Outside the intent loop the edit gate closes only when the configured judge finds that a request
  or an edit contradicts or extends a confirmed record's examples and no loop has run for it; it opens
  when a loop reaches clear intent for it or the owner answers the question it raised. A question, a notice
  or a change no confirmed record covers never closes it. The gate belongs to one session and one owner
  message.
examples:
- id: EX-1
  given: SR-001 is confirmed with the example add(1, 2) returns 3 and no loop ran
  when: the prompt says make add subtract
  then: the judge flags a contradiction naming that example, the edit gate closes, and the contradiction
    is put to the owner as one question through the question tool
- id: EX-2
  given: the same confirmed requirement
  when: the prompt is "add a multiply function next to add"
  then: an extends flag is raised and the gate closes
- id: EX-3
  given: the same confirmed requirement
  when: the prompt is "also tidy the add docstring"
  then: no flag is raised and the gate stays open
- id: EX-4
  given: the same prompt after /plumb intent reached a clear intent for it
  when: an edit tool is called
  then: the edit proceeds
- id: EX-5
  given: the gate closed on a contradiction
  when: the owner answers the question it raised
  then: the gate opens; no check is rerun
- id: EX-6
  given: no confirmed record covers the status line's colour
  when: the prompt asks to change that colour
  then: the gate stays open and no model runs
- id: EX-7
  given: a confirmed decision such as DEC-054 on how browser resolution behaves
  when: the owner only asks a question about it, or a system notice arrives
  then: the gate stays open
- id: EX-8
  given: a fixture of at least 30 labelled prompts
  when: each prompt goes through the gate check
  then: the gate closes on every contradicts prompt and on no benign one
- id: EX-9
  given: a prompt matches a confirmed record and no judge is reachable
  when: the gate check runs
  then: plumb says no judge is reachable and holds the edit, never deciding by rule
- id: EX-10
  given: the owner types the same text in two sessions and one session's gate is closed
  when: the other session's check answers ready
  then: the other session's gate opens
- id: EX-11
  given: the hook logged the owner's message under digest A
  when: the gate check runs
  then: it reports digest A and opens the gate closed under A; never a second digest for the same message
proof:
  plan: 'Recommended for the owner to decide: in a scratch repository with a confirmed add requirement,
    the owner types make add subtract and the agent''s edit is refused naming the example, with one question
    through the question tool; the owner answers and the edit goes through; the owner then asks a plain
    question about a confirmed decision and the agent edits without a hold. The hook tests and the labelled-prompt
    fixture run as the check.'
  kind: hook
