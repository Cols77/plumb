---
id: SR-306
title: The merge refuses any validate error or a new stale link
feature: FEAT-003
statement: The merge check into main refuses a landing while validate shows any error, whether or not
  it was present at the merge base, and a link stale in the result but not at the base; each is named
  to the agent with the step that clears it. The owner is asked nothing.
examples:
- id: EX-1
  given: a validate error present on main before the branch
  when: the branch merges into main
  then: the merge is refused naming the error
- id: EX-2
  given: a branch that leaves a link it changed stale
  when: it merges into main
  then: the merge is refused naming the link and saying repin after its tests pass
- id: EX-3
  given: a link already stale at the merge base that the branch does not touch
  when: it merges
  then: the merge is not held for it
- id: EX-4
  given: no validate error and no new stale link
  when: the branch merges
  then: the merge goes through
proof:
  plan: 'A scratch repository with a validate error already on main: a clean branch is refused naming
    it; once fixed it lands.'
  kind: command
