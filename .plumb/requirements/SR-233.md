---
id: SR-233
title: A replaced record is retired with its trail, and its tests follow
feature: FEAT-001
statement: 'A superseded record is retired, and deleted at the next landing (DEC-145): git history and
  the supersedes trail keep it, it no longer reaches the owner or the staleness check, tests of the examples
  the new record carries relink to it, others are unlinked, and plumb validate warns about a retired example
  still verified by a test. A supersedes link naming a gone record is not dangling; plumb reports any
  other deleted record only through the links that named it.'
examples:
- id: EX-1
  given: an old requirement describes behaviour a newer one replaced
  when: the newer one is linked as superseding it
  then: the old one's links no longer appear among the stale links and no question reaches the owner about
    them
- id: EX-2
  given: a requirement that still describes current behaviour but whose links moved
  when: it is reviewed
  then: it is repinned, not retired
- id: EX-3
  given: SR-002 supersedes SR-001 and SR-001/EX-1, which SR-002 does not carry, is still verified by tests/test_a.py
  when: plumb validate runs
  then: it warns [retired-example] that SR-001/EX-1 is retired by SR-002 but still verified by tests/test_a.py
    and says to unlink the test and drop it when it covers nothing else; it never says to move the test
    to SR-002 or keep SR-001
- id: EX-4
  given: SR-001 is approved, SR-002 supersedes it, and SR-001#3 is the only test of SR-001/EX-2
  when: the agent unlinks SR-001#3 with a note
  then: 'the link is removed: a superseded record''s example is retired, so the only-test refusal does
    not protect it'
- id: EX-5
  given: a test function whose sr markers name only superseded records and that no live record links to
  when: its retired examples are unlinked
  then: the test function is deleted (the whole file when nothing live remains); a test a live record
    still links to stays and only loses the retired id from its marker
- id: EX-6
  given: SR-001 has two tests verifying EX-1 and SR-002 supersedes it verifying neither
  when: plumb validate runs
  then: both links are warned, one per link
- id: EX-7
  given: a commit with trailer SR-001 that unlinks tests/test_a.py from SR-001 and deletes the file
  when: plumb claims check runs over it
  then: 'tests/test_a.py is declared: a path a claimed record linked in the commit''s parent counts'
- id: EX-8
  given: a record a current record supersedes was deleted at a landing, and a record file deleted outright
  when: plumb validate runs
  then: the supersedes link naming the first is not dangling; the other links naming either are reported
    dangling, and a deleted record no link names is not reported
proof:
  plan: 'Recommended for the owner to decide: in a scratch repository, the AI supersedes a requirement
    and shows the status listing no stale link from the retired one, plumb explain on it reaching its
    successor, and validate warning about a test left on a retired example until it is unlinked.'
  kind: command
