id: SR-104
title: Model jobs run in the background through the host's own dispatch,...
feature: FEAT-008
statement: 'Reading and judging are jobs queued by the hooks and run by a background worker, so no hook
  waits on a model; jobs are batched (one read job per turn covering everything shown, one judge job per
  capture covering every record it wrote or changed) because each model start costs seconds; while a job
  runs the status line and, in a terminal or shell, a bar or plain lines say its current step in plain
  words and its progress (SR-108); the clarify job is queued by the hook too and is collected by the agent''s
  plumb clarify --wait outside any hook. Each job runs through the one configured dispatcher: Claude Code
  runs claude -p with a plumb agent selected by --agent, no tools, a small model, the job''s answer schema
  and no user or project settings, MCP servers, skills or CLAUDE.md, in a neutral working directory, and
  plumb''s hooks do nothing inside it; Hermes runs a delegated child session; OpenRouter only when configured.
  Only the hook-started worker applies results, and it recomputes every job''s inputs from the logs, so
  a job file carries no authority. A dispatcher that fails makes the job fail with an error the owner
  sees; nothing is confirmed, settled or rejected and the job is retried on the next turn. There is never
  a second route or a rule-based fallback.'
examples:
- id: EX-1
  given: the owner's message arrives
  when: the prompt hook runs
  then: it queues the read job and returns within its budget without waiting for the model
- id: EX-2
  given: the Claude Code dispatcher runs a job
  when: plumb's hooks fire inside that headless session
  then: they exit at once and queue nothing
- id: EX-3
  given: the configured model is unreachable
  when: the turn ends
  then: the summary says plumb could not check the owner's answers, nothing is confirmed, and the job
    is retried next turn
- id: EX-4
  given: the same job inputs queued twice
  when: the worker runs
  then: the job runs once
- id: EX-5
  given: the configured model is unreachable
  when: the worker runs the read job
  then: the word rules of approvals.py are not called and nothing is confirmed
- id: EX-6
  given: the Claude Code dispatcher builds its command
  when: plumb starts the job
  then: the command selects the plumb agent with --agent and passes --setting-sources empty, --strict-mcp-config
    and --disable-slash-commands, runs in an empty temporary directory, and the job's context holds no
    CLAUDE.md text
- id: EX-7
  given: a judge job queued by the agent through plumb capture, with inputs that differ from the logs
  when: the worker runs it
  then: the worker uses the inputs it recomputed from the logs, not the file's, so the file cannot make
    a record look supported
- id: EX-8
  given: a turn whose previous reply showed five records and one open card
  when: the prompt hook queues jobs
  then: one read job covers all six items, not six jobs
- id: EX-9
  given: a capture that writes one intent and six requirements
  when: the capture finishes
  then: one judge job is queued for the seven records
- id: EX-10
  given: a read job takes eight seconds
  when: the owner looks at the status line
  then: it says "reading your answer" and the agent has carried on with nothing confirmed
- id: EX-11
  given: the worker judges a capture of seven records
  when: the owner looks at the status line
  then: it says "judging 7 records" with the progress, and the line disappears when the job ends
- id: EX-12
  given: a job that fails midway
  when: it stops
  then: the progress line is replaced by one naming the step that failed, and the status line no longer
    shows it as running
