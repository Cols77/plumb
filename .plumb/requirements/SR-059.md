---
id: SR-059
title: An imported record is confirmed only where an upstream human consent pins its current content
feature: FEAT-004
statement: For each imported SR, a pi-agent-factory consent record with decision approve, reviewer human
  and the consent phrase whose requirement_sha256 matches the source SR file's current content yields
  one approval by import citing the consent path and digest, written only after the owner confirms it
  in their own terminal (never under the agent session marker); every other imported record is proposed;
  a by import approval confirms only what an earlier import event outside the agent session approved at
  that hash, in status, hooks, merge and plumb validate alike.
examples:
- id: EX-1
  given: a consent file for SR-077 whose requirement_sha256 matches the current SR-077 file
  when: the import runs
  then: SR-077 is confirmed by import and the approval cites the consent file
- id: EX-2
  given: a consent file pinning an older SR-078 content
  when: the import runs
  then: SR-078 is proposed
- id: EX-3
  given: a consent file with reviewer agent
  when: the import runs
  then: it is ignored and the SR is proposed
- id: EX-4
  given: an agent session, a consent file pinning the current SR-077, or a by import approval the agent
    appended itself
  when: the import runs, or plumb status reads the log
  then: SR-077 stays proposed and no by import approval confirms it
