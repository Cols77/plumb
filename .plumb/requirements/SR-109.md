Given a project with the canonical Claude skill templates and no trusted live Hermes activation, when install hermes runs, then .hermes/plugins/plumb/skills/plumb/SKILL.md and plumb-clarify/SKILL.md reuse the canonical content with the selected launcher. Given a foreign or missing skill file, when install, dry-run, uninstall, or plugin registration runs, then foreign files are preserved, dry-run writes nothing, uninstall removes only owned files, and foreign files are never registered as trusted. Given the pinned Hermes PluginManager in a temporary home, when the generated plugin registers skills, then bare names plumb and plumb-clarify resolve explicitly as plumb:plumb and plumb:plumb-clarify, while flat plumb discovery is not claimed. Edge cases: absent register_skill is safe; invalid/missing files are inert; launcher changes update owned files idempotently; parentless cron and live activation remain unsupported evidence classes.
