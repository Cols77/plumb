---
id: SR-238
title: The pi-agent-factory import is read-only, idempotent and never...
feature: FEAT-004
statement: plumb import reads pi-agent-factory's register (requirements, features with bundles, NCs and
  their relations as symbol and test-node link ends) without writing to it; a dry run prints the plan;
  a repeated import changes nothing. Every imported record is proposed, except a requirement whose upstream
  human consent pins its current content, which is approved by import citing that consent; an approval
  the agent appended itself never approves.
examples:
- id: EX-1
  given: a scratch target and a source
  when: plumb import --dry-run runs
  then: it prints create lines for every record and the target is unchanged
- id: EX-2
  given: a target after one import
  when: the same import runs again
  then: no file changes and no import event is appended
- id: EX-3
  given: the source SR-003 statement changed
  when: the import runs again
  then: the plan shows update SR-003 statement and the record is rewritten, re-pinned and proposed
- id: EX-4
  given: a consent file for SR-077 whose requirement_sha256 matches the current SR-077 file
  when: the import runs
  then: SR-077 is approved by import and the approval cites the consent file
- id: EX-5
  given: a consent file pinning an older SR-078 content
  when: the import runs
  then: SR-078 is proposed
- id: EX-6
  given: a consent file with reviewer agent
  when: the import runs
  then: it is ignored and the SR is proposed
- id: EX-7
  given: a by import approval the agent appended itself, not written by an import from a matching consent
  when: plumb status reads the log
  then: SR-077 stays proposed and the approval is ignored
- id: EX-8
  given: an SR binding implemented_by path src/x.py symbol mod:fn
  when: it is imported into a target holding src/x.py
  then: the link names src/x.py::fn and an edit elsewhere in src/x.py leaves it current
- id: EX-9
  given: FEAT-001 lists SR-050 that its bundle lacks
  when: the import runs
  then: FEAT-001's requirements include SR-050 and a membership-difference finding names it
- id: EX-10
  given: any import
  when: it finishes
  then: the source tree's files and git status are unchanged
- id: EX-11
  given: a pi-agent-factory checkout with an approved SR-012 and no consent file
  when: plumb import runs
  then: SR-012 is imported as proposed and the checkout is unchanged

    scratch target and shows the dry-run plan, the second run changing nothing, the source''s git status
