---
id: SR-003
title: Links pin both ends; a moved end makes the link stale; dangling links are errors
feature: FEAT-001
statement: Every link records the content hash of both of its ends; plumb reports the link stale (naming
  the source, the target or both) when either current hash differs from its pin, dangling (an error) when
  its target is missing, and unpinned (a warning) without a pin; repinning refreshes pins, logs a repin
  event and never confirms.
examples:
- id: EX-1
  given: SR-001 verified_by a test file with current pins
  when: the test file's content changes
  then: plumb reports the link stale with the target moved
- id: EX-2
  given: the same link
  when: the test file is re-saved with CRLF line endings only
  then: the link stays current
- id: EX-3
  given: a link whose target record or file does not exist
  when: plumb validate runs
  then: it reports a dangling-link error
- id: EX-4
  given: a stale link
  when: plumb repin names it
  then: its pins are refreshed, a repin event is logged and no record becomes confirmed
