---
id: SR-033
title: plumb explain answers in the owner's terms for plain words, a path or an ID
feature: FEAT-001
statement: plumb explain <anything> (alias why) resolves record IDs, then a repository path (the requirements
  that own it), then plain words (best matching records), and prints each record's upward chain in the
  owner's terms - state, the owner's words it derives from, decisions, examples, test state and code.
  The installed /plumb command routes explain with plain-language arguments, keeps why as an alias, and
  advertises only subcommands the CLI has; plumb --help no longer lists unavailable commands.
examples:
- id: EX-1
  given: SR-001 "Invoice totals are rounded to the cent" deriving from INT-001 and implemented by src/billing.py
  when: plumb explain SR-001 runs
  then: it prints the title and state, the owner's quote, EX-1 and "code src/billing.py"
- id: EX-2
  given: the same records
  when: plumb explain src/billing.py runs, then plumb explain src/orphan.py
  then: the first resolves to SR-001; the second says no requirement owns the file yet and exits 1
- id: EX-3
  given: the same records
  when: plumb explain how are invoice totals rounded? runs
  then: it resolves by words to SR-001 or INT-001, not SR-002
- id: EX-4
  given: plumb install claude-code
  when: the /plumb command file is read
  then: its argument hint offers "explain <anything a feature, a behaviour, a file or an ID>", not "why
    <ID|path>", and each advertised subcommand exists in the CLI
