id: SR-289
title: Replaced records leave the tree and count nowhere
statement: When work lands, every record a current record supersedes, and every decision deciding only
  such records, is deleted from .plumb; the current record's supersedes link to the gone id stands and
  validate reports no dangling link for it. The tests that verified only dropped examples go in the same
  commit as their links, and documents no current record, the README or the code cites go with them. Status,
  validate, the cards and the conflicts count only the records present.
examples:
- id: EX-1
  given: SR-103 is superseded by a current requirement
  when: the clean-up lands
  then: SR-103's file is gone, the current requirement's supersedes link to SR-103 stands, and plumb validate
    reports no dangling link for it
  quote: a lot of dirty artifacts that should be removed
  prompt: ff6c56bf42d907e1
- id: EX-2
  given: DEC-013 decides only INT-009, which is replaced
  when: the clean-up lands
  then: DEC-013 is gone with INT-009
- id: EX-3
  given: a test verifies only an example that a current requirement dropped
  when: the clean-up lands
  then: the verified_by link is removed and the test is deleted in the same commit; a test that also verifies
    a current example stays
- id: EX-4
  given: a document under docs/ that no current record, the README or the code cites
  when: the clean-up lands
  then: the document is gone; docs/hosts.md, cited by a current record and the README, stays
- id: EX-5
  given: a card or an intent conflict about a record that is gone
  when: plumb status runs
  then: it is neither shown nor counted as awaiting the owner
- id: EX-6
  given: the clean-up has landed and the tests passed
  when: the owner says /plumb status
  then: the card shows no stale link, no regression, no record awaiting the owner on a gone record, and
    the judge backlog counts current records only
  quote: Plumb status is very dirty
  prompt: ff6c56bf42d907e1
