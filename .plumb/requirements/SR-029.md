---
id: SR-029
title: One source definition for the trace and the covering tests; flat layouts are traced
feature: FEAT-001
statement: plumb.trace.is_code_path is the one definition of source code that the untraced-change trace
  (stop hook, prompt hook, merge boundary) and the covering-test selection share. A file under a configured
  source_dirs entry is source; when .plumb/config.yaml does not name source_dirs, a code file (by suffix)
  anywhere outside the test directories, docs/ and dot directories is source too, so a repository not
  laid out as src/ (a flat package, a root module) gets the same untraced-change signal. Generated files,
  tests, docs and plumb's own state are never source.
examples:
- id: EX-1
  given: a repository with no source_dirs configured and a changed mypkg/extra.py and tool.py that no
    requirement owns
  when: the stop hook runs
  then: the summary names both as untraced and queues the read-back for the next prompt, without blocking
- id: EX-2
  given: the same changes on a branch
  when: plumb validate --merge BASE runs
  then: it lists mypkg/extra.py and tool.py as untraced and exits 4; NOTES.txt is not listed
- id: EX-3
  given: source_dirs set to [lib] in .plumb/config.yaml
  when: lib/x.py, tool.py and src/mul.py change
  then: only lib/x.py is source
- id: EX-4
  given: the covering-test selection and the trace
  when: they decide whether a changed path is source
  then: they use the same is_code_path answer
