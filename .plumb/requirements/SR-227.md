---
id: SR-227
title: A big request's records are approved as one set, in one step
feature: FEAT-007
statement: In the loop a big request's records are one set; once clean, the judge cascade approves it
  in one step under one set hash over its members' hashes, marked judge-approved; editing a member unconfirms
  it and the set. With no judge reachable the set is held, never approved by rule.
examples:
- id: EX-1
  given: an intent with members SR-070 and SR-071, clean
  when: the judge cascade validates the set
  then: one approval event, marked judge-approved, carries the set hash of the sorted [id, hash] pairs
    and approves all three records
- id: EX-2
  given: the set is approved
  when: SR-071 is edited
  then: SR-071 is an unconfirmed edit and the set shows as unconfirmed
- id: EX-3
  given: a clean set and no judge reachable
  when: approval is sought
  then: plumb says so and holds the set; nothing is approved by rule
proof:
  plan: 'Recommended for the owner to decide: in a live session on a scratch repository, the owner opens
    /plumb intent for a change touching two features, answers only the trade-off question, and the plumb
    line says the judge approved the set.'
  kind: live-session
