id: SR-348
title: Every run fixes and reruns by itself; the owner is asked only on a...
statement: After a run, each issue filed becomes a debug case in plumb's own repository (kind eval-issue,
  the plumb command as target, expected and got as detail, the context as log), unless an open case already
  holds the same command and got. By default plumb evaluate <task> then runs plumb's debug workflow on
  the new cases (the self-debug fix on a branch per case), merges each fixed branch into the current branch
  through plumb's merge check, and runs the task once more; --rounds N allows N fix rounds, each ending
  in a rerun, and --rounds 0 only documents the issues. The loop stops early when a run files no issue,
  when the debug workflow needs the owner (a fix the judge reads as changing a requirement's or intent's
  meaning reaches the owner through the question tool), or when the merge check holds a fix (a waiting
  question, an unconfirmed proof, a failing test), naming why. Each round prints its score line, the cases
  opened, each case's outcome and each merge. The owner is asked nothing else.
examples:
- id: EX-1
  given: a run filed an issue about plumb capture
  when: the run ends
  then: one debug case of kind eval-issue is open in plumb's repository with the command, the expected,
    the got and the context
- id: EX-2
  given: an open eval-issue case with the same command and got
  when: a later run files it again
  then: no second case is opened and the run's score still counts the issue
- id: EX-3
  given: --loop 3 and the second run files no issue
  when: the second run ends
  then: the loop stops after two runs and says so
- id: EX-4
  given: --loop 2 and the debug workflow holds a case on a meaning question for the owner
  when: the debug round ends
  then: the loop stops before the second run, names the case, and the question reaches the owner through
    the debug workflow as today
- id: EX-5
  given: --loop 2 and the first debug round fixes every case
  when: the round ends
  then: the second run starts and its score line follows the first's
- id: EX-6
  given: --loop 2 and the first debug round fixed a case on its branch
  when: the round ends
  then: the branch is merged into the default branch through plumb's merge check, and the second run starts
    on the merged code
  quote: ensure plumb compliant merge of the fixes
- id: EX-7
  given: the merge check holds a fixed branch (a question waits or a proof is unconfirmed)
  when: the merge is tried
  then: the loop stops before the next run and says what holds the merge; nothing is forced
