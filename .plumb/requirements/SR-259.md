id: SR-259
title: A capture that contradicts another branch's claim is put to the...
feature: FEAT-006
statement: When a capture or direct edit would change a record another branch has claimed, or the judge
  finds a new requirement contradicts another branch's claim in the same feature, the agent asks the owner
  one question through the question tool showing both versions by branch, before any record is written,
  and one early decision that matters is raised once; it outlives the question and is answered by it.
  A compatible overlap is one warning line. With no judge, or an unsure JEV, the overlap counts as unsure,
  never as compatible. Until a record matches the owner's answer, the agent is told every turn that it
  differs and status lists it; a record that changed on main after this branch started is named as such.
examples:
- id: EX-1
  given: branch feat-x claimed a change to SR-005 "relay checks"
  when: this worktree captures a different change to SR-005, by capture or a direct edit
  then: before any record is written the agent asks the owner one question through the question tool showing
    both versions by branch, and one decision that matters is raised
- id: EX-2
  given: branch feat-x claimed new intent in FEAT-002
  when: this worktree captures a new requirement in FEAT-002 that the judge finds contradictory
  then: the same question is asked and the decision is recorded
- id: EX-3
  given: branch feat-x claimed new intent in FEAT-002
  when: this worktree captures a new requirement in FEAT-002 the judge does not find contradictory
  then: only a one-line warning naming the record and feat-x reaches the agent, and no decision is written
- id: EX-4
  given: the conflict on SR-005 was already raised as a decision on branch feat-x
  when: this worktree captures SR-005 again
  then: no second decision is written and the line names that decision's question, with the owner's answer
    once given
- id: EX-5
  given: the agent asked the owner the conflict on SR-005
  when: the owner answers "keep feat-x's" in the question tool
  then: the decision holds that version, recorded from the owner's answer, and feat-x's next awareness
    line names it without a further turn
- id: EX-6
  given: branch feat-x claimed new intent in FEAT-002 and no judge can be reached, or JEV is unsure on
    an overlapping new requirement
  when: the capture runs
  then: 'the agent is told both versions and why plumb could not judge ("judging unavailable: <cause>");
    the overlap is treated as unsure, never as compatible, and put to the owner if the versions differ;
    no word rule judges in its place'
- id: EX-7
  given: feat-b raised an early decision on SR-005 against feat-a, main merged one of them, and the decision
    is unanswered
  when: the conflict is put to the owner on main
  then: both versions are labelled by branch, never as "this work", and the owner's answer to the merge's
    intent conflict on SR-005 also answers the decision
- id: EX-8
  given: the owner kept feat-x's version of SR-005 and main's SR-005 still holds another version
  when: main's next prompt or stop hook runs, or status is shown
  then: the agent is told every turn that SR-005 differs from the owner's answer until it matches, and
    status lists it
- id: EX-9
  given: the owner kept main's version of SR-005, the answer merged into feat-x, and a later request changed
    SR-005 again on feat-x
  when: feat-x's next prompt or stop hook runs or the brief is shown
  then: SR-005 is not named as holding the turned-down version; only a record still holding that version
    is named (the answer is a signal, never a lock)
- id: EX-10
  given: feat-x started from main; main then changed and committed SR-005, so main's claim cleared
  when: feat-x captures or edits different words for SR-005
  then: the question shows main's version and this branch's, one decision is raised once, and feat-x's
    brief and status say SR-005 changed on main after this branch started; nothing is raised once feat-x
    holds main's version or leaves SR-005 as it started
proof:
  plan: 'Recommended for the owner to decide: two live sessions in two worktrees; after the first changes
    a requirement, the owner asks the second for a contradicting change and gets one question-tool question
    before any code is written; after the answer, the other branch''s next line names the decision.'
  kind: live-session
