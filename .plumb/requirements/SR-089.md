---
id: SR-089
title: Owner-visible text names no shell command and speaks at the owner's level
feature: FEAT-007
statement: 'No text the owner sees (the README and owner guides, cards, summaries, the band and status
  line, background-check messages, /plumb answers, error messages, merge and push reports, git''s check
  messages, the Obsidian vault, and the content of the records the owner confirms) names a shell command;
  it names the /plumb command or the plain words to say. All of it speaks at the owner''s level: goals,
  behaviours and the owner''s words, never plumb''s or the code''s inner workings (internal codes, record
  numbers without their titles, folder and file names, test names) unless the owner asks; an idea that
  is genuinely needed is explained first in one plain sentence. One place holds plumb''s wording for the
  owner, two checks (shell commands, inner workings) test every surface, and records are checked when
  the agent writes them, so the agent rewords them before the owner ever sees them (rulings R14, R18).'
examples:
- id: EX-1
  given: a push carrying a requirement the owner has not confirmed
  when: the push check reports
  then: it says to type /plumb confirm with the requirement's title or to say ok, and names no command
    to run, no way to skip the check and no record number without its title
- id: EX-2
  given: a merge where code tied to a requirement changed
  when: the merge report lists it
  then: it asks the owner to look at what changed in that requirement, by its title, and names no command
    to run
- id: EX-3
  given: a turn that touched a decision
  when: the summary is shown
  then: it names the decision by its question in plain words, never by its number alone
- id: EX-4
  given: the owner asks why a merge is held, and the answer needs the idea that plumb remembers the exact
    wording confirmed
  when: the agent or plumb answers
  then: the answer first says in one plain sentence that plumb remembers the exact wording the owner confirmed
    and asks again when it changes, then uses it
- id: EX-5
  given: the README
  when: both checks run on its owner sections
  then: they find nothing, and the agent's command reference sits in its own section
- id: EX-6
  given: a requirement awaits the owner
  when: the owner opens its note in the Obsidian vault
  then: the note says to type /plumb confirm with its title or to say ok in a Claude Code session, names
    no command to run, and shows its links by title
- id: EX-7
  given: the agent writes a requirement whose statement uses one of plumb's internal terms
  when: plumb records it
  then: plumb refuses it and tells the agent which words to put in the owner's terms; the owner is asked
    nothing
- id: EX-8
  given: a record quotes the owner's own words, and those words mention a command
  when: plumb records it
  then: the owner's words are kept exactly as the owner said them
- id: EX-9
  given: the owner asks what drifted, asks to see a requirement in full, or asks whether a requirement
    does what they meant
  when: the agent shows plumb's answer
  then: the answer names each requirement by its title and its examples in plain words, says what to do
    next as a /plumb command or plain words, and shows no record number without its title, no fingerprint,
    no folder or file name and no command to run; the technical form appears only when the owner asks
    for detail
