---
id: SR-039
title: The JEV client sits behind the judgment protocol, its credential named in config and read from
  the environment
feature: FEAT-002
statement: The JEV live client is reached only through get_backend and the JudgmentBackend protocol, which
  gains entailment, contradiction, choose and ask. Its credential is read from the environment variable
  named by judgment.jev.credential_env (or the user store), never from the repository; plumb jev setup
  records only that name, plumb jev status reports configured, credential present, reachable and model
  version without printing the secret, and live tests are skipped when the credential is absent.
examples:
- id: EX-1
  given: judgment.backend jev and no credential in the environment
  when: a hook asks for an intent-change judgment
  then: the heuristic answers and one notice is logged for the session
- id: EX-2
  given: any repository
  when: plumb jev setup --env-var MY_KEY runs
  then: config.yaml names MY_KEY, a jev-setup event holds the name, and no secret is written anywhere
- id: EX-3
  given: the credential variable is unset
  when: the test suite runs
  then: every jev_live test is skipped and the suite passes
- id: EX-4
  given: 'judgment.jev says provider: openrouter and nothing else'
  when: plumb loads its config
  then: JEV posts to https://openrouter.ai/api/alpha/decisions with model typesafe/jev-1.13, validated
    against typesafe/jev-1.13, reading OPENROUTER_API_KEY; any judgment.jev value set explicitly (base_url,
    path, model, validated_against, credential_env) wins over the preset
- id: EX-5
  given: OPENROUTER_API_KEY is not in the environment and ~/.config/plumb/jev.json names an env file outside
    the repository that holds it
  when: plumb resolves the JEV key
  then: the key is read from that file in place, the source label is env-file, and the key is written
    to no repository file, log entry, judgment record, notice or output; an env file inside the repository
    is refused
- id: EX-6
  given: the owner says /plumb jev setup openrouter and names an env file outside the repository
  when: the agent runs plumb jev setup --provider openrouter --env-var OPENROUTER_API_KEY --env-file PATH
  then: config.yaml gets only provider, model and the variable name, the user-level jev.json names the
    variable and the env file, and /plumb jev status shows the provider, endpoint, key source label, reachability
    and the normalized resolved version, never the key
- id: EX-7
  given: a JEV key resolves, from the environment or through the env file
  when: the jev_live test runs
  then: it sends one tiny synthetic request, no repository content, and passes; with no key it is skipped
