---
id: SR-039
title: The JEV client sits behind the judgment protocol, its credential named in config and read from
  the environment
feature: FEAT-002
statement: The JEV live client is reached only through get_backend and the JudgmentBackend protocol, which
  gains entailment, contradiction, choose and ask. Its credential is read from the environment variable
  named by judgment.jev.credential_env (or the user store), never from the repository; plumb jev setup
  records only that name, plumb jev status reports configured, credential present, reachable and model
  version without printing the secret, and live tests are skipped when the credential is absent.
examples:
- id: EX-1
  given: judgment.backend jev and no credential in the environment
  when: a hook asks for an intent-change judgment
  then: the heuristic answers and one notice is logged for the session
- id: EX-2
  given: any repository
  when: plumb jev setup --env-var MY_KEY runs
  then: config.yaml names MY_KEY, a jev-setup event holds the name, and no secret is written anywhere
- id: EX-3
  given: the credential variable is unset
  when: the test suite runs
  then: every jev_live test is skipped and the suite passes
