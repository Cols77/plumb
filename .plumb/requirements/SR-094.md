---
id: SR-094
title: A big plan is checked and repaired before the owner is offered it
feature: FEAT-007
statement: 'Before a big plan (an escalated set of records) is offered for confirmation, plumb checks
  its structure: every part comes from the plan''s intent, every "will" is served by a requirement, every
  requirement has an example, every "done when" item has an example, and nothing goes against a "won''t"
  (plumb''s judge decides that one). The agent fixes every gap in the structure itself and checks again
  until the plan is clean; the owner is asked only about intent or tradeoffs (a "will" that cannot be
  served without breaking a "won''t", two incompatible readings, a scope choice). The offer to confirm
  (the summary''s offer line, /plumb confirm of the plan, a Confirm button) appears only for a clean plan,
  and an ok passed on for a plan that is not clean is refused (ruling R18.4).'
examples:
- id: EX-1
  given: a big plan where one requirement has no example
  when: plumb checks the plan
  then: the gap goes to the agent, no offer is shown, the agent adds the example, and the next check is
    clean and shows the offer
- id: EX-2
  given: a plan whose "will" "email the reminders" goes against its "won't" "keep email addresses"
  when: plumb checks the plan
  then: the owner is asked one question about that tradeoff, recorded as a decision that matters
- id: EX-3
  given: a plan that is not clean
  when: the agent passes on an ok for the plan
  then: it is refused, naming the gaps to the agent
- id: EX-4
  given: any gap the agent can fix
  when: the owner's views are drawn
  then: the owner never sees it
