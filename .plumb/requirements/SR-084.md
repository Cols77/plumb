---
id: SR-084
title: Projects set up the old way keep working and can move to the plugin
feature: FEAT-007
statement: A project set up the old way (plumb's settings, the /plumb command and the skills copied into
  the project) keeps working as before, and while the plugin is active there the plugin stays silent,
  so nothing runs twice. /plumb init there, or "move plumb to the plugin", removes only what plumb wrote
  (its own settings and unchanged copies), points git's checks at plumb's launcher, and names anything
  it left in place (ruling R15).
examples:
- id: EX-1
  given: a project set up the old way, with the plugin also installed
  when: a turn runs
  then: each of plumb's checks runs once and the owner sees one summary
- id: EX-2
  given: that project, where the owner edited the copied /plumb command and added a Claude Code setting
    of their own
  when: the owner says "move plumb to the plugin"
  then: plumb's own settings and the unchanged copied skills are removed, the edited command and the owner's
    own setting stay and are named, and git's checks call plumb's launcher
- id: EX-3
  given: a machine without the plugin (a teammate, a build server)
  when: the old project-level checks run
  then: they behave exactly as before
