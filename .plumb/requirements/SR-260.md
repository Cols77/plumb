id: SR-260
title: The merge is the one hold on unapproved or conflicting intent
feature: FEAT-003
statement: 'One lightweight merge check runs when git records a merge, rebase, cherry-pick or revert step
  (quick, no tests) and at push, where the pre-push hook runs the same check with the covering tests and
  the full suite only when full verification is pending (P10). A merge is held only by what the owner
  named (DEC-252): a conflict (an open intent conflict, colliding ids, or a contradiction the judge is
  sure of), a question waiting for the owner on a touched record (one filed by an ended session travels
  in the JSON form and the landing session asks it once, DEC-519; a hidden-regression flag is such a question,
  ended by the owner''s needed answer), a failing test (a test linked to a touched requirement whose latest
  recorded run fails, read from the evidence with no test run), and, for a merge into the default branch,
  a requirement whose behaviour the merge changes (its words, pins aside, or its linked code or tests
  differ from the base, or a plain commit naming it in its SR trailer changes code or tests; link-refresh
  commits and merge commits'' lists deliver nothing, DEC-518) whose proof the agent has not shown working
  or the owner has not confirmed through the question tool (DEC-256, DEC-257); and by integrity (DEC-255):
  stale links the merge adds, new links to files no test covers, record files unreadable or left out of
  the commit, a broken log (a merge that deletes a committed log entry not kept in an archive segment)
  and any validate error in the merged result. Tests, questions and proofs hold only a merge into the
  default branch; a merge into a work branch holds only on conflicts and integrity (DEC-271). Records
  waiting on a judge, links and exemptions added since an approval, and paths no trailer declares are
  listed in the full report (plumb context merge and the JSON form) and never hold; an exemption added
  on a branch is honoured and listed, the judge accepting it unless it contradicts the owner (SR-288,
  SR-372). The landing job starts when a merge into the default branch is recorded, by git merge or by
  a git commit that finishes it; shared log entries the checkout has not committed yet do not hold a merge
  (the landing job commits them). A rebase, cherry-pick or revert step is held while it meets an open
  intent conflict on a record. The check exits 1 for integrity, 5 for a failing test or an unconfirmed
  proof and 4 for a conflict or an open question, reporting the first of 1, 5 and 4 that applies; the
  quick merge check at git''s merge step and plumb merge-check print only what holds the merge (SR-374
  EX-6); the full report (plumb context merge, and plumb validate --merge, the report-only form with the
  same verdict) lists the rest as well and fits one screen.'

    covering tests only.'
