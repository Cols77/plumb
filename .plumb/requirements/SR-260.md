id: SR-260
title: The merge is the one hold on unapproved or conflicting intent
feature: FEAT-003
statement: One lightweight merge check runs when git records a merge, rebase, cherry-pick or revert step
  (quick, no tests) and at push, where the pre-push hook runs the same check with the covering tests and
  the full suite only when full verification is pending (P10). A merge is held until every touched requirement
  is approved, by the owner or the judge, at its current hash, no link or exemption added since is unapproved,
  no intent conflict is open, no ids collide, commits touch only paths their trailers' requirements declare,
  links are fresh and point at tested files, no affected acceptance test fails or lacks a passing run,
  the log is intact (a merge that deletes a committed log entry not kept in an archive segment is a broken
  log) and validate shows no error in the merged result. A rebase, cherry-pick or revert step is held
  while it meets an open intent conflict on a record. The check exits 1 for an undeclared path, a stale
  or dangling link, a broken log or any other validate error in the merged result (SR-306), 5 for a failing
  or unverified acceptance test and 4 for unapproved or conflicting intent, reporting the first of 1,
  5 and 4 that applies; its report fits one screen.
examples:
- id: EX-1
  given: any repository
  when: the merge check runs without tests
  then: no file outside .plumb/cache changes
- id: EX-2
  given: 25 untraced paths
  when: the report renders
  then: it shows 10 and "+15 more" with the full list in its JSON form
- id: EX-3

  when: git push runs
  then: the push is refused

  then: it names the path with the fix and exits 1
- id: EX-5

  when: the merge check runs
  then: it names the moved end and the repin and exits 1
- id: EX-6
  given: a confirmed example whose acceptance test fails and an unconfirmed touched record
  when: the merge check runs
  then: it exits 5 (precedence 1, then 5, then 4)
- id: EX-7
  given: a merge that adds a stale link, or a link to a file no test covers
  when: it is merged
  then: the merge is held naming them
- id: EX-8

  when: the merge check runs
  then: it lists SR-034 by title as awaiting approval and exits 4
- id: EX-9

  then: SR-001 stays confirmed but is listed as extended with "new link in this range implemented_by src/z.py"
    and the check exits 4; once the extension is approved (judge-validated against the owner's words,
    else the owner's answer through the question tool) it exits 0
- id: EX-12
  given: the same range
  when: the agent adds the same link by editing SR-001's frontmatter
  then: the check lists the same new link and exits 4

  when: the agent appends src/** to trace.exempt in .plumb/config.yaml
  then: src/z.py is still listed as untraced, the exemption is listed as added in this range and the check
    exits 4; once the exemption is approved it exits 0 and lists it among the approvals
- id: EX-14

  then: src/z.py is still listed as untraced and the check exits 4

  then: nothing is recorded and the check keeps listing the exemption as added and exits 4; only the owner's
    own logged words, judge-validated, or the owner's question-tool answer approve it
- id: EX-16
  given: the touched SR-001 is approved at its current hash
  when: the merge check runs
  then: it exits 0
- id: EX-17
  given: a merge result with an open intent conflict
  when: the merge check runs
  then: it exits 4 and names the conflict by the requirement's title for the agent to put to the owner
- id: EX-18
  given: the quick merge check is installed
  when: git merge produces an intent conflict
  then: git does not record the merge commit and the output names what holds it
- id: EX-19
  given: the quick merge check is installed
  when: git merge runs on a branch whose tests were never run
  then: the check reports what holds the merge without starting any test run
- id: EX-20
  given: a merge held by an open intent conflict
  when: the owner answers it and the touched requirements are approved
  then: the quick check passes and the merge can be finished
- id: EX-21
  given: JEV is configured and a merge leaves an intent conflict open
  when: the quick merge check or the pre-push hook reports it
  then: no judgment is requested and nothing is written to the log; a judgment is shown only when one
    is already logged
- id: EX-22
  given: the quick merge check is installed and a merge leaves an intent conflict open or touches an unapproved
    requirement
  when: 'the merge is finished by hand: git commit after a text conflict or after git merge --no-commit,
    git merge --continue, or git pull'
  then: git does not record the merge commit and the output names what holds it; a conflict left out of
    the commit holds it too
- id: EX-23
  given: the quick merge check is installed
  when: a rebase, cherry-pick or revert step meets an intent conflict on a record
  then: git stops on the record; continuing with the conflict still in it is refused, and after the owner's
    answer the step continues with the chosen version
- id: EX-24
  given: the owner already answered an early conflict choosing between exactly the two versions of SR-005
    a merge meets
  when: the merge check meets the resulting intent conflict
  then: it is settled from that answer (logged and staged), nothing is asked again, and finishing the
    merge records it
- id: EX-25
  given: an early decision on SR-005 was never answered and a merge leaves an intent conflict on SR-005
  when: the merge check runs and the owner then answers the conflict
  then: only the conflict is asked (the decision is not asked beside it), and the owner's answer also
    answers the decision
- id: EX-26
  given: main has not moved since feat-x branched, and feat-x touches an unapproved requirement and a
    file no requirement declares
  when: feat-x is merged into main with a plain git merge, a git pull, or an explicit fast-forward
  then: 'nothing held stays recorded on main: a plain merge or pull records a merge commit the quick check
    holds, and an explicit fast-forward is checked after git made it and main is put back where it was,
    local changes kept, and the agent is told what holds it'
- id: EX-27
  given: a validate error already present on main before the branch, which the branch does not touch
  when: the merge check runs on the merged result
  then: it names the error and exits 1

    covering tests only.'
