id: SR-385
title: plumb ships ready-made workflows for the work it hands to the agent
statement: 'plumb ships its own workflows for the work it hands to the coding agent: the debug cases a
  landing leaves, the plan and build steps of an intent loop, and landing a branch. Each carries its gates,
  the model of each stage (Sonnet unless a stage failed on it), the one-heavy-job lock around test runs
  and the checks that end it. Where plumb tells the agent to run such work on a host that has workflows,
  it names the shipped workflow; the agent writes no workflow of its own.'
examples:
- id: EX-1
  given: a landing left 3 debug cases
  when: the agent's next turn starts
  then: the text names plumb's debug-cases workflow with the 3 cases as its input, and the agent runs
    it as shipped, writing no script
- id: EX-2
  given: an intent loop whose clarify gate passed and the owner opted in to a workflow
  when: the plan step starts
  then: the plan and the build run as phases of plumb's shipped intent workflow, each phase ends on its
    gate command, and the next phase starts only when that command exits 0
- id: EX-3
  given: a branch whose build is done
  when: plumb's landing workflow runs
  then: main is merged into the branch, the full test run goes under the one-heavy-job lock, the links
    the merge moved are repinned after their tests pass, and the merge into main goes through the merge
    check with nothing forced
- id: EX-4
  given: a shipped workflow's stage that edits code
  when: the stage's agent is started
  then: it runs on Sonnet; a larger model is used only for a stage that already failed on Sonnet
proof:
  plan: 'Acceptance tests: the case text names the shipped workflow, each shipped script parses and names
    its gates and models. Then plumb evaluate complex before and after, read side by side (score, issues
    filed, wall time).'
