---
id: SR-254
title: A merge is never green while an affected acceptance test lacks a...
feature: FEAT-003
statement: 'The merge check refuses while an acceptance test of a touched requirement, or of one covering
  a changed path, fails or lacks a passing run on the current identity; a failure stays until a run passes
  it. A regression is an existing test that passed and now fails; a new red test is not one; a same-tree
  rerun pass is flaky. Shared test infrastructure sets full verification pending: the quick check at merge
  never runs tests, holds with exit 5 and has the agent ask the owner once, through the question tool,
  to run the full suite now or waive it for this exact change; the pre-push check runs the full suite
  once while it is still pending, and a passing run clears it. The report-only form and the running form
  give the same verdict on the same tree.'
examples:
- id: EX-1
  given: confirmed SR-001 with EX-1 verified_by tests/test_mod.py, which passed, and add() changed to
    subtract
  when: the covering run fails test_add and the merge check runs
  then: it lists "SR-001 EX-1 tests/test_mod.py (regression)" and exits 5; after a fix and a passing run
    it exits 0
- id: EX-2
  given: the same regression
  when: plumb drift and plumb status run
  then: drift reports the failing acceptance test and exits 1; status counts SR-001 as failing and names
    EX-1
- id: EX-3
  given: tests/core/test_links.py::test_pin_drift passed with recorded evidence
  when: it now fails
  then: it is a regression listed at the merge check, which holds until a run passes it; the owner is
    not asked
- id: EX-4
  given: a test that passed with recorded evidence and whose source was then edited
  when: it now fails
  then: it is still a regression, noted test source changed since the pass
- id: EX-5
  given: a new test written test-first
  when: it fails on its first run
  then: it is not yet passing, not a regression, and nothing interrupts the turn
- id: EX-6
  given: confirmed SR-001 with EX-1 verified_by tests/test_mod.py, and a new test in it that has never
    passed
  when: the run fails it and the merge check runs
  then: it lists "SR-001 EX-1 tests/test_mod.py (failing)" and exits 5
- id: EX-7
  given: a failing acceptance test of SR-001
  when: src/pkg/mod.py changes again and no test is rerun
  then: the merge check still lists the failure marked stale and exits 5, drift still reports it, and
    a passing run clears it
- id: EX-8
  given: confirmed SR-001 whose acceptance test passed, then src/pkg/mod.py changed
  when: the merge check runs before any rerun
  then: it lists SR-001 EX-1 tests/test_mod.py as an unverified acceptance test and exits 5; after a passing
    run it exits 0
- id: EX-9
  given: confirmed SR-001 and SR-002 (doubling, verified_by tests/test_helper.py) with a passing full
    run, and a committed tests/conftest.py that breaks pkg.helper
  when: the merge check runs
  then: it says the full verification pending holds the merge, lists SR-001 and SR-002 as affected, and
    exits 5; after a run that fails test_helper it lists the regression and still exits 5
- id: EX-10
  given: the same project and a change to src/pkg/mod.py that breaks twice(), with only tests/test_mod.py
    rerun
  when: the merge check runs
  then: it lists SR-002 EX-1 tests/test_helper.py as unverified (stale) and exits 5; after rerunning it,
    as a failing regression, still 5
- id: EX-11
  given: a pyproject.toml comment change that leaves full verification pending
  when: the question tool asks the owner whether to run the full suite or waive it for this exact change,
    and the owner waives it
  then: the merge exits 0 and says the run is waived for this exact change; a later edit makes it 5 again
- id: EX-12
  given: full verification pending and no answer from the owner
  when: the agent writes a waiver itself
  then: the waiver is refused with exit 3 and the merge still exits 5
- id: EX-13
  given: uv.lock changed since the last full run
  when: the pre-push check runs
  then: the full suite runs once and full verification pending is cleared when it passes
- id: EX-14
  given: the full run fails a test
  when: the pre-push check finishes
  then: it ran the suite once, exits 5 and writes no merge-evidence event
- id: EX-15
  given: a passing full run on the same tree and environment identity
  when: the merge check runs
  then: no suite runs and the report says full run reused
- id: EX-16
  given: a full run that collected no tests (exit 5), hit a collection error, or ran nothing
  when: full verification pending is computed
  then: it is still pending
- id: EX-17
  given: a full run in which a test fails
  when: full verification pending is computed
  then: it stays pending, naming the failed test, until a run passes that test
- id: EX-18
  given: a test fails once
  when: it passes on the same-tree rerun
  then: evidence records flaky-pass with both attempts, neither a pass nor a regression
- id: EX-19
  given: a test that fails on every rerun with the same error on the merge base too, where nothing of
    the change is present (a broken environment)
  when: the merge check runs
  then: the merge check exits 5 naming the test, the plumb line says one case went to debugging, and no
    question reaches the owner
proof:
  plan: 'Recommended for the owner to decide: in a scratch repository the agent breaks a covered function
    and runs the merge check, which exits 5 naming the regression; after the fix and a passing run it
    is green; a pyproject.toml change brings the question tool''s run-or-waive question, and the waiver
    turns red again after one more edit.'
