id: SR-254
title: A merge is never green while an affected acceptance test lacks a...
feature: FEAT-003
statement: 'The merge check refuses a merge into the default branch while an acceptance test of a touched
  requirement, or of one covering a changed path, fails or lacks a passing run on the current identity;
  a failure stays until a run passes it. A regression is an existing test that passed and now fails; a
  new red test is not one; a same-tree rerun pass is flaky. Shared test infrastructure sets full verification
  pending: the quick check at merge never runs tests, holds with exit 5 and has the agent ask the owner
  once, through the question tool, to run the full suite now or waive it for this exact change; the pre-push
  check runs the full suite once while it is still pending, and a passing run clears it. The report-only
  form and the running form give the same verdict on the same tree. On a merge into a work branch these
  test problems are listed and never hold (DEC-271). A test in a frozen part (SR-380) counts in no merge
  hold (DEC-404).'
examples:

    subtract
  when: the covering run fails test_add and the merge check runs

    it exits 0

    EX-35), are still listed and hold'

    turns red again after one more edit.'
