id: SR-032
title: Hooks inject only what is relevant and new to the session, and...
feature: FEAT-001
statement: 'The hooks give the agent the records that are relevant to the prompt and not already in this
  session (or whose hash or confirmation state changed since they were given), and nothing when nothing
  is new, so repeated records never fill the context. Details such as examples and covering tests are
  pulled on demand with plumb show rather than sent every prompt. A record held back to keep the context
  lean is not marked as given. A /clear or a compaction makes the session''s records new again, since
  the agent lost them. The session-start brief stays short and points to the rest. Today this is done
  with one line per record under the hooks.prompt_lines and hooks.prompt_tokens limits (a mechanism, not
  the owner''s intent: it may change if a better way keeps the context lean).'
examples:
- id: EX-1
  given: a session whose first prompt injected "SR-003 [proposed] Links pin both ends"
  when: a second prompt names SR-003 again and nothing changed
  then: the hook injects nothing; another session still gets the line
- id: EX-2
  given: the same session
  when: SR-003's statement is edited and a prompt names SR-003 and SR-004
  then: only the SR-003 line is injected again
- id: EX-3
  given: SR-004 injected as proposed
  when: the owner confirms it and a prompt names it
  then: '"SR-004 [confirmed]" is injected once with the compare line, and not on the next prompt'
- id: EX-4
  given: hooks.prompt_tokens 10 and a prompt naming SR-003 and SR-004
  when: the hook runs twice
  then: the first injects SR-003 and points to plumb show SR-004; the second injects SR-004 only
- id: EX-5
  given: 60 intents and 5 open NCs
  when: the session starts
  then: the brief is at most 6 lines, with counts, open NCs and a pointer, and lists no intent title
