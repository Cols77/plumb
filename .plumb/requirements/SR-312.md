---
id: SR-312
title: plumb refreshes only what is out of date, and each step is gated...
feature: FEAT-001
statement: 'plumb keeps its health fresh by refreshing only what is out of date: tests whose covered code
  changed since their last result, and links whose files changed. A background job does it after a change,
  one job at a time, with load-sensitive tests waiting for a free machine. Before an intent-loop stage
  closes (clarify, plan, done), and before a commit or a merge, plumb refreshes whatever is still out
  of date and the step holds while anything stays out of date, stale or failing. The hooks only read the
  last result. How often the background job runs is a setting whose default the owner sets from measured
  costs.'
examples:
- id: EX-1
  given: a test linked to a requirement failed in the last run and the code it covers changed since
  when: the background job runs
  then: it reruns that test and no test whose code did not change, and the status no longer says 'not
    rerun since the change'
- id: EX-2
  given: nothing changed since the last refresh
  when: a turn ends
  then: no refresh job starts
- id: EX-3
  given: a refresh job is already running
  when: another change lands
  then: no second job starts; the running one is followed by at most one more
- id: EX-4
  given: the plan stage of an intent loop with one linked test out of date
  when: the agent closes the plan gate
  then: plumb reruns that test first; if it passes the gate closes, if it fails or stays out of date the
    gate refuses and names it
- id: EX-5
  given: a stale link remains after the refresh
  when: the agent closes the clarify, plan or done gate
  then: the gate refuses and names the link
- id: EX-6
  given: a commit or a merge touching code with an out-of-date test
  when: it is made
  then: the out-of-date test is rerun first and the commit or merge holds while it fails
- id: EX-7
  given: a turn's hooks run
  when: they build the status
  then: they read the last refresh's result and run no tests themselves
- id: EX-8
  given: a refresh job fails with an error
  when: it is caught
  then: the status keeps its last result marked out of date, the gate stays closed, and the case goes
    to debugging
- id: EX-9
  given: a test that passed in main, and a worktree whose change touches the code it covers
  when: the worktree's loop closes a gate
  then: the test is out of date there and is rerun in the worktree, while main's result stays valid for
    main
- id: EX-10
  given: a test whose file and covered code are byte-for-byte the same in main and in a worktree
  when: the worktree refreshes
  then: main's result is reused and the test is not rerun
- id: EX-11
  given: a worktree merging into main
  when: the merge is made
  then: the combined result is checked for freshness before the merge closes
proof:
  plan: 'In a live session, an edit breaks a linked test: the background refresh reruns only that test
    and the status turns to failing without the owner sending a message; the agent then tries to close
    an intent-loop gate and is refused, naming the test; after the fix the gate closes.'
