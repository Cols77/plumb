---
id: SR-017
title: Covering-test selection within a turn budget
feature: FEAT-001
statement: 'For the files changed in a turn, plumb selects the covering tests within verify.turn_budget_s:
  documentation changes select nothing, shared test infrastructure sets full verification pending instead
  of running everything, and unknown coverage runs a bounded sample and sets the same flag.'
examples:
- id: EX-1
  given: only docs/concept.md changed
  when: covering tests are selected
  then: nothing is selected
- id: EX-2
  given: pyproject.toml changed
  when: covering tests are selected
  then: status says full verification pending and no full run starts
- id: EX-3
  given: a changed file with no known covering test
  when: covering tests are selected
  then: a bounded sample is selected and full verification pending is set
- id: EX-4
  given: a selection whose real run time exceeds its estimate and hits the hard limit
  when: the run times out
  then: the tests that finished before the limit are recorded as evidence and the next selection allows
    for the observed pace
- id: EX-5
  given: a repository whose test map is not built and cannot be built within the hook budget (a fresh
    clone)
  when: a turn changes src code and the stop hook (or plumb turn end, or a Codex, Pi or Hermes stop) runs
  then: the agent is asked to run plumb tests run --paths for the change, the summary says full verification
    pending (coverage unknown), the regression check of this turn's runs still runs, and the map is built
    outside the hook
