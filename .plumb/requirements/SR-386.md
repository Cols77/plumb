---
id: SR-386
title: 'plumb coordinates several sessions: one heavy job, one landing...'
statement: 'plumb''s heavy commands (a test run, a full run, a repin after tests, a judge batch, a self-fix)
  take the one-heavy-job lock themselves, in every session and worktree; a command that waits says what
  it waits for, and a lock whose holder is no longer running is taken over. A branch ready to land is
  handed to one landing queue; one branch lands at a time, a branch that waits on the owner does not hold
  the ones behind it, and plumb status shows one board: each branch, its state, what it waits on and which
  session holds it.'
examples:
- id: EX-1
  given: session A is in a full test run
  when: session B starts a test run
  then: B waits, says once that it waits for A's run, and starts when A's ends
- id: EX-2
  given: the lock names a process that is no longer running
  when: a heavy command starts
  then: it takes the lock over, says so once, and runs
- id: EX-3
  given: one session and no lock held
  when: a heavy command starts
  then: it runs at once and says nothing about the lock
- id: EX-4
  given: two branches handed to the landing queue
  when: the first is landing
  then: the second waits, and plumb status shows both with their state and their session
- id: EX-5
  given: the first branch in the queue waits on an answer from the owner
  when: the queue moves
  then: the next branch lands, main is never left in the middle of a merge, and the board says what the
    first one waits on
proof:
  plan: 'Acceptance tests with two processes on one repository: the second heavy command waits and then
    runs, a dead holder''s lock is taken over, two queued branches land in order and the board shows them.'
  kind: other
