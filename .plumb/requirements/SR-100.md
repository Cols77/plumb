---
id: SR-100
title: Bounded Hermes adapter hardening
statement: Plumb shall provide a project-local Hermes adapter whose Release A behavior preserves recognized
  instructions, reports activation conservatively, binds events to the installed project, initializes
  the first owner turn, and documents unsupported runtime surfaces without claiming full parity.
examples:
- id: EX-1
  given: Only nonempty CLAUDE.md exists
  when: Install Hermes
  then: CLAUDE text is retained and no AGENTS shadow is created
- id: EX-2
  given: Nonempty Hermes and Claude files exist
  when: Install Hermes
  then: Only the selected Hermes context file receives the block
- id: EX-3
  given: An empty Hermes file and nonempty CLAUDE.md exist
  when: Install Hermes
  then: CLAUDE.md is selected and the empty Hermes file remains unchanged
- id: EX-11
  given: The first Hermes filename is empty and the second is nonempty
  when: Install Hermes
  then: The second Hermes filename remains untouched and selection falls through to AGENTS or Claude type
- id: EX-12
  given: Nonempty AGENTS.override.md and AGENTS.md exist
  when: Install Hermes
  then: Only AGENTS.override.md receives the block
- id: EX-4
  given: Claude context has a plumb block
  when: Uninstall Hermes
  then: The block is kept and shared or unknown ownership is explained
- id: EX-5
  given: Plugin files and discovery flag exist
  when: Run status
  then: Installed files and prerequisites are reported while runtime activation remains unverified
- id: EX-6
  given: The generated plugin belongs to repo A and process cwd is repo B
  when: A prompt callback runs
  then: Only repo A receives the hook payload
- id: EX-7
  given: The generated plugin root lacks .plumb
  when: Any event callback runs
  then: No subprocess is launched and empty adapter output is returned
- id: EX-8
  given: An observer may fire before ancestry is known
  when: The first eligible parent prompt arrives
  then: One brief is obtained after filtering, and later prompts do not duplicate it
- id: EX-9
  given: parent_session_id is explicit
  when: Prompt and later callbacks run
  then: No owner prompt or summary events are emitted for the child
- id: EX-13
  given: A child observer fires without parent metadata
  when: Later callbacks identify its parent session
  then: No startup or other subprocess event is emitted
- id: EX-10
  given: Another transform wins or a reply is interrupted
  when: The turn settles
  then: The missing summary is marked unseen
description: Release A implementation scope A1-A8 from the reconciled Hermes compatibility plan; proposed
  and not a claim of full Claude parity.
