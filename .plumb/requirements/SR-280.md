---
id: SR-280
title: plumb adopts a repository once, on a plain request, and stays...
feature: FEAT-007
statement: 'On a plain request or /plumb init, plumb adopts the repository: its record folder with settings,
  git''s checks at commit, merge and push each calling one plumb launcher in the user''s folder, and a
  way for git to merge plumb''s records; adopting again changes nothing. A repository not adopted gets
  one line per session suggesting adoption and nothing else. plumb''s own repository is adopted the same
  way.'
examples:
- id: EX-1
  given: a fresh git project and the plugin installed
  when: the owner says "set up plumb here" or types /plumb init
  then: plumb's record folder exists, git's checks at commit, merge and push each call plumb's launcher,
    git knows how to merge plumb's records, and the project's Claude Code settings are unchanged
- id: EX-2
  given: a git repository without .plumb/
  when: it is adopted
  then: the record directories, config, claims, ignore and attributes files and empty logs are created
- id: EX-3
  given: an adopted repository
  when: adoption is asked for again
  then: plumb says it is already adopted and changes nothing
- id: EX-4
  given: the adopted project
  when: git's hooks are listed
  then: the commit check is installed and calls plumb's launcher; what it holds is P11's
- id: EX-5
  given: a project without plumb's record folder
  when: a session starts and the owner sends three messages that edit files
  then: the only plumb output of the session is the one line "/plumb init to adopt this repository", and
    plumb writes nothing
- id: EX-6
  given: a project without plumb's record folder
  when: plumb's checks run after a message, an edit and an answer
  then: each finishes within a tenth of a second without starting plumb itself
- id: EX-7
  given: an adopted project
  when: git's hooks are listed
  then: the merge-time check is installed and calls plumb's launcher, running no test; what it holds is
    P11's
- id: EX-8
  given: plumb's own repository with the plugin installed
  when: a commit is made there
  then: a commit whose trailer names no requirement it serves is held by the commit check, as in any adopted
    repository
proof:
  plan: 'Recommended: in a live session the owner says "set up plumb here" in a scratch git repository
    and sees the record folder and git''s checks appear with the project''s Claude Code settings unchanged;
    asks again and sees nothing change; then opens a session in a second, unadopted repository and sees
    only the one adoption line. The owner decides whether this walk is the proof.'
  kind: live-session
