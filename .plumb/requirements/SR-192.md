---
id: SR-192
title: A background plumb process opens no console window on Windows
statement: On Windows, every background process plumb starts (the understand worker, the background test
  map) is created with CREATE_NO_WINDOW and a new process group and never with DETACHED_PROCESS, so neither
  it nor any git, pytest or model command it runs opens a console window; it still outlives the process
  that started it; on other systems the launch starts its own session as before
examples:
- id: EX-1
  given: a Windows machine
  when: the stop hook starts the understand worker
  then: no console window appears for the worker nor for the commands it runs
  quote: Why are there still windows spawning during executions?
  prompt: e37cccf68020416a
- id: EX-2
  given: a Windows machine
  when: the background test map starts
  then: no console window appears for it nor for its git and pytest calls
- id: EX-3
  given: the hook that started a background process has exited
  when: the process runs on
  then: it keeps running to the end of its work
- id: EX-4
  given: macOS or Linux
  when: a background process starts
  then: it starts in its own session, as before
proof:
  plan: 'on the owner''s Windows machine: start the worker through the hook and watch for windows while
    it runs a job that calls git and the model'
  kind: live-session
