---
id: SR-272
title: Long plumb work shows its step and progress
feature: FEAT-005
statement: 'plumb work expected to take more than about two seconds reports, at least once per second,
  its step in plain words and its progress (done of total, or elapsed time when the total is unknown):
  a bar redrawn in place in a terminal, bounded plain lines otherwise, and in the status line and plumb''s
  small band, which animates while plumb works; a failure replaces it with one line naming the step.'
examples:
- id: EX-1
  given: a run of 400 tests started in a terminal
  when: it is running
  then: one line shows a bar, 'running the tests', 120 of 400, and the test file currently running, redrawn
    in place
- id: EX-2
  given: the same run started from the agent's shell, where stderr is not a terminal
  when: it is running
  then: plain progress lines appear at a steady interval, never one per test, and the last line says the
    run finished with its result
- id: EX-3
  given: a merge check running its 120 covering tests
  when: the owner looks at the Claude Code status line
  then: 'it reads ''plumb ⏳ merge check: running the covering tests · 40/120'''
- id: EX-4
  given: a step whose total is unknown, such as building the test map on a fresh clone
  when: it is running
  then: the message names the step and the elapsed time, with no percentage or bar fill
- id: EX-5
  given: a command that finishes within two seconds
  when: it runs
  then: no progress display appears
- id: EX-6
  given: a read job takes eight seconds
  when: the owner looks at Claude Code
  then: the band animates 'reading your answer' and the agent has carried on with nothing approved
- id: EX-7
  given: the background judge working through 160 written records
  when: the owner looks at the status
  then: the band animates and says how many are judged so far, such as 'judging the backlog · 10/160'
- id: EX-8
  given: a long execution that fails midway
  when: it stops
  then: the progress line is replaced by one line naming the step that failed, and the status no longer
    shows it as running
- id: EX-9
  given: a host with no band, such as Codex
  when: long plumb work runs
  then: the plain progress lines and the status line still show it
proof:
  plan: 'Recommended for the owner to decide: the AI runs a long plumb command (building the test map
    on a fresh clone, then a merge check) once in a terminal and once from the agent''s shell, and shows
    the bar, the plain lines and a screenshot of the status line and band animating with the step and
    count.'
  kind: command
