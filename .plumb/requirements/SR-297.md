---
id: SR-297
title: The merge refuses a landing that adds a validate error or a new...
feature: FEAT-003
statement: The merge check into main refuses a landing whose result has a validate error not present at
  the merge base, or a link stale in the result but not at the base, and names each to the agent with
  the step that clears it (repin after tests, relink, or a card when the meaning changed). Links and errors
  already present at the base never hold the merge. The owner is asked nothing.
examples:
- id: EX-1
  given: a branch whose landing would add one validate error
  when: it merges into main
  then: the merge is refused naming the error, and the owner is asked nothing
- id: EX-2
  given: a branch that leaves SR-200's link to a file it changed stale
  when: it merges into main
  then: the merge is refused naming the link and saying repin after its tests pass
- id: EX-3
  given: a link already stale at the merge base
  when: a branch that does not touch it merges
  then: the merge is not held for it
- id: EX-4
  given: a branch adding no error and no stale link
  when: it merges
  then: the merge goes through
proof:
  plan: A scratch branch that leaves a link stale is refused naming it; after the repin it lands.
  kind: command
