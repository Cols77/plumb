---
id: SR-083
title: /plumb init adopts a project; projects not adopted stay silent
feature: FEAT-007
statement: '/plumb init (or "set up plumb here") adopts the project: plumb''s record folder with its settings,
  a check at each commit that the commit names the requirement it serves, a way for git to merge plumb''s
  records, a quick check at merge time that runs no tests, and the full test run at push. git''s checks
  each call one plumb launcher kept in the user''s own folder. Nothing of Claude Code''s (commands, skills,
  background checks) is copied into the project. In a project plumb has not adopted, the plugin stays
  silent apart from one line per session: "/plumb init to adopt this repository" (rulings R15, R17).'
examples:
- id: EX-1
  given: a fresh git project and the plugin installed
  when: the owner types /plumb init
  then: plumb's record folder exists, git's checks at commit, merge and push each call plumb's launcher,
    git knows how to merge plumb's records, and the project's Claude Code settings are unchanged
- id: EX-2
  given: the adopted project
  when: a commit names no existing requirement it serves
  then: the commit check holds it with one plain line
- id: EX-3
  given: a project without plumb's record folder
  when: a session starts and the owner sends three messages that edit files
  then: the only plumb output of the session is the one line "/plumb init to adopt this repository", and
    plumb writes nothing
- id: EX-4
  given: a project without plumb's record folder
  when: plumb's checks run after a message, an edit and an answer
  then: each finishes within a tenth of a second without starting plumb itself
- id: EX-5
  given: an adopted project
  when: a merge brings in a requirement the owner has not confirmed
  then: the merge-time check holds it without running any test, and the full test run happens once, at
    push
