id: SR-361
title: Every judge question is asked as soon as it is raised
statement: When the judge raises questions for the owner about records the session's own branch changes
  compared with main, the agent asks all of them at its next chance to ask, even mid-task, through the
  question tool, grouping those that hinge on one principle into one question whose answer settles them;
  there is no limit per turn and nothing is kept for a later turn. A question about records the session's
  branch does not change is never pushed into that session; it waits in /plumb status. A session in main's
  checkout changes nothing of its own and is told to ask none.
examples:
- id: EX-1
  given: the judge raises five questions while the agent is in the middle of a task
  when: the agent can next ask
  then: all five are asked through the question tool before the task goes on; none waits for a later turn
- id: EX-2
  given: twelve questions are raised and eight of them hinge on two principles
  when: they are asked
  then: the owner gets the two principle questions and the four others, six in all, in one go
- id: EX-3
  given: the owner answers a principle question
  when: the judge reads the questions that hinge on it
  then: those questions are settled from the answer and not asked
- id: EX-4
  given: the owner dismisses a question
  when: the turn ends
  then: it is not asked again in a loop; the band and the session start count it as waiting
- id: EX-5
  given: the judge raised a question in the background after the agent last ran the clarify check, and
    no regression, covering-test run, untraced file or stale link of the turn comes first (SR-373's one
    next action)
  when: the agent is about to end its turn
  then: plumb stops it once and tells it to ask the waiting questions now; it asks them through the question
    tool before the turn ends, and a later turn is not stopped again for the same questions
- id: EX-6
  given: a judge question waits on a record only session A's branch changes
  when: session B, on another branch, runs the clarify check or ends its turn
  then: B is not told to ask it and is not stopped for it; session A is told to ask it
  quote: a session should only be blocked by questions that touch the corresponding work, not other
  prompt: acf3b49752d46192
- id: EX-7
  given: judge questions wait on records no session's branch changes
  when: the owner runs /plumb status
  then: the questions are listed there as waiting for the owner, and no session is told to ask them
- id: EX-8
  given: a session works in main's checkout with uncommitted record changes
  when: the judge raises a question on one of those records
  then: the session is not told to ask it; /plumb status lists it
proof:
  plan: 'In a live session on this repository after the plugin is reloaded from main: a request makes
    the judge raise questions; the agent asks them all right away, in plain words and merged by principle;
    nothing obvious is asked; the turn ends with no ''N questions for you'' line and the band shows nothing
    waiting.'
  kind: live-session
  post_merge: true
