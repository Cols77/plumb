id: SR-149
title: plumb relink moves one link to a new target
statement: plumb relink <record#n> <target> --note <why> keeps the link's number, kind and example, points
  it at the new target with fresh pins on both ends, and logs a relink event with the old and new targets
  and pins
examples:
- id: EX-1
  given: SR-124#5 verified_by plugin/hooks/trial.test.tsx (dangling) for no example
  when: plumb relink SR-124#5 tests/plugin/mod/trial.test.tsx --note "moved" runs
  then: SR-124#5 is verified_by tests/plugin/mod/trial.test.tsx, pinned to the file and record as they
    are now, and the events log holds one relink entry with both targets
  quote: remove/move a link
  prompt: 02c090e63309bddb
- id: EX-2
  given: a new target that does not exist
  when: plumb relink runs
  then: it exits 1 naming the missing target and the record is unchanged
- id: EX-3
  given: the record already has the same kind, target and example as another link
  when: plumb relink would make link n a copy of it
  then: it is refused, naming the existing link and suggesting plumb unlink
- id: EX-4
  given: a kind that cannot point at the new target (a record-only kind given a file)
  when: plumb relink runs
  then: it is refused with the same message plumb link gives
proof:
  plan: relink a dangling link in a scratch repository and show plumb show and plumb validate
