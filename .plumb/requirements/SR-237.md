---
id: SR-237
title: A capture names the requirements its new intent changes or contradicts
feature: FEAT-002
statement: When an intent is captured, plumb finds the existing requirements whose meaning it changes
  or contradicts and names them by title in the capture output for the agent, so the same capture supersedes
  or rewords them instead of leaving them to go stale; a contradiction it cannot resolve reaches the owner
  only as one question to arbitrate.
examples:
- id: EX-1
  given: a new intent removes behaviour that existing requirements still describe
  when: it is captured
  then: the capture output for the agent names those requirements by title, and the same capture supersedes
    or rewords each, so none is left describing the removed behaviour
- id: EX-2
  given: a new requirement says the agent relays the owner's conflict choice while another says it never
    does
  when: it is captured or merged
  then: the capture output for the agent names the contradiction, nothing is approved, and it reaches
    the owner only as one question-tool question to arbitrate
- id: EX-3
  given: the owner states a new principle
  when: it is captured
  then: one intent records it, and the capture output for the agent names the requirements it changes
proof:
  plan: 'Recommended for the owner to decide: in a live session the owner states an intent that removes
    a behaviour an existing requirement describes; the agent''s capture output names that requirement
    and the same capture supersedes it.'
  kind: live-session
