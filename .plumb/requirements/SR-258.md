id: SR-258
title: Intent in flight is shared, and a contradicting capture is caught...
feature: FEAT-006
statement: 'Each worktree shares the intent it has in flight as a claim in a shared git ref, a signal
  never a lock, cleared when its branch merges or is deleted, and reads other worktrees read-only and
  cheaply: under 50 ms with warm caches, no git process for a branch whose tip has not moved, and nothing
  written in another worktree. The agent is told, one line per record and once per session, when another
  branch changes a record it works on; nothing is refused or held.'
examples:
- id: EX-1
  given: five other worktrees
  when: the prompt hook computes overlaps with warm caches
  then: it takes under 50 ms and starts no git process
- id: EX-2
  given: a branch whose tip has not moved since the last scan
  when: a session starts
  then: no git command runs for that branch
- id: EX-3
  given: another worktree
  when: the awareness check runs
  then: no file in that worktree is created or modified
- id: EX-4
  given: a worktree that was removed while its changing.json path is still recorded
  when: the check runs
  then: that worktree is ignored
- id: EX-5
  given: feat-x's session published its edit of SR-005 as pending, the edit was then committed with no
    session to publish again, and main merged feat-x while its worktree stays on disk, idle
  when: another worktree's session brief, prompt or stop hook, or status looks at what other worktrees
    are changing
  then: feat-x is not named as changing SR-005
- id: EX-6
  given: worktree feat-x has edited SR-005
  when: a session starts in main's worktree
  then: the session start tells the agent SR-005 "relay checks" is also being changed on branch feat-x
- id: EX-7
  given: that line was given once this session
  when: the next prompt is about relay checks again and feat-x has not changed SR-005 since
  then: no line is repeated
- id: EX-8
  given: a branch without a worktree whose commits changed SR-007
  when: a session starts
  then: the session start names SR-007 and that branch
- id: EX-9
  given: no other worktree or branch changes a record this session touches
  when: the hooks run
  then: no awareness line is given
- id: EX-10
  given: a session on branch feat-x captures a change to SR-005 "relay checks"
  when: the capture completes
  then: refs/plumb/claims holds a claim naming SR-005, branch feat-x and a one-line summary of the request
- id: EX-11
  given: two worktrees record a claim at the same moment
  when: both write the register
  then: both claims are kept and no update is lost
- id: EX-12
  given: a claim recorded on branch feat-x
  when: feat-x is merged into main, or deleted
  then: the claim no longer appears in the register
- id: EX-13
  given: another branch claims SR-005
  when: this worktree edits or captures SR-005
  then: nothing is refused, locked or held; plumb only informs
- id: EX-14
  given: feat-x's change to SR-005 was merged into main with a merge commit, and feat-x then got one more
    commit
  when: main changes SR-005 again or shows the brief or status
  then: 'feat-x''s merged version is no longer in flight: no question or decision is raised and no line
    names feat-x'
proof:
  plan: 'Recommended for the owner to decide: two live sessions in two worktrees; the owner asks one to
    change a requirement and watches the other session''s agent say that branch is changing it, once.'
  kind: live-session
