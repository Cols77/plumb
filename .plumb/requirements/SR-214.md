id: SR-214
title: The owner's message is read by meaning; the clear part is taken...
feature: FEAT-008
statement: 'A reader model independent of the coding agent reads each hook-logged owner message by meaning,
  against the open questions and what the last reply showed, returning per item: answered, change asked,
  reversed or open, with its words and a confidence. An item counts as answered only when the last reply
  showed it at that version and the owner''s words about it are in the message. The clear part at or above
  the calibrated threshold, which the owner''s own answers set, is taken; only the rest is asked again
  through the question tool.'
examples:
- id: EX-1
  given: a conflict question whose options are Keep this, Keep the other and Both
  when: the owner replies 'keep what main has'
  then: the reader names the option that side means and the conflict is settled on it
- id: EX-2
  given: a question with options 1, 2 and 3 shown in text
  when: the owner replies '2, and also make the pane resizable'
  then: the question is answered with option 2 and the pane request goes on as a new request, checked
    against confirmed intent; no question is raised for the '2'
- id: EX-3
  given: the same conflict question
  when: the owner replies 'hmm, either could work'
  then: the conflict stays open, nothing is recorded, and it is asked again through the question tool
- id: EX-4
  given: a message that answers a question and adds a request whose meaning the reader returns as open
    ('and do the thing with the pane')
  when: the reader runs
  then: the question is answered and only the pane request is asked about through the question tool, saying
    what was unclear
- id: EX-5
  given: the last reply showed the reminder intent and the plugin-UX requirement
  when: the owner writes 'the reminder part is fine, I am not sure about the UX one, some features might
    have to stay internal to plumb'
  then: 'the reminder item is answered as agreed with those words, and the UX requirement gets a change
    asked: some features stay internal to plumb'
- id: EX-6
  given: the reader answers with a confidence of 0.7 and the threshold is 0.9
  when: plumb applies it
  then: nothing is taken and the item stays open
- id: EX-7
  given: the last reply showed only the reminder timing requirement
  when: the owner writes 'ok, and the export one is fine too'
  then: the reminder item is answered as agreed; the export requirement, not shown, is not taken as answered,
    and that part goes on as a new request checked against confirmed intent
- id: EX-8
  given: a question offering keep, drop or reword for an addition, and one offering two versions
  when: the owner answers 'keep it', 'drop it', 'reword to X', or 'the second, plus the first's date'
  then: the reader maps them to answered keep, answered drop, change (X) and change (the second version
    with the first's date)
- id: EX-9
  given: the last reply showed five items and left a question open
  when: the owner answers in one message
  then: one read job covers the message against all five items and the question, and returns one entry
    for each
- id: EX-10
  given: the owner has answered and the read job is still running
  when: the agent starts its next piece of work
  then: the progress shows plumb reading the answer, the agent proceeds, nothing is taken yet, and the
    answers are applied when the job returns
- id: EX-11
  given: twenty of the owner's answers show the owner agrees with the reader only above a confidence of
    0.8
  when: the reader's threshold is recomputed
  then: the threshold becomes 0.8, the lowest confidence those answers support, instead of the starting
    0.9
- id: EX-12
  given: the last reply showed the reminder timing requirement
  when: the owner writes 'Fine. Also add a dark mode to the settings page.'
  then: the reminder item is answered as agreed and the dark mode request goes on as a new request, not
    a reservation about the reminder
- id: EX-13
  given: the last reply showed the reminder timing requirement
  when: the owner writes 'Ok. The reminder should go out a day earlier.'
  then: the reader returns change asked (a day earlier) for the reminder, not agreement, since the second
    sentence is about it
- id: EX-14
  given: no reader model can be reached
  when: the owner's message needs reading
  then: plumb says so and holds the reading; nothing is taken by word rules
proof:
  plan: 'Recommended for the owner to decide: in a live session on a scratch repository, the last reply
    shows two items; the owner writes one message agreeing with one, changing the other and adding a new
    request (the plumb line shows each outcome and the new request goes on); an unclear sentence comes
    back as one question through the question tool. The reader''s evaluation set runs as the command-level
    check.'
  kind: live-session
