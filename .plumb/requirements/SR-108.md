---
id: SR-108
title: Long plumb executions show progress and the current step, in the...
statement: 'A plumb execution expected to take more than about two seconds reports, at least once per
  second, the step it is on in plain words and its progress (done of total, or elapsed time when the total
  is unknown): as a progress bar redrawn in place when stderr is a terminal, as bounded plain lines otherwise,
  and in the Claude Code status line through the session state file while it runs.'
examples:
- id: EX-1
  given: a full suite run of 400 tests started in a terminal
  when: it is running
  then: one line shows a bar, 'running the full suite', 120 of 400, and the test file currently running,
    redrawn in place
- id: EX-2
  given: the same run started from the agent's shell, where stderr is not a terminal
  when: it is running
  then: plain progress lines appear at a steady interval, never one per test, and the last line says the
    run finished with its result
- id: EX-3
  given: a merge-check running the full suite
  when: the owner looks at the Claude Code status line
  then: 'it reads ''plumb ⏳ merge check: running the full suite · 120/400'''
- id: EX-4
  given: a step whose total is unknown, such as building the test map on a fresh clone
  when: it is running
  then: the message names the step and the elapsed time, with no percentage or bar fill
- id: EX-5
  given: a command that finishes within two seconds
  when: it runs
  then: no progress display appears
- id: EX-6
  given: the background worker judging a backlog of 160 proposed records
  when: the owner looks at the status line
  then: it says how many are judged so far, such as 'judging the backlog · 10/160'
- id: EX-7
  given: a long execution that fails midway
  when: it stops
  then: the progress line is replaced by one line naming the step that failed, and the status line no
    longer shows it as running
