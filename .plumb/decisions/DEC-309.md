title: How do evaluate and debug cooperate?
question: How do evaluate and debug cooperate?
chosen: Evaluate only documents the issues; then the debug workflow is called on them, its fixes are merged
  through plumb's merge check, and the benchmark runs again (--loop N); the owner is asked through the
  question tool only when a fix would change the intent or a requirement's meaning
alternatives:
- The owner runs plumb debug and the merge by hand between runs
- Issues stay in the file only; nothing is fixed or rerun
rationale: 'the owner''s own words on 2026-10-21: ''Evaluate just documents the issues. but then debug
  is called to work on those issues, and ensure plumb compliant merge of the fixes. Of course it should
  come back to the user with question tool when fixing implies changing the intent'''
matters: true
recommended: Every issue becomes a debug case after the run; --loop N chains evaluate, debug and evaluate
  again, stopping when no issue is filed or the debug workflow needs the owner
