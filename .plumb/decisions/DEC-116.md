title: Where does a worktree find the owner's prompt text?
question: Where does a worktree find the owner's prompt text?
chosen: In the main checkout's session log, reached through git's common directory; the owner's messages
  are not copied into the tracked log, nor are the owner's answers to plumb's questions or plumb's first
  reading of a message. A record is judged once, on the machine that captured it, before it merges; a
  checkout without that machine's log never judges it again.
rationale: 'The owner answered through the question tool on 2026-11-01: "Keep them out of git (Recommended)",
  asked "should your messages stay out of git, with the judge reading them only from this machine''s private
  log?" after being told the INT files are the agent''s summary, not their words, and that a clone elsewhere
  would check records against the intent records only. Before that they had asked: "Shouldn''t only my
  intent recorded and commited? Meaning INT files? therefore we wouldn''t need my words to be commiteed,
  correct?" The premise entries committed since SP8 (bf87ffbe1) stop; those already in git history stay.
  On 2026-11-01 the owner answered through the question tool, asked whether the copy of each message kept
  for plumb''s first reading of a request and their answers to plumb''s questions should stay out of git
  too: "Both out of git (Recommended)". Their reasoning, verbatim: "Let''s think what means an intent
  that is being merged. Word to intent matching should already have been validated locally when merged.
  So what''s the point of having the words versionized? and then why should it be re-checked everytime?"'
alternatives:
- Track the prompt text under .plumb/log so every checkout has it.
- Keep copying lines by hand into each worktree.
- Commit each message a record comes from with that record, so any clone judges against the owner's words.
matters: true
recommended: In the main checkout's session log, reached through git's common directory; prompt text is
  not copied into the tracked log.
