title: Track every intent, debug and evaluate loop of the project from...
quote: I want to improve the way we can track with plumb each debug and intent loop. from any plumb session
  related to a given project, I want to be able to track each intent loop and their progress, remaining
  actions, and also show a description of what is supposed to be achieved. Same for the debug loop and
  the evaluate loop
readback: 'From any plumb session of a project, in the main checkout or a worktree, plumb''s band gives
  access to one list of every loop of the project: the intent loops of every session, the problems plumb
  is fixing itself (the debug loop) and the evaluate runs. Each loop shows what it is meant to achieve,
  how far it is, what is left to do and what it waits for. From the list, a loop no session works on can
  be reopened in a new interactive session when the owner picks it, and a message can be sent to the session
  working on a loop.'
will:
- 'one plumb command lists every loop of the project, across sessions and worktrees: its kind, its goal
  in plain words, its progress, what is left, what it waits for and where it runs'
- the band's one line gains a short count of the loops being worked on; pressing it opens a docked pane
  on the project's loops; Enter on a row shows its goal, the steps done and what is left
- 'the loops pane shows one type of loop at a time, with a clear switch between the three types: intent,
  debug and evaluate'
- 'an intent loop''s row: the intent''s read-back as its goal, its steps (clarify, plan, build, proven),
  the current task done of total, the plan items left and what it waits for'
- 'a debug row per problem plumb is fixing itself: the symptom in plain words, where its fix stands and
  what is left'
- 'an evaluate row per run: the task and model, the round of the rounds asked, and what is left'
- loops nobody works on any more are kept apart below the live ones, marked idle since their last activity
- when the owner picks an idle loop in the list, a new interactive Claude Code session opens on it, takes
  it over and starts from plumb's brief of the loop
- 'the owner''s message is sent to the session working on a loop: typed on its row in the pane, or passed
  on unchanged by the agent of any session'
wont:
- open a session by itself, with no press of the owner
- stop, close or delete a loop from the list
- 'resume the old conversation of the session that ran a loop: the new session starts from plumb''s brief'
- 'change the known problems line or its pane: it keeps its own pane'
- grow the band beyond the lines it has today
- list agents, agent counts or tokens
- show loops of another machine or clone
- build the Sessions page of the browser room, which stays for later
- change the pane of this session's own intent loop
assumptions:
- a plumb session related to the project is a session in the main checkout or in one of its git worktrees
  on this machine
- the goal of an intent loop whose records are not written yet is the owner's opening words, read from
  the local session log and never committed
- 'a finished loop leaves the list: an intent loop at intent done, a problem once resolved, an evaluate
  run once it ended; its result stays where it is kept today'
- a loop is live while its session was active lately; otherwise it is idle since its last activity
- the band's count is of the loops being worked on; idle loops are counted apart
mode: incremental
