id: INT-022
title: Parallel work by awareness instead of locks (R10)
quote: 'yes'
readback: Several agents, worktrees and clones work on one repository at once. git stays the coordinator
  and plumb holds no shared mutable runtime state. New record IDs never collide between worktrees, because
  they are reserved through one shared git ref with compare-and-swap; IDs that still collide across clones
  are renumbered at merge by plumb merge-fix, which rewrites every reference without touching history.
  Logs never conflict, because every entry is its own file under .plumb/log/<kind>/, and the current JSONL
  logs are migrated without breaking the hash chain. A merge driver merges record files field by field;
  a real content conflict becomes an intent conflict shown to the owner with both versions, and the record
  stays unconfirmed until the owner chooses. The brief, the prompt delta and the status line say when
  another worktree or branch is changing the same records. plumb check --merge on the merge result covers
  intent conflicts and ID collisions and can run as a pre-merge-commit or pre-push hook.
will:
- collision-free IDs reserved through refs/plumb/ids, shared by every worktree
- plumb merge-fix renumbers IDs that collide across clones and rewrites every reference
- one file per log entry, with an idempotent migration of events.jsonl and evidence.jsonl that keeps the
  hash chain and the evidence identities
- a frontmatter-aware merge driver installed by plumb hooks install
- content conflicts become intent conflicts the owner resolves, shown with both versions
- cross-worktree and cross-branch awareness in the brief, the prompt delta and the status line
- plumb check --merge covers intent conflicts and ID collisions, as a pre-merge-commit or pre-push hook
wont:
- locks, leases, admission or any shared mutable runtime state
- transaction machinery or a guarded publish
- rewriting git history (old commits keep their trailers)
- an agent choosing the side of an intent conflict
assumptions:
- refs/plumb/ids lives in one clone and is not pushed; other clones meet at merge-fix
- awareness covers worktrees and local branches; remote-tracking branches are off by default
mode: incremental
