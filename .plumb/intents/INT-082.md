id: INT-082
title: An independent judge, and a hold when none is reachable
quote: My intent is that most of the time the system shouldn't rely on deterministic tooling to understand
  intent or process text, unless we're sure the deterministic solution can handle any type of situation.
readback: Every record the agent writes or changes is checked by a judge independent of the coding agent,
  against everything you said and the context you said it in, not just a quoted fragment. JEV answers
  first when it is confident past the threshold calibrated on your own answers; otherwise the judge model
  you configured answers, and one judge_model setting governs everything about verdicts. When no judge
  can be reached, plumb tells you once and holds only the steps that need a verdict; it never decides
  by fixed rules instead.
will:
- Judge every new or changed record, and every stale link, against your whole logged words and their context, once, on the machine that captured it; other checkouts keep that judgment (DEC-116, owner 2026-11-01).
- Ask JEV first and the configured judge model below JEV's calibrated threshold, logging which judge gave
  each verdict and with what confidence.
- Mark a judgment made on a quote alone, and never fast-track a record on it.
- Keep JEV's provider, credential name and question form as settings, with the key never written into
  the repository.
- With no judge reachable, say so once, apply the verdicts already given, and hold only what needs a verdict
  until a judge answers.
- Judge code against its requirements edge by edge, weakest first, as advice, and list unjudged touched
  requirements at the merge.
wont:
- Decide any verdict by keyword, heuristic or other fixed rule, as a fallback or otherwise.
- Let the coding agent that wrote a record or the code be its judge.
- Show you the judge's doubts as a card or a read-back line to read; they reach you only as questions
  through the question tool.
- Ask you for a record id or a shell command to judge, align or set anything up.
- Hold your prompt, or work that needs no judge, because a judge is unreachable.
- Change, create or remove a link because of a fidelity judgment.
assumptions:
- 'Assumed: the ''configured judge model'' of P8 is the same model P9''s cascade calls Sonnet; judge_model
  names it and its default follows P9, Haiku still allowed.'
- 'Assumed: ''above its calibrated threshold'' is strict, so a JEV probability equal to the threshold
  goes to the judge model (old SR-182 said ''at or above'').'
- 'Assumed: the owner''s words outlive the session through P3''s pre-intent record on the machine that heard them, so the old rule copying the premise message into the committed log (SR-102) gives way to DEC-074 and DEC-116 (nothing the owner writes is copied into the tracked log; owner 2026-11-01: "Both out of git (Recommended)").'
- 'Assumed: low-confidence judgments go to the judge model, not to the host coding agent (old SR-024),
  because P8 asks for an independent judge.'
- 'Assumed: a judge that keeps failing in the same way (repeated out-of-schema answers) is a case that
  cannot settle and goes to P5''s debug workflow.'
- 'Assumed: agent-side commands such as alignment and fidelity may still take record ids; only owner commands
  never do (P2).'
