id: INT-030
title: When plumb does something that takes a while, you can see how far...
quote: There should be a progress bar indicating the progress of long executions with a message indicating
  what's going on
readback: 'When plumb does something that takes a while, you can see how far along it is and what it is
  doing right now, in plain words: a progress bar with a message in a terminal, the same message and progress
  in the Claude Code status line where you actually look, and plain progress lines in the agent''s shell
  so its output also says what happened.'
will:
- Every plumb execution that can take more than a couple of seconds (a full test run, the covering tests
  of a turn, building the test map, merge-check, an import, align, and the background jobs that judge
  the backlog) reports its current step in plain words and how far along it is (done of total, or elapsed
  time when the total is unknown).
- In a terminal, that is one progress bar with the message, redrawn in place.
- In the agent's shell (no terminal), the same progress comes as plain lines at a steady interval, bounded
  in number, and a final line says what finished.
- While it runs, the Claude Code status line (and the SP7 band once it exists) shows the same message
  and progress, because you watch the agent, not the shell.
wont:
- No progress display for hook runs that finish within their budget.
- 'No invented estimates: when the total is unknown, the step and the elapsed time are shown, no percentage.'
- No change to what the commands themselves do or decide.
assumptions:
- Long means expected to take more than about two seconds.
- Progress refreshes about once per second; the status line reads it from the session state file the way
  it reads status today.
- A long execution started by the agent is still shown to you through the status line even though its
  shell output is hidden until it finishes.
mode: incremental
