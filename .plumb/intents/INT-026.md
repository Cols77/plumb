id: INT-026
title: Agents spawned by a workflow get the plumb context they need
quote: yes record the intent, and make sure agents get the required packets in this workflow only if needed.
readback: 'An agent that a workflow spawns should work from the same plumb context as the main agent:
  the intent behind its task, your own words, the related records and the tests that cover what it changes.
  Today it gets only the task prompt and the project instructions, and must pull the rest itself. The
  context is given as a packet, and only when the task needs it, so it doesn''t bloat the context (INT-016).'
will:
- 'A way to build a context packet for a task: the requirement with its examples, its parent intent with
  your words, the decisions it depends on, related records, and the tests covering the files it may change.'
- Give a spawned agent that packet only when its task needs more than the requirement's examples, e.g.
  when it changes behaviour that other requirements rule.
- Let the verifying agent check the change against the intent and your words, not only that tests exist
  and pass.
wont:
- Inject every record into every agent.
- Change how the main agent's own hooks inject context.
assumptions:
- Claude Code does not run plumb's session-start and prompt hooks for subagents, so the packet goes in
  the task prompt or is pulled with a plumb command.
- Which tasks need a packet is judged by the agent that writes the workflow, using what the requirement
  touches.
